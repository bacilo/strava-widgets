# WMA age-grading factor tables

Two committed, hand-sourced JSON tables used by `src/analytics/wma-factors.ts`
(REC-06, D-09) to compute age-graded performance percentages. Both files are
generated by `node scripts/convert-wma-tables.mjs` from raw source artifacts
downloaded into the gitignored `scripts/wma-source/` directory — **do not
hand-edit either JSON file**; re-run the converter instead.

## Sources

### Road (`data/wma/road-factors.json`) — 5k, 10k, half, marathon, both sexes

- **URL:** `github.com/AlanLyttonJones/Age-Grade-Tables` (`2025 Files/MaleRoadStd2025.xlsx`
  and `FemaleRoadStd2025.xlsx`)
- **Licence:** CC0-1.0
- **Edition bundled:** 2025 (approved 2025-01-10 by the Masters Long Distance
  Running Council (MLDR) of USA Track & Field)
- Contains both the per-age factor table (`Age Factors` worksheet) and the
  open-class standard time per distance (`OC sec` row) in the same workbook —
  no separate standards source needed for road.

### Track (`data/wma/track-factors.json`) — 400m, 800m, 1mi, both sexes

- **Factors URL:** `howardgrubb.co.uk/athletics/wmatnf23.html`
- **Factors edition bundled:** WMA 2023 (Howard Grubb's "simple version to
  lookup WMA 2023 factors", December 2022)
- **Open standards URL:** `howardgrubb.co.uk/athletics/wmalookup15.html`
- **Open standards edition bundled:** 2015

**Why two different pages for one table:** the 2023 factors page is
deliberately a "factors-only" calculator — it converts a raw result into an
age-adjusted result (`result × factor`) and has no open-class standard time
anywhere on the page (confirmed by direct inspection of its source; the WMA
2023 Appendix B PDF it links to is exclusively about Combined Events scoring,
not single-event standards, so it isn't usable as a standards source either).
The same author's older lookup tool, `wmalookup15.html`, is the only reachable
page on this domain that ships single-event open standards
(`new facrow(event, distanceKm, standardSec, ...)`). Its 2010-edition and
2015-edition tables carry **identical** standard times for 400m/800m/1mile in
both sexes, which indicates the WMA single-event open standard times are
revised far less often than the age-factor tables themselves. This file
therefore deliberately pairs the newer (2023) age factors with the most
recent available (2015) open standards, and records both editions separately
(`edition` for factors, `standardsEdition` for standards) rather than
silently blending them under one label.

A future maintainer who finds a genuinely 2023-or-later single-event
standards table should re-point `TRACK_STANDARDS_HTML`/
`TRACK_STANDARDS_SOURCE_URL` in `scripts/convert-wma-tables.mjs` and re-run —
this is a deliberate, documented action, not an oversight (per RESEARCH.md's
State of the Art note that pre-2020 road and pre-2023 track tables are
superseded and must not be bundled; the *factors* half of that rule is
already satisfied here).

## Re-running the converter

1. Download the raw source artifacts into `scripts/wma-source/` (gitignored):
   - `MaleRoadStd2025.xlsx`, `FemaleRoadStd2025.xlsx` from the GitHub repo
     above.
   - `wmatnf23.html` from `howardgrubb.co.uk/athletics/wmatnf23.html`.
   - `wmalookup15.html` from `howardgrubb.co.uk/athletics/wmalookup15.html`.
2. `node scripts/convert-wma-tables.mjs`
3. The script logs, per table, the edition, the number of ages and distances
   parsed, and the parsed `male`/`5k`/age-50 factor (road) so a re-run is
   self-evidencing. A re-run against unchanged source files reproduces a
   byte-identical `factors`/`openStandardSec` block — only `generatedAt`
   differs.

## Schema

Both files share the same shape:

```json
{
  "schemaVersion": 1,
  "generatedAt": "<ISO string>",
  "note": "<provenance note>",
  "surface": "road" | "track",
  "edition": "<factor-table edition>",
  "source": "<factor-table source URL>",
  "openStandardSec": { "male": { "<distanceKey>": 0 }, "female": { "...": 0 } },
  "factors": { "male": { "<distanceKey>": { "<age>": 0 } }, "female": { "...": {} } }
}
```

`track-factors.json` additionally carries `standardsEdition` and
`standardsSource`, documenting the open-standards provenance separately from
the factors provenance (see "Why two different pages" above).

Distance keys: road uses `5k`, `10k`, `half`, `marathon` (matching
`TargetDistanceKey` in `src/analytics/best-effort.types.ts`); track uses
`400m`, `800m`, `1mi`. `800m` is intentionally not a `TargetDistanceKey` — it
exists only so `1k` can be interpolated between `800m` and `1mi`
(`interpolate1kFactor` in `src/analytics/wma-factors.ts`), per D-09.
