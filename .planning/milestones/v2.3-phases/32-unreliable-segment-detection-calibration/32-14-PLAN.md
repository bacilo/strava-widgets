<interfaces>
The three defect sites, as committed:
- `findValley` (~1070-1111): `counts` bins ALL of `values` over edges spanning
  `floor(lowMetres/binWidth)*binWidth` to `floor(highMetres/binWidth)*binWidth`, so the first bin
  counts values below `lowMetres` and the last counts values at or above `highMetres`. `maxLeft` /
  `maxRight` come from `counts.slice(0, i)` / `counts.slice(i + 1)`, so those out-of-interval bins
  are exactly the shoulders gating `counts[i] <= 0.5 * min(maxLeft, maxRight)`. The docblock already
  claims both are "restricted to the interval". The existing
  `if (maxLeft === 0 || maxRight === 0) continue;` guard (a prior D-13 fix) stays.
- `parseDecisionText` (~751-755): `const [startSec, endSec] = span.split('-').map((s) => Number(s.trim()));`
  with no validation. An en-dash leaves the span unsplit, so `startSec` is NaN and `endSec` is
  undefined. Today's real Decision line uses plain hyphens (`7409028052:586-624`,
  `3647739864:945-971`) and parses correctly — latent, not manifesting.
- `namedItemSegmentMetres` (~1131-1144): returns `segment.metres` for the FIRST segment overlapping
  `item.window`, never checking for a second.

`HIDDEN_PAUSE_BIN_WIDTH_METRES = 20`. On the live archive `valleyFound` is false both pre- and
post-merge, and the shipped `HIDDEN_PAUSE_MIN_METRES = 116.95` is the anchor interval's MIDPOINT
fallback (D-08), not a found valley.
