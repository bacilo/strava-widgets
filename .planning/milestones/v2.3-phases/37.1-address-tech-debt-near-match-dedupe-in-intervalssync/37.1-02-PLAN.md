## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| intervals.icu API -> IntervalsSync | `start_date`, `id`, `name` in the payload are untrusted |
| archive JSON -> IntervalsSync | `start_date`, `source_provider` read from data/activities/*.json |
| IntervalsSync -> nightly CI log | log lines are public in the CI run output |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-37.1-input | Tampering | near check on payload start_date | mitigate | Non-finite epochs never match (findNearMatch, plan 01 unit rows); loadArchiveIndex only indexes finite epochs; the exact path is unchanged |
| T-37.1-05 | Information disclosure / log injection | near-skip log line and nearMatches | mitigate | Line and result carry ids, ISO start date and signed integer delta only; no activity name; acceptance grep checks the line has no `name` |
| T-37.1-06 | Denial of service | swallowing genuine runs | mitigate | Scope limited to FIT-imported records read from disk, never batch-added epochs; still-written rows for intervals, Strava-origin, strava-export and an in-batch 60 s pair |
| T-37.1-07 | Tampering | corrupt FIT-imported record falls out of the index | accept | Same fail-open behaviour as the exact path; throwing would abort the nightly sync; documented in the comment (research P4) |
| T-37.1-08 | Repudiation | silent skip | mitigate | One log line per skip, nearMatches on the result, summary count in index.ts |
| T-37.1-02 | Tampering | data/ tree during tests | mitigate | Temp dirs only, directory-digest guard, existing snapshotDataTree in fit-import.test.ts; `git status --porcelain -- data` empty after each run |

No package installs in this plan, so no supply-chain row.
