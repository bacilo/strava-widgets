<position_on_scope>
## Should the static route also get the Origin/Host gate? Yes. Reasoning, from D-12's own text.

D-12's operative sentence scopes the header check to writes: *"every write rejects unless
`Origin`/`Host` matches the curate origin."* Read alone, that would let the liveness fix stand on
its own. But D-12's justification sentence is broader and is what this gap actually falsifies:
*"Binding alone satisfies the literal 'localhost-only' wording but leaves the endpoint reachable
from any other tab in the developer's own browser; the header check closes drive-by CSRF and DNS
rebinding in a few lines of Node built-ins."*

DNS rebinding is a Host-header attack and is route-agnostic — a rebound hostname reaches the static
route exactly as easily as the write route, and the static route today accepts it. And
`24-VERIFICATION.md` records the key link `any browser tab → curate-server.mjs static route →
safeResolve` as **✗ NOT GATED**, phrasing its failed truth 5 as *"D-12's Origin/Host gate protects
the curate server ... from any other browser tab, including hostile pages"*. A liveness-only fix
leaves that key link unwired and truth 5 re-fails on the next verification pass.

So: apply `isTrustedOrigin(req, EXPECTED_HOST)` to `serveStaticRoute`, reusing the existing
predicate unchanged. Two consequences to handle deliberately rather than discover:

1. An ordinary browser navigation to `http://127.0.0.1:4173/strava-widgets/` sends a matching
   `Host` and no `Origin`, so `isTrustedOrigin` returns true — the tool keeps working. Subresource
   loads (`<script>`, `<link>`) behave the same. This is asserted, not assumed (T1 control case,
   T3 live smoke).
2. A developer who types `http://localhost:4173/...` instead of the banner's `127.0.0.1` now gets
   403 on every asset instead of a working page. That is a deliberate, disclosed behaviour change
   and OD-4's start banner already prints the correct URL. The 403 body must name the expected
   origin so the failure is self-explaining rather than mysterious.

**Not widened:** `/__curate/health` and `/__curate/overlay.js` remain ungated GETs. They serve a
local-only, non-secret script to a local-only server and carry no write. Gating them is not in
`24-VERIFICATION.md`'s `missing` list, and is recorded as an accepted residual in the threat model
rather than silently added.
