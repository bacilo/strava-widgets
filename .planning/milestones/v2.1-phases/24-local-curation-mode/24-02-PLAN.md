<objective>
Add D-03's two inert additions to the published dashboard: a `data-activity-id` attribute on
the "Best Efforts This Run" `<section>`, and one `dashboard:best-efforts-mounted` CustomEvent
dispatched at the exact moment the panel is in the DOM. These are the ONLY changes this phase
makes to published dashboard source, and they ship in the public bundle deliberately — they
carry no endpoint, no write and no curate code, so criterion 3 is untouched by them.

Purpose: `mountBestEffortsAndBadges` is fired without `await` behind a `requestToken` guard,
so an overlay cannot assume the panel exists at any point after navigation. The event gives it
a defined moment to attach; the attribute gives it a stable handle that does not couple curation
to display strings like `"400 m"` or to table column order (the MutationObserver approach D-03
explicitly rejected).

Output: a modified `detail-sections.ts` and `detail.ts`, plus a new source-structure regression
guard proving both halves — the only kind of proof this repo can produce, since `vitest.config.ts`
is `environment: 'node'` with no DOM library anywhere in `package.json`.
</objective>

    `panelContainer.replaceChildren(buildBestEffortsSection(rows, exclusionReason, detail.id));`

    (b) Immediately after that line, as the LAST statement of the function, dispatch
    `container.dispatchEvent(new CustomEvent('dashboard:best-efforts-mounted', { detail: { activityId: detail.id }, bubbles: true }))`.

    `bubbles: true` is load-bearing: the curate overlay's script tag is injected at the end of
    `index.html` and attaches a single listener on `document`, which is the only target that
    reliably exists before any view container does. Dispatching on `container` with bubbling
    reaches `document` through `#app` without the overlay needing to know container identity.

    Position is non-negotiable and must be recorded in a comment: the dispatch goes AFTER the
    `myToken !== requestToken || mountedContainer !== container` guard has passed AND AFTER
    `panelContainer.replaceChildren(...)` has placed the section in the DOM. Dispatching right
    after the guard would fire before the `<section data-activity-id="...">` exists in the
    container the overlay queries against; dispatching before the guard would attach the overlay
    to a panel a fast activity-to-activity navigation is about to discard.

    Extend the function's existing JSDoc with a sentence naming this as D-03(b) and stating that
    the event is inert — it carries only the activity id, performs no fetch, and reaches no
    endpoint.

    other `requestToken` guard in the file stay untouched.
