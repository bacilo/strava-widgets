## 19-10: `npm test` file-level failures unrelated to this plan (worktree environment gap)

**Found during:** Task 1 verification gate (`npm test`).

**Observation:** `npx vitest run` reports 5 failed test *files* against 837 passed *tests*, 0 failed:

```
FAIL src/dashboard/views/records-logic.test.ts
FAIL src/dashboard/views/trends-cadence-hr-logic.test.ts
FAIL src/dashboard/views/trends-gear-logic.test.ts
FAIL src/dashboard/views/trends-training-load-logic.test.ts
FAIL src/dashboard/views/trends-yoy-logic.test.ts
 Test Files  5 failed | 41 passed (46)
      Tests  837 passed (837)
```

Each failure is `ENOENT: no such file or directory, open 'data/stats/<name>.json'` at module-load time (e.g. `data/stats/year-over-year.json`). `data/stats/` is gitignored (`.gitignore` line: `data/stats/`) and populated only by `npm run compute-all-stats` against live intervals.icu data. The affected test file's own header comment states this explicitly: *"absent on a fresh clone until that pipeline runs"* (`trends-yoy-logic.test.ts:18`).

**Root cause:** this plan runs inside a `git worktree`-isolated agent. `git worktree add` checks out only tracked files; gitignored data generated by the daily pipeline in the main checkout is not shared with worktrees. This is a structural characteristic of worktree-based parallel execution, not a regression introduced by plan 19-10 — `src/dashboard/styles.css` and `src/dashboard/styles.test.ts` (this plan's only files) have zero relationship to `data/stats/*.json`.

**Scope decision:** not fixed, per SCOPE BOUNDARY — out of scope for a CSS/stacking-context plan, and running the live-data pipeline (`compute-all-stats`) requires intervals.icu credentials not appropriate to invoke from an isolated worktree agent. `npx vitest run src/dashboard/styles.test.ts` (this plan's actual surface) is 50/50 green; the delta against the plan's stated 919-test baseline is not meaningfully computable from this worktree because 5 unrelated files never load. Recommend either committing minimal fixture data for these 5 files' live-data describes, or excluding them from worktree-mode `npm test` runs, in a future infra plan — not proposed here as an architectural change (Rule 4) because it is out of this plan's scope entirely.

## 19-16, 2026-08-13: WR-03 — ten selectors hardcode literal `4px`/`8px`/`6px` instead of the radius tokens

**Found during:** Task 3, cross-checking `19-VERIFICATION.md` § Gaps Summary WR-03 against Round 4's actual scope.

**Observation:** `19-VERIFICATION.md` names ten selectors in `src/dashboard/styles.css` that declare literal pixel radii (`4px`/`8px`/`6px`) instead of `var(--radius-control)`/`var(--radius-panel)`. The verifier independently confirmed this is not currently a rendering defect: the literal values equal the token values, so the rendered rhythm is presently consistent — it is a maintainability warning, not a visible break.

**Reasoning:** Deferred out of Round 4 for three reasons. First, it is not a rendering defect today, per the verifier's own independent confirmation that literal and token values currently match. Second, Round 4 (plans 19-13 through 19-16) is scoped to GAP 7's diagnosis, fix, and guard-layer hardening, not a token-adoption sweep. Third, changing ten selectors' radii immediately before the phase-gate checkpoint would introduce ten rendered changes that each need their own honestly-discharged checkpoint row — landing that in the same wave as a gate that is open precisely because rendered changes were discharged in bulk (CR-01/CR-02/CR-03 at the 19-09 checkpoint) would repeat the exact failure shape this phase exists to close.

**Re-entry trigger:** the next phase that retunes `--radius-control` or `--radius-panel`. At that point the ten literal-value selectors will silently split off from the rest of the control set — they will not track the retuned token — and the drift becomes a real rendering defect rather than a coincidental match.

**Scope decision:** not fixed this round. Tracked here so the next token-retuning phase inherits the list rather than rediscovering it.
