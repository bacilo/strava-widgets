<objective>
Remove the last known way for an assertion in this file to pass for the wrong reason.

Purpose: `selectorListDeclares` splits a rule head on every comma, including commas nested inside `:not()`. Against plan 19-03's shared hover selector this produces a fragment byte-identical to the real `[aria-disabled="true"]` needle used at `styles.test.ts:249`. It returns the correct answer today only because the hover rule's body happens not to contain `opacity: 0.6`. That is a coincidence, and this phase has already shipped one defect that survived behind a test passing for the wrong reason.

This is the same failure class as GAP 1 — a check that appears to interrogate structure but is actually matching text at a position the structure does not reach. Plan 19-06 closed that class for the stylesheet's parse; this plan closes it for the test file's own selector parsing.

Output: a depth-aware splitter, self-tests for it, and a recorded audit of what the remaining helpers can and cannot catch.
</objective>

<groundwork>
Verified empirically during planning. The mutation below is the discriminating experiment; use it rather than inventing one.

**The collision.** `selectorListDeclares` (`styles.test.ts:44-57`) does `head.split(',').map(s => s.trim())` and requires an exact token match. Splitting the shared hover rule's head yields, among others, the exact string `[aria-disabled="true"]` — which is also the needle at line 249.

**Verified discriminating mutation.** Two changes together, both required:

1. Delete the real `:disabled, [aria-disabled="true"] { … }` rule.
2. Add `opacity: 0.6;` to the **shared hover rule's** body — the rule whose head contains `:where(:not(`.

Step 2 must target the hover rule specifically. `.activity-table tbody tr:hover` carries a byte-identical `background: color-mix(in srgb, var(--surface) 92%, var(--text));` declaration and appears earlier in the file, so a naive string replacement of that declaration hits the wrong rule and the mutation silently fails to reproduce. This was observed during planning.

**Measured outcome of that mutation on `selectorListDeclares('[aria-disabled="true"]', 'opacity: 0.6')`:**

| Splitter | Result | Meaning |
|----------|--------|---------|
| naive `head.split(',')` | `true` | **false pass** — the real rule is deleted and the assertion still passes |
| depth-aware top-level split | `false` | correct red |
| depth-aware split, unmutated file | `true` | no regression on the real rule |

**The fix.** Split the head character by character, tracking parenthesis depth, and break only on a comma at depth 0. `19-REVIEW.md` § WR-03 contains a reference implementation of `splitTopLevelSelectors`.

**Scope note.** `ruleWithHeadContaining` (added by plan 19-04) already sidesteps comma splitting by matching a substring of the head, so it is unaffected. `declarationsFor` does not split on commas at all. This plan changes one helper.
</groundwork>
