<objective>
Make both Records activity tables row-navigable using the shared helper, move the link into the
Date cell, and delete the two redundant "View Activity" CTA columns.

Purpose: REC-08 ("Records rows navigate on row click rather than via a large button"), UX-01
and UX-02 on the Records screen. Today these rows already *look* clickable - they inherit
`.activity-table tbody tr { cursor: pointer }` and the row hover - while having no click
handler at all. That mismatch is the single most visible defect this phase fixes, and is the
likely source of the "View Activity does not navigate" confusion recorded in `19-VALIDATION.md`
whose cause was never established.

Output: `records.ts`'s `buildPrTable` and `buildProgressionTable` produce navigable rows with a
Date-cell anchor and no CTA column.
</objective>

  `export function activityDetailHref(activityId: string): string`   // '#/activity/<id>'

`attachRowNavigation` adds the `activity-table__row--navigable` marker class and a `click`
listener guarded by `closest('a')`, navigating through `navigateTo`. It sets no `tabindex` and
no `role` (D-01).

Row types this plan reads, from `src/dashboard/views/records-logic.ts`:

  `PrTableRow` (`records-logic.ts:47-56`) - carries `rank`, `durationSec`, `paceSecPerKm`,
  `agePercent`, `ageDerived`, `startDate`, `activityId`, `lowConfidence`, `excluded`,
  `exclusionReason`. **It carries no activity name.**

  `ProgressionRow` (`records-logic.ts:188-194`) - carries `activityId`, `startDate`,
  `durationSec`, `improvementSec`. **It carries no activity name.**

Already in `records.ts` and reused unchanged:

  `DISTANCE_LABELS: Record<TargetDistanceKey, string>` (`records.ts:64`) - the human label for
  a target distance, already used for headings at `records.ts:420` and `records.ts:533`.
  `formatActivityDate`, `formatEffortDuration`, `formatPace` - imported from `./list.js`.

`records.ts` currently imports neither `navigateTo` nor `router.js`. It must continue not to -
it imports the helper, which owns the router dependency.
