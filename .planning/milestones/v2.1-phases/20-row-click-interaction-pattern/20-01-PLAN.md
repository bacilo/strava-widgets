Create `src/dashboard/row-navigation.ts` with four exports:

1. `NAVIGABLE_ROW_CLASS` - a `const` string whose value is exactly `activity-table__row--navigable`.
   This is D-10's scoping marker. It must be defined here and only here, because plan 20-04's
   stylesheet rules and its test assertions both key off this literal string.
2. `activityDetailPath(activityId: string): string` - returns the router path
   `/activity/<activityId>` (leading slash, no leading `#`, no query). This is the argument
   shape `navigateTo` expects and the shape `buildTableRow` already passes.
3. `activityDetailHref(activityId: string): string` - returns `#` concatenated with

   `activityDetailPath`, not as a second independent template literal - one definition, per

   20-03.

   `buildTableRow` behavior. It must do exactly two things and nothing more:
   - add `NAVIGABLE_ROW_CLASS` to `rowEl.classList`;

     `(event.target as HTMLElement).closest('a')` is truthy, and otherwise calls
     `navigateTo(activityDetailPath(activityId))`.

   It must NOT set `tabindex`, must NOT set `role`, must NOT register a `keydown` listener, must
   NOT add extra guards for text-selection drags or modifier/middle clicks, and must NOT assign
   `location.hash`. Claude's Discretion in `20-CONTEXT.md` defaults to "match what `list.ts`
   already ships (the `closest('a')` guard only)" - take the default. Anything beyond it is a
   behavioral change to the interaction model Phase 19's success criterion 4 froze, and would
   require a checkpoint call-out.

Write a file-header comment covering, in prose:

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| dashboard index JSON -> DOM | Activity ids and athlete-authored names read from published JSON are interpolated into DOM node properties. The publishing pipeline is trusted, but the interpolation discipline is what has to hold. |
| user click/keyboard -> hash router | The only state change this module can cause is a same-origin hash navigation. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-20-URL-01 | Tampering | `activityDetailHref` / `activityDetailPath` string interpolation | mitigate | The returned string is always prefixed `#/activity/`, so no `javascript:` or `data:` scheme is reachable regardless of the id value. The value is assigned to the `href` property of a created element by callers (plans 20-02/20-03), never parsed as HTML. `isValidActivityId` (`/^i?\d{1,20}$/`, `router.ts`) remains the chokepoint that rejects a malformed id before any fetch is issued. |
| T-20-NAV-02 | Tampering | `attachRowNavigation`'s click listener | mitigate | Navigation goes only through `navigateTo` (`router.ts:171-177`). Task 1's automated check rejects any direct `location.hash =` assignment in this module; plan 20-04 extends the same check across every view file. |
| T-20-A11Y-03 | Denial of Service (usability) | row-level click listener double-firing with an in-row anchor | mitigate | The `closest('a')` guard is preserved verbatim from `list.ts:339-341`, and Task 1's automated check fails if it is absent. |
| T-20-SC | Tampering | npm/pip/cargo installs | mitigate | Zero installs are authorized in this phase. Do not add `jsdom`, `happy-dom`, `puppeteer` or `playwright` as an escape hatch for the DOM assertions this repository deliberately cannot make. No `## Package Legitimacy Audit` is required because no plan in this phase installs a package. |
