<objective>
Turn the three `<div class="activity-row">` renderers into real `<a class="activity-row">`
elements, delete the redundant "View Activity" CTA from the Activities mobile card, and move
`buildTableRow`'s inline click handler onto the shared helper from plan 20-01.

Purpose: UX-01 (every activity row is clickable), UX-02 (redundant CTAs removed where the row
itself is the affordance) and UX-03 (a real link semantic, not a click handler on a bare
`<div>`) on the Overview and Activities surfaces.

Output: `list.ts` and `overview.ts` produce whole-row links with a curated `aria-label`, and
`list.ts` no longer carries its own copy of the row-click guard.
</objective>

`attachRowNavigation` adds the marker class and a `click` listener guarded by `closest('a')`,
navigating via `navigateTo`. It sets no `tabindex` and no `role`, and registers no `keydown`
listener (D-01, D-02).

Existing `list.ts` helpers this plan reuses unchanged:

  `formatActivityDate(startDateLocal: string): string`
  `formatDurationHms(sec: number): string`
  `formatPace(secPerKm: number): string`
  `appendStatusBadges(container: HTMLElement, row: DashboardIndexRow): void`

`appendStatusBadges` (`list.ts:181-199`) and `appendLowConfidenceBadge` emit only
non-interactive `<span>` elements - the low-confidence badge uses `title` +
`aria-describedby` + an `.sr-only` span. There is therefore no focusable-inside-focusable
conflict when they are nested inside a whole-row `<a>`, and `closest('a')` remains a sufficient
click guard. This was verified during pattern mapping; do not re-derive it.

`overview.ts:15` already imports `renderActivityRow, formatActivityDate` from `./list.js`. It
imports neither `navigateTo` nor `router.js`, and must continue not to - it imports the helper
instead.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `dashboard-index.json` -> DOM | `row.name` is athlete free text and `row.id` is an activity id; both are interpolated into DOM node properties on every row this plan touches. |
| user click/keyboard -> hash router | Row activation causes a same-origin hash navigation and nothing else. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-20-VW-01 | Tampering | `renderActivityRow` / `renderRecentPrRow` athlete-name rendering | mitigate | `row.name` reaches the DOM only through `textContent`, never `innerHTML`/`outerHTML`/`insertAdjacentHTML` (T-16-VW-01, T-17-VW-01). Both tasks' automated checks fail on any HTML-string assignment in the file. The new `aria-label` is set with `setAttribute` on a created element, so its value is never parsed as markup either. |
| T-20-VW-02 | Tampering | `href` interpolation on the new whole-row anchors | mitigate | Every `href` comes from `activityDetailHref`, which always prefixes `#/activity/`, so no `javascript:` or `data:` scheme is constructible from an id. The value is assigned to the `href` property of a created element, never through HTML parsing. `isValidActivityId` (`/^i?\d{1,20}$/`) remains the router-side chokepoint. |
| T-20-VW-03 | Elevation of Privilege | focusable content nested inside a whole-row anchor | accept | `appendStatusBadges` and `appendLowConfidenceBadge` emit only non-interactive `<span>` elements (verified at `list.ts:158-199` during pattern mapping), so no nested interactive element is created and `closest('a')` stays a sufficient guard. Re-verified by plan 20-05's keyboard checkpoint row, which counts tab stops per row. |
| T-20-SC | Tampering | npm/pip/cargo installs | mitigate | Zero installs authorized. Do not add jsdom, happy-dom, puppeteer or playwright to automate the row-click assertions this repository deliberately cannot make. |
</threat_model>
