## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `localStorage` → `readStoredWeekStart` | A value writable by the user via devtools, by a browser extension, or by any other same-origin script. This is the ONLY new untrusted-input path in phase 22 |
| browser storage subsystem → this module | `getItem`/`setItem` can throw (Safari private mode, disabled cookies, quota exceeded) even when the value itself is benign |

There is no network, auth, session or access-control surface in this phase: the dashboard is a
static client-only SPA over already-public published JSON.

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-22-WK-01 | Tampering | `readStoredWeekStart` / `parseWeekStart` in `calendar-preferences.ts` | mitigate | ASVS V5 allow-list parse: `parseWeekStart` accepts ONLY the exact literals `'sunday'` and `'monday'` and returns `'monday'` for every other input, including case variants. No normalisation, no repair, no write-back. Unit-covered against `null`, `undefined`, `''`, `'MONDAY'`, `'Sunday'`, `'3'`, `0`, `{}`, `[]`, `true`. Header note mirrors `theme.ts`'s `T-16-TH-01` convention |
| T-22-WK-02 | Denial of Service (client-side) | `storage.getItem` / `storage.setItem` | mitigate | try/catch around BOTH paths, matching `theme.ts:63-69` and `theme.ts:101-108`. A throwing `getItem` returns `'monday'` rather than propagating an exception that would abort `calendar.ts`'s `mount()`; a throwing `setItem` is swallowed because the grid is already rebuilt and that is the behaviour that matters.
