<objective>
Generalize the Calendar's pure grid math off its hard-coded Sunday-first assumption, and add the
per-week total derivation CAL-02 needs — both inside `calendar-logic.ts`, which stays pure,
DOM-free and total.

Purpose: ROADMAP success criterion 2 is explicit that `buildMonthGrid`'s Sunday hard-coding must be
generalized and unit-covered for both week-start values, not just restyled. Everything downstream in
this phase (the persistence module, the view wiring, the October 2025 checkpoint read-back) depends
on this function being correct first, so this is Wave 1 and nothing runs beside it.

Output: `buildMonthGrid(rows, month, weekStart)` with a required third parameter, a `WeekStart`
union exported for the rest of the phase, `totalTimeSec` on `DayCell`, a `WeekTotal` interface, a
`weekTotals` array on `MonthGrid`, and a test file that pins both week starts explicitly.

**Explicitly NOT in scope (D-15).** No change to `src/dashboard/views/trends-logic.ts`,
`src/dashboard/views/records-logic.ts`, `src/types/analytics.types.ts`, the streak logic, or the
build-time pipeline. `weekStartISO` stays Monday-fixed everywhere outside the Calendar view. A user
who selects Sunday will still see Monday-based weeks on Trends; that inconsistency is knowingly
shipped and is NOT a gap.

**Explicitly NOT in scope (settled discretion).** `monthTotalTimeSec` is deliberately NOT added to
`MonthGrid`. RESEARCH.md Open Question 2 floated it as "free"; no success criterion asks for a
month-level time figure and `calendar.ts:243` renders only km and run count, so an unread field
would be scope with no consumer. Do not add it.
</objective>
