<objective>
Close `22-REVIEW.md` **WR-01** / `22-VERIFICATION.md` **truth #8**: `theme.ts` silently discards an
explicit `storage: null` override, which makes three of Round 3's own BL-03 tests vacuous passes of a
different code path. Also land the `isAuto` seam that plan `22-14` needs to fix CR-01.

Purpose: `theme.ts:108` and `theme.ts:145` compute `resolveStorage(options.storage ?? undefined)`.
`null ?? undefined` is `undefined`, and `resolveStorage(undefined)` falls through its `if (override)`
truthiness check straight to `globalThis.localStorage` — so an explicit "do not persist" instruction is
upgraded to the REAL browser store. The three `theme.test.ts` cases at ~199, ~206 and ~267 that pass
`storage: null` pass only because `vitest.config.ts` sets `environment: 'node'` repo-wide with no setup
file assigning `globalThis.localStorage`, so the fallthrough happens to land on `null` by accident.
Under jsdom or in a real browser those same test bodies would read and WRITE the real `localStorage`.
That is the same vacuous-pass shape this phase was already penalised for in Rounds 1 and 2.

Output: an override contract that honours `null`; `theme.ts` passing `options.storage` through
untouched; `watchSystemTheme` gaining an `isAuto` guard option; and replacement tests that install a
live sentinel `globalThis.localStorage` so every degraded-storage assertion **fails if the override is
ignored**.

**Explicitly NOT in scope.** No change to `nav.ts` (that is plan `22-14`), no change to
`styles.css` (plan `22-15`), no new npm package, no change to `vitest.config.ts`'s
`environment: 'node'` — this repo deliberately has no jsdom and this plan does not add one. The D-15
scope fence stands.
</objective>
