proves, that it uses zero new dependencies, and that it exists because the browser-extension

CLI flags, parsed in the `process.argv.includes(...)` style already used for `--ci` in
`src/index.ts`:

  --url URL              target to navigate to; default `https://bacilo.github.io/strava-widgets/`
  --mechanism NAME       one of `screencast`, `screenshot-burst`, `throttled`; required
  --throttle-ms N        only for `throttled`; the additional latency to impose
  --out DIR              where frames and the JSON report are written; default a timestamped
                         directory under `.planning/phases/25-ci-hardening-light-theme-verification/capture/`
  --keep-open            leave Chrome running after the run, for eyeball inspection

Mechanics:

1. Launch Chrome as a child process from `/Applications/Google Chrome.app/Contents/MacOS/Google
   Chrome` with `--remote-debugging-port` on an ephemeral port, a fresh `--user-data-dir` under the
   OS temp dir (throwaway per run — this is what guarantees cleared site data and an empty HTTP
   cache), `--no-first-run`, `--no-default-browser-check`, and `about:blank` as the start URL.
   Launch HEADFUL. Do NOT pass any headless flag: headless Chrome does not follow the macOS
   appearance setting, which would silently defeat D-05's whole discriminator. Do NOT pass any flag
   or send any CDP command that forces a colour scheme.

2. Discover the page target by polling `http://127.0.0.1:PORT/json/list` with global `fetch` until a
   target of type `page` appears, then open a `WebSocket` (Node global, no dependency) to that
   target's `webSocketDebuggerUrl`. Implement a small id-to-promise correlation map for CDP
   request/response plus an event listener registry — roughly 40 lines, not a library.

3. Enable the domains the mechanism needs (`Page.enable`, and `Network.enable` only for the
   `throttled` mechanism) BEFORE navigating, so no frame is missed.

4. For `screencast`: call `Page.startScreencast` with `format: 'png'` and `everyNthFrame: 1`, at a
   quality and max width/height that do not throttle delivery, then `Page.navigate` to the target
   URL. On each `Page.screencastFrame` event, immediately send `Page.screencastFrameAck` (frames
   stop arriving without the ack), write the base64 payload to a `frame-NNN.png` file under the out
   directory, and record that frame's `metadata.timestamp` — which CDP reports as
   `Network.TimeSinceEpoch`, i.e. SECONDS since the Unix epoch. Convert to milliseconds so it is
   directly comparable to the page's own `performance.timeOrigin`.

   For `screenshot-burst`: navigate, then issue `Page.captureScreenshot` in a tight loop from the
   moment the navigation event fires, recording `Date.now()` at request and at response for each
   shot. This mechanism exists to reproduce and quantify the ~855 ms floor from a different client
   than the browser extension, so the report can say whether that floor was the extension's or this
   machine's.

   For `throttled`: same as `screencast`, but before navigating call
   `Network.emulateNetworkConditions` with `offline: false`, a `latency` of the `--throttle-ms`
   value, and downlink/uplink throughputs low enough to widen navigation-start to first-paint.
   Record the exact emulation parameters in the report — this is a disclosed deviation, not a hidden
   setting.

5. After the load event fires, evaluate one expression via `Runtime.evaluate` returning a single JSON
   object carrying: `performance.timeOrigin`; the `first-paint` and `first-contentful-paint` entries'
   `startTime` from `performance.getEntriesByType('paint')`; that navigation entry's `responseEnd`,
   `domInteractive`, `loadEventEnd` and `type`; `localStorage.getItem('dashboard-theme')`;
   `matchMedia('(prefers-color-scheme: dark)').matches`;
   `document.documentElement.getAttribute('data-theme')`; the computed `body` background colour; the
   `script[type=module][src]` hashed asset filename; and `document.title`.

6. Sample each captured frame's background colour without a new image library: decode the PNG pixel
   data using Node's built-in `zlib.inflateSync` over the IDAT chunks and read a small fixed sample
   set (the four corners inset by 8 px plus the centre), reporting each sample as an `rgb(r, g, b)`
   string. If PNG decoding proves disproportionate, switching to a lossy format is NOT an acceptable
   substitute for exactness — instead write the frames and report the mechanism's timing only,
   marking the colour column `not-sampled (frames retained at PATH)` so a human can judge them. Do
   not silently guess a colour.

7. Emit a JSON report to `report.json` in the out directory AND a human-readable summary to stdout
   containing, per frame: sequence number, absolute timestamp in ms, `t_since_navigation_ms` (frame
   timestamp minus `timeOrigin`), `beats_first_paint` (boolean: `t_since_navigation_ms` at or below
   the first-paint startTime), and the sampled colours. Print a final line naming the earliest frame
   that beats first paint, or stating that none did.

8. Exit code 0 if the run completed and produced a report; exit 1 if Chrome could not be launched,
   the CDP socket could not be opened, or the page never fired its load event within a timeout. The
   exit code is about the harness working, NOT about whether a frame beat first paint — that is a
   measurement, not a pass/fail.

Always kill the Chrome child process and remove the throwaway user-data-dir on exit unless
`--keep-open` was passed. Do not add anything to `package.json`: the harness is invoked as `node
scripts/first-paint-capture.mjs`, because it is checkpoint instrumentation rather than part of any
gate.
