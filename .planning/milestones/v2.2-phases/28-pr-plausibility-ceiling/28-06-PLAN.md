<objective>
Make the ceiling's movement visible after ship, not just at ship: persist the derived per-distance
ceiling into a small committed file, diff each run against it, report any movement, and commit the
update through the nightly data-commit path that already exists.

Purpose: nightly CI regenerates `best-efforts.json` every day, so a silently re-derived ceiling could
re-admit a demoted effort weeks after the PR-04 review. D-06 requires the movement be reported;
D-07 requires the previous value be durable, and `data/stats/` is gitignored and starts empty on
every runner, so a committed file is the only durable place. Git history then becomes the audit
trail: every ceiling move is a commit that can be blamed.

Output: a never-throwing state module, its wiring into the compute step, the seeded committed file,
and one added glob on the existing CI commit step.
</objective>

    comparison here would hide exactly the drift this file exists to catch.

    `formatCeilingMovement(rows)` renders the rows as console lines in the house register — a named
    condition with its measured values, never an adjective — for example

    string array so the caller decides how to print, keeping this module free of side effects other
    than the loader's warnings.

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-28-06-E | Repudiation | a ceiling moving with nobody seeing it | mitigate | Every run prints a movement section or an explicit unchanged line, and a move produces a committed diff that `git blame` attributes — D-06's whole point. |
| T-28-06-SC | Tampering | npm/pip/cargo installs | mitigate | Not applicable — zero packages installed. The pinned `git-auto-commit-action` SHA is unchanged, so no new third-party action version is introduced either. |
