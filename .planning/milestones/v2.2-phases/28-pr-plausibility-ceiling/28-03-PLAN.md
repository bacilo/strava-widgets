<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| archive-derived effort population → ceiling derivation | The population array originates in stream-derived data that can contain non-finite or negative values from a corrupted stream. |
| derived reason string → shipped JSON and rendered badge | The demotion reason is written into `best-efforts.json` and later displayed. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-28-03-A | Denial of Service | `deriveCeiling` on a corrupted population | mitigate | An empty population returns the fail-open shape rather than throwing, asserted by a test; the sort operates on a copy so a caller's array cannot be corrupted; no branch divides by a possibly-zero population size without the floor check having run first. |
| T-28-03-B | Tampering | the derived `ceilingMps` value | mitigate | The derivation's signature admits only a distance key and a population array, so no caller can pass a pre-computed ceiling, a date window, or a target count — PR-02's non-circularity is enforced by the type, not by convention. |
| T-28-03-C | Tampering | the reason string emitted into shipped JSON | mitigate | The string is assembled from numbers via `toFixed` and fixed literals only; no caller-supplied text is interpolated, so a corrupted archive cannot inject content into a reason that a later plan renders. |
| T-28-03-D | Repudiation | an undocumented constant change | mitigate | Both constants cite `28-CEILING-CALIBRATION.md` by section in their doc comments, and a test pins the exact reason string that embeds `CEILING_K`, so changing the constant without regenerating the artifact fails a test. |
| T-28-03-SC | Tampering | npm/pip/cargo installs | mitigate | Not applicable — zero packages installed. 28-RESEARCH.md records `simple-statistics` and `d3-array` as vetted and rejected; any install here is a defect. |
