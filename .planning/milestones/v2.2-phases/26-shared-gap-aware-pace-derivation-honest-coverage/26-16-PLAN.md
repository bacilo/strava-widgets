**Where the quotable evidence comes from — read this before writing a row.** The chart bands are
Chart.js canvases. A screenshot of a chart is not quotable evidence of the values it plots; this
project has a recorded lesson saying so. Two surfaces on this page carry evidence, and they are
different in kind:

- The **Pace Distribution histogram is DOM** (`buildPaceDistributionRows` in `detail-sections.ts`),
  so its bar labels are quotable text a human can read and copy directly.
- The **pace chart band's y-axis tick labels are canvas `fillText` calls**, formatted by
  `formatPaceValue` as `M:SS/km`. The only way to get them as quotable strings is to patch
  `CanvasRenderingContext2D.prototype.fillText` in the DevTools console BEFORE the band re-renders,
  then force a re-render via a hash-route change (the prototype patch survives the route change;
  a full page reload would discard it).

  The x-axis tick format is `M:SS` in time mode and `N.N km` in distance mode — neither matches
  `/^\d+:\d{2}\/km$/`, so that regex cleanly isolates the pace y-axis. The tooltip label reads
  `Pace: M:SS/km`, which also does not match the anchored regex, so tick capture and tooltip
  reading do not contaminate each other.

**Choosing an assertion that is satisfiable in BOTH directions.** Chart.js picks "nice" round tick
values that may extend BELOW the data minimum — with a data range of `[147, 1049]` the smallest tick
could plausibly be `100` (`1:40/km`). **Do not assert anything about the smallest tick label**: an
assertion like "no tick faster than 2:00/km" is at risk of being unpassable even against a correct
fix, and this project has shipped an unpassable checkpoint row before. Assert on the LARGEST tick
label instead, where the separation is enormous and one-sided: pre-fix the entire plotted extent
tops out at 266.7 sec/km so the largest tick cannot exceed `5:00/km`; post-fix the extent reaches
1,049 sec/km so the largest tick must reach at least `15:00/km`. The fast end is covered instead by
the tooltip row, which reports real data values rather than axis ticks.
