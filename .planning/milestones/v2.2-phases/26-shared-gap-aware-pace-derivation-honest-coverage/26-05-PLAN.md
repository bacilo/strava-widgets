pace sites that are outside PACE-01's scope.

stream pace):

- `src/widgets/shared/route-utils.ts` — `(movingTimeSec / distanceMeters) * 1000` (embeddable widget surface; found by research, not named in D-18)
- `src/analytics/gear-aggregate-logic.ts` — `bucket.movingTimeSec / (bucket.distanceM / 1000)` (per-gear aggregate; found by research, not named in D-18)

From `src/dashboard/curation-seam.test.ts` — the in-repo precedent for a vitest source-text guard:
`readFileSync` against a `new URL(relativePath, BASE_DIR)`, `stripComments` imported from
`./row-semantics.test.js`, and a local `countOccurrences(haystack, needle)` returning
`haystack.split(needle).length - 1`.

From `src/dashboard/row-semantics.test.ts:68-71`:
`export function stripComments(source: string): string` — removes block comments then line comments,
with self-tests already in that file.

From `scripts/lib/curation-guard.mjs:76-100` — the scanner shape to borrow (not import): a pure

Create `src/analytics/pace-single-source.test.ts` with a header stating what it guards (PACE-01,
Criterion 4, D-18), what it deliberately does not guard (metadata-derived pace, naming all four
sites), and that the banned literals quoted in the header are stripped before scanning so the file
cannot flag itself.

Write and export a pure scanner
`findStreamPaceViolations(files: Array<{ path: string; source: string }>): Array<{ path: string; needle: string; count: number }>`
that, for each file, strips comments and then counts occurrences of each banned literal, emitting a
violation for any file other than the allow-listed `pace-derivation.ts` with a non-zero count. The
banned literal list is exactly `dt / (dd / 1000)` and `elapsed / (metres / 1000)`. Taking the file
list as an argument rather than reading the disk inside the scanner is what makes Task 2's planted
violation a permanent in-suite test rather than a one-off.

Write a separate `readSourceTree(rootUrl)` helper doing the recursive `readdirSync` walk over
`src/`, collecting every `.ts` file, with try/catch around both `readdirSync` and `readFileSync`
that records a read failure as its own violation entry rather than throwing (the fail-closed shape
from `curation-guard.mjs`; a directory the audit cannot read must not silently pass).

Then write these tests:
1. `findStreamPaceViolations(readSourceTree(...))` returns an empty array, and the failure message
   lists the offending paths and literals if it does not.
2. False-positive guard, asserted by name in both directions: the returned violations do not
   include `route-utils.ts`, `gear-aggregate-logic.ts`, `compute-dashboard-index.ts` or `detail.ts`
   — AND each of those four files is confirmed present in the scanned file list, so the guard is
   not passing merely because the walk missed them. A guard that passes because it scanned nothing
   is the vacuous-discriminator failure this project has hit before.
3. Override containment: scan the same file list for `clipAtGaps`, and for `windowSec:` and
   `pauseRule:` used as call-site arguments, and assert every match is either inside
   `pace-derivation.ts` or inside a file whose path ends with `.test.ts`. This is what stops a
   production caller silently disabling the gap clipping or pinning a fixed window.
4. `pace-derivation.ts` itself contains at least one of the banned literals — the allow-listed file
   really is where the arithmetic lives, so the audit is not passing because the arithmetic
   vanished entirely.
