# Phase 26 — UI Design Contract

> Visual and interaction contract for Phase 26 (Shared Gap-Aware Pace Derivation & Honest
> Coverage). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Stack reality (confirmed by direct source read, not assumed):** This is a static,
> build-time-rendered SPA. No React/Vue, no component library, no CSS framework, no icon
> library. Markup is produced by hand-written TypeScript DOM-builder functions under
> `src/dashboard/views/`, styled by one global stylesheet (`src/dashboard/styles.css`) that
> already declares a complete token set (spacing, typography, color, radius). This phase adds
> **zero new tokens, zero new CSS classes for color, and zero new dependencies** — every visual
> element specified below reuses an existing class, an existing accessible-badge helper, or an
> existing footnote/legend pattern already shipped in this codebase. Where CONTEXT.md's locked
> decisions (D-08, D-09, D-11) left a concrete markup shape undecided, this spec derives one from
> the nearest existing precedent and marks it `[derived]`.

## Color

Pre-existing theme-aware palette (`styles.css:14-116`), reused unchanged — **this phase adds
zero new color tokens and zero new semantic colors**:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--bg)` (`#ffffff` light / `#1a1a2e` dark) | Page background |
| Secondary (30%) | `var(--surface)` (`#f5f5f7` light / `#242444` dark) | Cards (`.card`), stat tiles, activity rows, `.badge` sits on this background |
| Accent (10%) | `var(--accent)` (`#fc4c02` light / `#ff6b35` dark) | **Unchanged reserved list — this phase does not add to it.** Primary CTA fill, focus ring, chart pace line/bars, loading indicator. None of Phase 26's new elements (coverage caption, gap marker, disagreement badge) use accent. |
| Destructive | `var(--destructive)` (`#dc2626` light / `#f87171` dark) | Destructive actions only (curation exclusion, unrelated to this phase) — not used by any Phase 26 element |

**Accent reserved for (unchanged, confirmed by grep — zero new `var(--accent)` call sites this
phase adds):** primary CTA background, two-tone focus ring, `--chart-pace` line/bar color,
in-flight loading indicator text. Nothing in Phase 26 qualifies for accent treatment.

**Why the new elements stay neutral, not color-coded (a deliberate, derived decision):** The
gap marker (D-09), coverage caption (D-08) and pace-disagreement badge (D-11) are **disclosure,
not alarm** — CONTEXT.md D-12 explicitly frames PACE-07 as "disclosure, not suppression," and
D-08 frames coverage as something a *healthy* run states too, not only an unhealthy one. Coding
these elements in an alarm color (there is no existing warning/amber token in this codebase —
only `--destructive`, which is reserved for actual destructive actions) would misrepresent a
factual disclosure as an error state, and reusing `--destructive` for it would blur the one
existing semantic color's meaning. **Decision: reuse the existing neutral `.badge` treatment**
(`border: 1px solid var(--border)`, `color: var(--text-secondary)`, no fill) for the D-11
pace-disagreement badge, exactly like `PR`, `Low confidence`, `Excluded from records`, `No
streams`, `No HR` today — one consistent badge vocabulary, distinguished by text, never by
color. The `⚠` glyph in the D-09 split marker is likewise rendered in the cell's inherited
`var(--text)` color, not a warning hue — its meaning comes from its paired text (aria-label +
legend), per the accessibility constraint below.

## Copywriting Contract

| Element | Copy |
|---------|------|
| **D-08 coverage caption** (COV-02) — one line, `.text-label`, placed as the first child of the `Pace Distribution` section, directly after the `<h2>` and before the histogram bars | `"{covered}% of elapsed time covered · {recordingGap}% recording gaps · {pause}% paused"` — **always renders all three segments**, even at `0%`, so a clean run states its own health rather than the reader inferring it from an absent line (D-08's explicit requirement). Percentages are whole numbers (`Math.round`), derived from `coverage.coveredSec / span`, `coverage.recordingGapSec / span`, `coverage.pauseSec / span` (the same `derivePaceWithCoverage` result the histogram consumes — D-16's single-return-value contract makes this line structurally unable to drift from the bars beside it). **Known rounding note for the planner:** the three rounded integers may not sum to exactly 100 (e.g. 33/33/34 rounds cleanly but 33.3/33.3/33.4 could round to 33/33/33); this is a cosmetic rounding artifact of *display*, not a violation of COV-01's exact-second sum, which is asserted on the unrounded seconds. Do not "fix" the displayed percentages to force a 100% sum — that would falsify the individual category values. |
| **D-09 split gap marker** (PACE-05) — inline, in the affected split's existing `Pace` `<td>` (`buildTextCell`/`buildKmCell` sibling, second column of `.splits-table`) | Marker: append `" ⚠"` (glyph, `aria-hidden="true"`, wrapped in `<span class="split-gap-marker">`) directly after the formatted pace text (e.g. `5:22/km ⚠`). The `<td>` itself carries `aria-label="{formatted pace} — includes {mm:ss} of {recording gap\|pause}"` (e.g. `"5:22/km — includes 2:14 of recording gap"`) so the glyph is never the sole carrier of meaning for assistive tech — mirrors the existing `aria-label` pattern already on the adjacent `vs. Avg` cell (`buildPaceBarCell`). |
| **D-09 gap-crossing legend** (PACE-05) — `[derived]` shape: one `<ul class="text-label">` appended below the `.splits-scroll` wrapper, present only when ≥1 split is flagged (same conditional-append pattern as the existing 1k age-grade footnote at `detail-sections.ts:439-445`) | One `<li>` per flagged split, each naming its own measured amount (a single generic sentence cannot carry per-split-specific durations, per D-09's explicit "not a bare flag" requirement): `"Km {n}: includes {mm:ss} of {recording gap\|pause}"`. Example: `"Km 4: includes 2:14 of recording gap"`. **Derived, not in CONTEXT.md verbatim** — CONTEXT.md's own example string (`"⚠ this km includes 2:14 of recording gap"`) is written from the reader's point of view standing at that split; this spec keeps that wording but prefixes the km number so multiple legend lines stay distinguishable when more than one split is flagged in the same activity. |
| **D-11 badge, detail view Pace stat card** (PACE-07) — third child of the existing `buildStatCard('…', 'Pace')` wrapper, appended only when the activity is flagged | `"Pace disputed — stream-derived {formatted pace}"`. Example: `"Pace disputed — stream-derived 5:51/km"`. The stat card's big `.text-display` number is **unchanged** (still shows the metadata value, `1:53/km`, per D-10 — nothing is silently substituted); the badge is the disclosure, appended below the `.text-label` "Pace" caption. |
| **D-11 badge, list/table/Overview row surfaces** (PACE-07, D-11) — appended via the existing `statusBadgeTexts`/`appendStatusBadges` single-source pipeline (`list.ts`), so it reaches all four `RowSurface` values (`activity-card`, `activity-table`, `overview-prs`, `overview-activities`) from one code change | Visible badge text: `"Pace disputed"` (short, matching the existing badge vocabulary's length — `"Low confidence"`, `"Excluded from records"`, `"{n} PR"` — the row surfaces are space-constrained per Phase 22's phone-width precedent, so the full stream-derived figure does not fit inline here). Full detail reachable via the same accessible pattern `appendLowConfidenceBadge` already uses: a `title` attribute for pointer users and a sibling `.sr-only` span wired by `aria-describedby` for keyboard/AT users, both carrying: `"Metadata pace disagrees with the stream-derived pace: {formatted stream pace} measured vs. {formatted metadata pace} shown"`. |
| **D-13 rebased `+/-` caption note** (PACE-07) — appended in the same caption area as D-09's legend (below `.splits-scroll`), present only on a flagged activity | `"Splits above are compared against the stream-derived average ({formatted stream avg}), not the disputed metadata average."` — states which baseline the `vs. Avg` column now uses, since D-13 silently rebases the comparison value and a reader who remembers the metadata pace would otherwise be confused why every split suddenly reads close to average. |
| Empty state (unaffected by this phase) | `buildNoStreamSection`'s existing copy — unchanged, no new empty state is introduced |
| Error state (unaffected by this phase) | `renderErrorState`'s existing copy — unchanged |
| Destructive confirmation | Not applicable — this phase introduces no destructive action (D-17: nothing is deleted, corrected, or recomputed; only disclosed) |

**Accessibility constraint carried into every copy row above (from the phase brief, binding):**
no element here is color-only or glyph-only. The `⚠` glyph is always `aria-hidden` and always
paired with a text equivalent (an `aria-label` on the cell, a legend line, or a badge's visible
text) — never the sole signal. The `.badge` treatment for `"Pace disputed"` never relies on hue
to communicate meaning (see Color section above) — its text says what it means.

**Anti-pattern to avoid:** do not create a new `.pace-warning`, `.gap-badge`, or similarly
color-scoped CSS class. Every new visual element must resolve to `.badge`, `.text-label`, or an
inline `aria-label`/`title` on an existing cell — introducing a parallel styling vocabulary for
"disclosure" elements is exactly the kind of drift Phase 19/20's shared-treatment work exists to
prevent.

## Layout & Responsive Notes

- **Splits table stays at 7 columns.** (Confirmed by direct read of `buildSplitsSection`,
  `detail-sections.ts:120-190`: `Km | Pace | Elapsed | Avg HR | Avg Cadence | Elev Δ | vs. Avg`
  — CONTEXT.md's "already carries eight" is off by one against the current source, but the
  binding constraint is unchanged either way: D-09 explicitly rejects a ninth/eighth column, and
  this spec adds none. The marker lives inside the existing `Pace` column's cell.)
- The existing `.splits-scroll` horizontal-scroll wrapper (Phase 17/22 precedent) is untouched —
  the gap marker adds one glyph character to existing cell text, not new column width, so it
  does not reopen the phone-width overflow Phase 22 fixed.
- The D-09 legend `<ul>` and the D-13 caption note both render **below** `.splits-scroll`, in
  normal document flow (full page width), not inside the horizontally-scrolling region — so they
  never scroll out of view independently of the table.
- The D-08 coverage caption is a single `.text-label` line; at the narrowest supported width
  (documented convention: iframe emulation down to ~500px, per `browser-checkpoint-evidence-limits`
  memory) it wraps naturally like any other `.text-label` paragraph — no truncation, no new
  breakpoint required.
- No new `@media` block is needed anywhere in this phase. Existing breakpoints
  (`380px`, `430px`, `640px`, `720px`/`721px`, `1000px`) are untouched.
- Theme-awareness: every element uses existing CSS custom properties (`var(--text)`,
  `var(--text-secondary)`, `var(--border)`, `var(--surface)`), all already declared per-theme —
  no theme-conditional logic is needed in TypeScript.
