<objective>
Serve the queue: two new exact-match `GET` routes inside the `/__curate` namespace, a second esbuild
step that bundles the queue client, a request-time stylesheet resolution so the page inherits the
dashboard theme across builds, and a startup log that tells the developer where the queue is.

Purpose: D-06 places the queue outside the published mount so no published routing or view file
changes and `curation-seam.test.ts`'s zero-occurrence pins keep holding.
Output: the two routes, `buildQueueBundle`, two new pure functions, and their tests.
</objective>

<plan_decision>
**PD-02 — the HTML shell is a pure exported string function, not a template file.**

`29-CONTEXT.md` leaves shell generation to discretion; `29-RESEARCH.md` floats either a static
template with a token or a server-built string. Choose the server-built string,
`renderQueuePage(stylesheetHref)`, placed beside `injectOverlayTag`:
- It mirrors the one precedent that exists in this subsystem — a pure, exported, idempotent,
  never-throw string function, unit-tested in `scripts/curate-server.test.mjs` without a server.
- It adds no second filesystem read path, no new "does this file exist" failure mode, and nothing new
  for `assertBuilt` to worry about.
- The stylesheet href cannot be static regardless (Vite content-hashes the CSS filename, today
  `assets/index-CQkdBpPg.css`), so the shell must be assembled per request either way.
</plan_decision>

  <behavior>
    - `extractStylesheetHref('<link rel="stylesheet" crossorigin href="./assets/index-ABC.css">')` → `/strava-widgets/assets/index-ABC.css`
    - Attribute order is irrelevant: a tag with `href` before `rel` resolves identically
    - Single-quoted attributes resolve identically
    - An already root-absolute href (`/strava-widgets/assets/x.css`) is returned unchanged, not double-prefixed
    - No stylesheet link, empty string, or malformed HTML → `null`, never a throw
    - A non-stylesheet `<link rel="icon" href="...">` is not mistaken for one
    - `renderQueuePage(href)` returns a full document containing `<!doctype html>`, `<meta charset="utf-8">`, a CSP meta with `script-src 'self'`, `<link rel="stylesheet" href="{href}">`, `<title>` naming the review queue, and `<script src="/__curate/queue.js"></script>`
    - `renderQueuePage(null)` returns the same document with NO `<link rel="stylesheet">` element (unstyled but functional), never the string `null` in an href
    - `renderQueuePage` output contains no inline `<script>` body and no inline `<style>` block (the CSP forbids both)
  </behavior>
  <action>
Write the `<behavior>` cases into `scripts/curate-server.test.mjs` as two new describe blocks, run
RED, then add both functions to `scripts/curate-server.mjs` directly beneath `injectOverlayTag`.

`extractStylesheetHref(html)`: two-step so attribute order cannot break it — first match every
`<link ...>` tag, keep the first whose attributes include `rel` with the value `stylesheet`, then pull
`href` out of that tag with a separate match tolerating single or double quotes. Normalize the result:
strip a leading `./`, and prefix `MOUNT_PREFIX` unless the value already starts with `/`. Return
`null` for anything unmatched. Never throw — a malformed `dist/widgets/index.html` must degrade to an
unstyled page, not a 500.

`renderQueuePage(stylesheetHref)`: returns the complete shell as one template string. Include the CSP
meta `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:;
connect-src 'self'` — the queue renders JSON-sourced text and this bounds the blast radius of any
escape from `textContent` discipline. Include `<h1>`-less empty `<body>` (the client builds the whole
body in plan 29-05) followed by the bundle script tag. No inline script, no inline style, no styling
of its own beyond the linked dashboard stylesheet (D-09/OD-3).

Document in both docblocks that these are response-body constructions only — nothing is ever written
back to `dist/widgets` (the publish artifact must stay pristine).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser (any origin) → curate HTTP server on 127.0.0.1:4173 | The Origin/Host gate is the entire trust boundary; there is no auth |
| request URL path → filesystem | `safeResolve` protects the mount route; the new curate routes must not derive paths from the URL at all |
| `dist/widgets` publish artifact → curate responses | Curate reads the built index at request time and never writes back to it |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-29-01 | Spoofing | DNS rebinding / cross-origin access to `GET /__curate/queue` and `/__curate/queue.js` | mitigate | `isTrustedOrigin(req, EXPECTED_HOST)` on both new branches, tested at 403 for a cross-origin Origin and for a mismatched Host, with the assertion proven failable |
| T-29-05 | Tampering | Path traversal via a dynamic `/__curate/queue/*` lookup | mitigate | Both branches are exact string comparisons with no filesystem-path derivation; a traversal request is pinned at 404 |
| T-29-02 | Tampering / Information Disclosure | XSS in the rendered queue | mitigate | The shell carries `script-src 'self'` with no inline script or style; the client uses `textContent` only (plan 29-05) |
| T-29-16 | Tampering | Curate writing back into the publish artifact | mitigate | `renderQueuePage`/`extractStylesheetHref` are response-body constructions only; `dist/widgets/index.html` is read, never written (docblock + no write call) |
| T-29-17 | Information Disclosure | The queue page or bundle leaking into the published bundle | transfer | Covered by plans 29-01 and 29-02; here, the bundle output goes only to the gitignored `.curate-dist/` and no Vite/tsconfig/build-widgets input references it |
| T-29-SC | Tampering | npm/pip/cargo installs | accept | This phase installs zero packages (29-RESEARCH.md § Package Legitimacy Audit: not applicable) |
</threat_model>
