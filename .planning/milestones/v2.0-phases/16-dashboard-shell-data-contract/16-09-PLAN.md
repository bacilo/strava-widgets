  <action>
    Create `scripts/verify-dashboard-publish.mjs`, an ESM Node script using only built-ins (`node:http`, `node:fs`, `node:path`) — no new dependency, consistent with D-01.

    It must:
    1. Fail fast with an actionable message if `dist/widgets/index.html` or `dist/widgets/data/dashboard/index.json` is missing, telling the operator to run `npm run build-widgets` first.
    2. Start a minimal static file server on an ephemeral port (`server.listen(0)`) rooted at `dist/widgets`, resolving request paths safely: reject any resolved path that escapes the root after `path.resolve`, and serve `index.html` for `/`. Set `Content-Type: application/json` for `.json` and `text/html` for `.html`.
    3. Read `data/dashboard/index.json` and pick three sample rows: the newest row overall, the newest row with `streams.available === true`, and the newest row with `streams.available === false` (skip that third check if the archive has none).
    4. GET each of these URLs and assert a 200 plus a non-empty body:
       - `/` (must return HTML containing `data-theme`, proving the theme bootstrap survived the build)
       - `/data/dashboard/index.json` (must parse, `schemaVersion === 1`, `activities.length > 0`)
       - `/data/stats/all-time-totals.json` and `/data/stats/streaks.json`
       - `/data/activities/<id>.json` for each sample row
       - `/data/streams/<id>.json` for the stream-available sample (must parse and expose a non-empty `t` array)
       - `/widgets.html`, `/heatmap.html`, `/pinmap.html`, `/routes.html` (the relocation and the pre-existing pages both still serve)
    5. Assert that `/data/streams/<id>.json` for the stream-UNAVAILABLE sample returns 404 — the degraded state the detail view renders as `No stream data for this activity.` must genuinely be a 404, not an accidental empty file.
    6. Assert that the SPA's hashed JS asset referenced by `index.html` resolves with a 200 (extract the `src` from the `<script type="module">` tag).
    7. Print a `✓` line per check, a final summary, close the server, and `process.exit(1)` on any failure with the failing URL and status named.

    Add `"verify-dashboard": "node scripts/verify-dashboard-publish.mjs"` to `package.json`'s `scripts`, immediately after `build-widgets`.

    Scope note: this script verifies that every URL the SPA can request is reachable from the publish directory. It does NOT and cannot verify hash routing, view mounting, or theming — those need a real browser and are the human checkpoint in task 2. Do not add a headless-browser dependency to close that gap; D-01 forbids it for this phase and RESEARCH.md recommends deferring it.
