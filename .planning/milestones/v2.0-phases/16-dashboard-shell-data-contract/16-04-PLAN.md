<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| committed repo data → batch compute | `data/activities/*.json`, `data/streams/manifest.json`, and `data/geo/activity-cities.json` are read unvalidated by a CI-run job |
| generated index → public web | `data/dashboard/index.json` is copied into the publish dir (plan 08) and served openly from GitHub Pages |
| athlete free text → downstream DOM | `name` is athlete-editable text carried verbatim through the index into browser rendering |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-16-IX-01 | Denial of Service | Per-activity read loop in `computeDashboardIndex` | mitigate | Every per-row read/parse is wrapped in try/catch that increments `totals.skippedUnreadable`, warns with the id, and continues — a single truncated or hand-edited activity file cannot abort a 1,867-row nightly build (same handling as `compute-best-efforts.ts`'s T-15-02) |
| T-16-IX-02 | Information Disclosure | Row construction from `StravaActivity` | mitigate | The row is built from an explicit member-by-member object literal; spreading the source record is forbidden and grep-asserted, so `athlete`, `upload_id`, `external_id`, `gear_id`, `private`, `visibility`, and `map.summary_polyline` never reach the published index |
| T-16-IX-03 | Tampering | `name` free text flowing into the published index | transfer | Escaping is deliberately NOT done here (it would double-encode the JSON). The mitigation lives at the render boundary: plans 06 and 07 must write `name` with `textContent`, never `innerHTML` — carried forward as threat T-16-VW-01 |
| T-16-IX-04 | Denial of Service | Missing optional inputs (`best-efforts.json`, `activity-cities.json`) | mitigate | Both loads are try/catch-guarded and degrade to empty lookups with a warning, so a failed upstream `compute-best-efforts` or `compute-geo-stats` step (both already `continue-on-error: true` in CI) leaves the dashboard with a slightly less annotated index rather than no index at all |
</threat_model>
