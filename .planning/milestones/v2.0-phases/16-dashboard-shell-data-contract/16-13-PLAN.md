<objective>
Make the build's outDir protection real, and make the phase's own exit gate actually run in the pipeline that publishes.

Purpose: two publish-pipeline defects. `scripts/build-widgets.mjs` passes `emptyDir` to Vite in three places; the real option is `emptyOutDir`, so the comment calling the guard "CRITICAL" describes protection that does not exist — `dist/widgets/` survives only because Vite's default is not to empty an `outDir` that lies outside `root`. Any future `root`/`outDir` change would wipe 11 widget bundles, four page HTML files and the copied data tree mid-build with no warning, and the deploy step would publish the gutted directory. Separately, `scripts/verify-dashboard-publish.mjs` self-describes as "the automated half of Phase 16's exit gate" and `npm run verify-dashboard` is wired in `package.json`, but `daily-refresh.yml` goes straight from `Build widgets` to the Pages deploy: neither the verify script nor `npm test` has ever run in CI, so a regression in URL shape, data copying or the index contract would deploy silently every night.

Output: five correctly-named build options and two blocking CI gate steps positioned between the build and the deploy.
</objective>
