  <action>
Create `src/streams/backfill-streams.ts` exporting `export async function backfillStreams(): Promise<void>` plus two pure helpers extracted for testability.

**Pure helper 1** — `export function classifyUnavailable(activity: { manual?: boolean; trainer?: boolean; source_provider?: string }): StreamUnavailableReason`. Rules, derived from measured archive composition: return `'manual'` when `activity.manual === true` (23 instances); return `'treadmill'` when `activity.trainer === true` and `manual` is not true (zero current instances — the code path exists because the taxonomy must be extensible, per RESEARCH.md Open Question 2); otherwise return `'no-original'`.

**Pure helper 2** — `export function buildBackfillTargets(provenance, existingStreamIds: Set<string>): { withOriginal: Array<{ id: string; originalPath: string }>; withoutOriginal: string[] }`. It reads `provenance.activities`, resolves each entry's `original` string (`"<source>:<relative/path>"`) into `path.join('export_data', source, relativePath)`, skips any id already in `existingStreamIds`, puts ids with a resolvable original into `withOriginal`, and puts ids listed in `provenance.archive_without_original` (or whose entry has no `original`) into `withoutOriginal`. Keep it pure — no filesystem access — so it can be unit-tested against literal provenance objects with no `export_data/` present.

**`backfillStreams()`** wiring:

1. Guard: if `data/provenance.json` does not exist, log `Nothing to backfill: data/provenance.json not found. Run: node dist/index.js consolidate-exports` and return — mirroring `consolidateExports`'s early-return-on-missing-input shape.
2. Instantiate `new FileStore('.')` (the same base the CLI already uses in `src/index.ts`'s `syncIntervalsCommand`).
3. Build the skip index: `existingStreamIds` from `fileStore.listFiles(config.streamsDir, '.json')`, excluding `manifest.json`, stripping the `.json` suffix. This is the idempotency mechanism — no separate "already processed" bookkeeping file, per RESEARCH.md's Don't Hand-Roll table.
4. Load the archive index: read every `data/activities/*.json` once into a `Map<string, activityRecord>` so `classifyUnavailable` has the `manual`/`trainer`/`source_provider` fields without re-reading files inside the loop.
5. `loadManifest(...)` from `config.streamsManifestPath`.
6. Call `buildBackfillTargets`.
7. Loop `withOriginal`. Per item, inside its own `try/catch`: `readOriginal(originalPath)`; determine `source` as `'fit'` when the path matches `/\.fit(\.gz)?$/` else `'gpx'`; `deriveFromSamples(id, recording.samples, source)`. When it returns a stream, `fileStore.writeJson(\`${config.streamsDir}/${id}.json\`, stream)` and `upsertAvailable(manifest, id, { source: stream.source, distanceSource: stream.distanceSource, sampleCount: stream.sampleCount, channels: stream.channels })`. When it returns `null`, `upsertUnavailable(manifest, id, 'no-samples')` and warn. On a thrown error, `upsertUnavailable(manifest, id, 'unreadable-original')` and `console.warn(\`  ${id}: could not read original (${error.message}); flagged unreadable-original\`)`. One bad file among ~1,841 must never abort the run.
8. Loop `withoutOriginal`: `upsertUnavailable(manifest, id, classifyUnavailable(archive.get(id) ?? {}))`. No stub stream file is written — CONTEXT.md D-04 is explicit that "unavailable" means no file at all plus a manifest entry.
9. Progress reporting: log a running counter every 100 processed items in the form `  ... 400/1841 processed (382 written, 12 skipped, 6 flagged)` so a multi-minute run over 1,841 files is observable.
10. `saveManifest(...)` once at the end, then print a final summary block following `consolidate.ts` lines 263-274: total archive activities, stream files written this run, skipped as already present, flagged unavailable broken down by reason code, and the count of files now under `data/streams/`.
11. Write nothing under `export_data/` — that directory is read-only for this command.

Do not add the size-gate report, the intervals reconciliation branch, or CLI registration here; those are plan 14-05 and would push this plan past its context budget.

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-01 | Denial of Service | per-original loop in `backfillStreams` | mitigate | Per-item `try/catch` that warns and records `unreadable-original` in the manifest, then continues; one bad file among 1,841 cannot abort the run. Asserted in Task 1 acceptance criteria. |
| T-14-09 | Tampering | `buildBackfillTargets` path resolution | mitigate | `original` values are resolved with `path.join('export_data', source, rel)`; the resulting path is only ever passed to `readOriginal` for reading. The command performs no writes under `export_data/` — asserted by the no-git/no-exec grep gate and by writes being routed exclusively through `FileStore` rooted at the repo root. |
| T-14-04 | Information Disclosure | committed stream files | mitigate | Written objects come from `deriveFromSamples`, whose schema (plan 14-01) carries no `lat`/`lng`; the full-resolution originals stay in gitignored `export_data/`. |
| T-14-10 | Repudiation | manifest completeness | mitigate | Every touched id gets a manifest entry on both the success and failure paths, so a missing stream file is always explained by a reason code rather than inferred from file absence. |
