<objective>
Validate the engine against an external reference: pick source-diverse activities, have the developer read the corresponding best-effort times out of Strava or Garmin Connect, freeze those values as fixtures, and assert the engine reproduces them within tolerance.

Purpose: this is the phase's third success criterion — "computed best efforts validate against known reference activities without producing implausible results". Unit tests prove the algorithm is internally consistent; only an external reference proves it is correct. Per D-05 and RESEARCH.md Open Question 1, the reference values exist only in the developer's own accounts and cannot be fetched by an agent, so a blocking checkpoint is unavoidable here.
Output: `15-FIXTURE-CANDIDATES.md` (the lookup worksheet) and `src/analytics/best-effort-fixtures.test.ts` (the frozen assertions).
</objective>
