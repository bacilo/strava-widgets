Export `findBestEffort(t: number[], d: number[], targetMeters: number): RawEffort | undefined`, implemented exactly as RESEARCH.md Pattern 1 specifies. The three properties that must not be altered:
- The end pointer `j` is declared once outside the `i` loop and is only ever advanced (`if (j < i + 1) j = i + 1;` then `while (j < n && d[j] - d[i] < targetMeters) j++;`). Resetting `j` per `i` reintroduces the O(n squared) behaviour Pitfall 2 rules out at 2.7 million committed sample points across the archive.
- When `j` reaches `n` the loop breaks — no later start index can reach the target either.
- The crossing time is interpolated between `t[j-1]` and `t[j]`: `needed = targetMeters - (d[j-1] - d[i])`, `segMeters = d[j] - d[j-1]`, `frac = segMeters > 0 ? needed / segMeters : 0`, `crossingTime = t[j-1] + frac * (t[j] - t[j-1])`. Never return `t[j]` directly; D-01 rules snapping out because it biases every result slow by up to one sample interval, and Phase 14's committed streams are decimated to 1-3 s spacing, which makes that bias larger than it would be on raw 1 Hz data (RESEARCH.md Pitfall 4).
- A candidate is kept only when `durationSec > 0` and it beats the incumbent.

The function assumes a validated series — callers run `validateStreamSeries` first. Keep the early return for `n < 2 || d[n-1] - d[0] < targetMeters`.
