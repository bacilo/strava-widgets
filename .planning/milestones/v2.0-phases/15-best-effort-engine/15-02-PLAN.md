`computeActivityEfforts(input: ActivityEffortInput): ActivityEffortResult`

where `ActivityEffortInput` is an exported interface with fields `activityId: string`, `startDate: string`, `activityDistanceM: number`, `maxSpeedMps: number | undefined`, `distanceSource: DistanceSource`, `t: number[]`, `d: number[]`; and `ActivityEffortResult` is an exported interface with fields `efforts: ComputedEffort[]`, `rejected: RejectedEffort[]`, `eligibleTargets: TargetDistanceKey[]`, `seriesError?: string`.

Implementation order inside the function:
1. Run `validateStreamSeries(t, d)`. On failure return `{ efforts: [], rejected: [], eligibleTargets: [], seriesError: <the reason string> }`. Nothing downstream may see an unvalidated series (threat T-15-01).
2. Compute `eligibleTargets` as the members of `TARGET_ORDER` for which `activityDistanceM >= TARGET_METERS[key] * 0.99` (D-01 verbatim — the 1% margin exists to absorb the difference between the canonical `distance` field and the stream's own span).
3. For each key in `eligibleTargets`, in `TARGET_ORDER` sequence, inside its own `try`/`catch`: call `findBestEffort(t, d, TARGET_METERS[key])`; if it returns `undefined`, continue silently (the stream simply never covers that distance — not an error, not a rejection); otherwise compute `impliedSpeedMps = TARGET_METERS[key] / raw.durationSec` and call `isPlausible(impliedSpeedMps, maxSpeedMps, WORLD_RECORD_SPEED_MPS[key])`. On `ok: false` push a `RejectedEffort` with the verbatim reason and continue to the next target. On `ok: true` push a `ComputedEffort` with `distance: key`, `durationSec` rounded to 0.1, `paceSecPerKm` computed from the UNROUNDED duration as `raw.durationSec / (TARGET_METERS[key] / 1000)` and then rounded to 0.1, `startOffsetSec` rounded to the nearest integer, `endOffsetSec` rounded to 0.1, and `lowConfidence: distanceSource === 'geo'`. A `catch` pushes a `RejectedEffort` whose reason begins `unexpected error:` followed by the message — one target throwing must never lose the activity's other six (Pitfall 6).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `data/streams/<id>.json` and `data/activities/<id>.json` on disk → orchestrator | Committed JSON that could be truncated by an interrupted write, hand-edited, or regressed by a future upstream change |

| orchestrator → `data/stats/best-efforts.json` | The project's own record of truth for PRs, consumed unquestioned by Phases 16-18 |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15-01 | Tampering | `computeActivityEfforts` series intake | mitigate | Every series passes `validateStreamSeries` before the sweep; a failure returns `seriesError` and the activity is counted as skipped rather than producing NaN durations. Asserted by the malformed-series tests in Task 1. |
| T-15-02 | Denial of Service | `computeBestEfforts` per-activity loop | mitigate | Per-activity try/catch + `console.warn` + continue (the `intervals-sync.ts:119-139` convention), plus per-target try/catch inside `computeActivityEfforts`. One corrupt file among 1,842 warns and is skipped; asserted by the corrupt-stream tmpdir test in Task 2. |
| T-15-04 | Tampering | rejection handling | mitigate | Every dropped effort is recorded in `document.rejected` with `activityId`, `distance` and the verbatim guard reason, and echoed to the console — a silently missing PR is impossible to distinguish from a rejected one otherwise. |
| T-15-05 | Information Disclosure | `data/stats/best-efforts.json` | accept | The document holds only durations, paces and second-offsets already derivable from committed data — no positions, no secrets, no third-party credentials. `data/stats/` is gitignored, so the file is never committed and never added to any workflow `file_pattern`. |
| T-15-SC | Tampering | npm installs | accept | Zero new packages in this plan (RESEARCH.md Package Legitimacy Audit: not applicable). No registry surface added, so no slopcheck or legitimacy checkpoint applies. |
