`export interface ComputeAgeGradingOptions { statsDir?: string; wmaDir?: string; athletePrivatePath?: string; }` — defaults `'data/stats'`, `'data/wma'`, `'data/private/athlete-private.json'`.

`export async function computeAgeGrading(options): Promise<AgeGradingDocument>`:

1. **Required input:** `<statsDir>/best-efforts.json`. Missing → throw, naming `compute-best-efforts` as the prerequisite (same treatment `compute-dashboard-index` gives its manifest).
2. **Required input:** both `<wmaDir>/road-factors.json` and `<wmaDir>/track-factors.json`, each through `parseWmaFactorTable`. These are **committed** files, so their absence is a genuine repository defect, not a degraded state — throw with a message naming `scripts/convert-wma-tables.mjs`.
3. **Optional input:** `loadAthletePrivateConfig`. When it returns `null`, write a document with `enabled: false`, a `disabledReason` string, empty `rankings` and `activities`, and **return successfully**. The reason string must be exactly the user-facing copy the Records page renders (18-UI-SPEC's Copywriting Contract, with the path corrected per plan 18-01's locked deviation): `Age-grading is off — add birthDate and sex to data/private/athlete-private.json to enable it.` Putting the copy in the document rather than in the view means the view has one fewer place to drift.
4. When enabled, for **every** entry in every `rankings[distance]` array: compute the athlete's age at that entry's `startDate` via `ageAtDate(birthDate, startDate)` — the age **at the time of the effort**, never the age today, which is the whole point of D-10's "a slower recent run can visibly out-grade a faster old one". Then `resolveAgeGrade(road, track, sex, distance, age, durationSec)`. Emit `{ rank, activityId, agePercent, derived }` with `agePercent` rounded to 1 decimal. A `null` result (a distance the tables cannot serve) is **omitted** from the output rather than emitted as `0` — the view renders an em-dash for a missing value, and a `0 %` would be a fabricated claim.
5. Also emit `activities[activityId][distance] = { agePercent, derived }` for **every** effort in `bestEfforts.activities`, not only PR-setting ones and not only ranked ones — the detail view's best-efforts panel (D-08) needs an age-grade column for every effort a run produced, including the 5 k split inside a 10 k run.
6. `derived` is `true` only for `1k` (D-09's interpolated value, which the view marks with `*` and an always-visible footnote).
7. Include `editions: { road: <road.edition>, track: <track.edition> }` so a future table revision is visible in the published payload.
8. Write `{ schemaVersion, generatedAt, note, enabled, disabledReason, editions, rankings, activities }` to `<statsDir>/age-grading.json`. **The document must not contain `birthDate`, `sex`, `restingHr`, or the derived age in years** — D-20's rule, restated in `age-grading.types.ts`'s header. Publishing the age would re-expose the birth year that plan 18-01 exists to protect.
9. Log a summary: enabled or the reason, entries graded per distance, and how many `resolveAgeGrade` calls returned `null`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `data/private/athlete-private.json` → build step → published JSON | `birthDate` and `sex` are the direct inputs; only percentages may cross |
| committed WMA tables → published percentages | A wrong table silently corrupts every number with no runtime error |
| CI runner → published artifact | The private file never exists in CI, so the disabled path is the *normal* path there |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-18-PII-07 | Information Disclosure | `data/stats/age-grading.json` | mitigate | Only `agePercent` + `derived` are emitted; the derived age in years is deliberately excluded so a percentage cannot be inverted back to a birth year. Asserted by a grep for `birthDate`/`sex`/`age` returning `0`, and independently enforced by plan 18-01's `assertNoPrivateArtifacts` build guard |
| T-18-AGE-01 | Integrity (silent wrongness) | age evaluation date | mitigate | Test case 3 pins that age is taken at the **effort's** date and is directional; a bug substituting today's date fails it |
| T-18-AGE-02 | Spoofing (fabricated value) | unservable distances, missing config | mitigate | A `null` grade is omitted rather than emitted as `0`; a missing config yields `enabled: false` plus actionable copy rather than placeholder numbers (D-13, and the 17-D31 precedent) |
| T-18-AVAIL-02 | Denial of Service (pipeline) | missing private config in CI | mitigate | The disabled path returns successfully and is the case CI always exercises; only genuinely-committed-file absences throw |
| T-18-WMA-01 | Tampering / integrity | committed factor tables | transfer | Owned by plan 18-02 (reproducible converter + externally-pinned spot-check); this step additionally publishes the `editions` so a silent table swap is visible in the artifact |
| T-18-SC | Tampering | npm/pip/cargo installs | mitigate | Zero package installs authorized. An executor that concludes an install is necessary must stop and run the Package Legitimacy Gate |
</threat_model>
