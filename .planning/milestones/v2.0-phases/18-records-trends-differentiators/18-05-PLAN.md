Create `src/analytics/gear-naming.ts` — pure, no I/O. Exports:

- `export const UNKNOWN_GEAR_LABEL = 'Unknown';` (D-18: the literal label, used identically by the index-adjacent code and the aggregate)
- `export interface GearUsage { gearId: string; startDate: string; }`
- `export function buildGearLabelMap(usages: readonly GearUsage[], gearMap: Record<string, string> | null): Map<string, string>` — returns `gearId → label`. Algorithm:
  1. Collect each distinct `gearId`'s earliest `startDate` (UTC comparison; append `Z` when absent, per the repo-wide Z-suffix rule documented on `list.ts`'s `formatActivityDate` — the archive carries both Strava Z-suffixed and intervals.icu non-Z shapes).
  2. Sort distinct ids ascending by that earliest date, breaking ties by `gearId` string comparison so the result is **fully deterministic** across runs.
  3. Assign each id a 1-based ordinal in that order.
  4. Label = the trimmed non-empty value from `gearMap[gearId]` when present, otherwise `` `Shoe ${ordinal}` ``.
  Never return the raw `gearId` as a label under any input — this is 17-D32's hard rule and the reason ordinals exist. A `null` `gearMap` (missing/malformed config) still yields the full ordinal labelling.

Create `src/analytics/gear-naming.test.ts` covering:
1. All-blank names (the live archive state): three ids with first-use dates out of chronological order in the input array produce `Shoe 1`/`Shoe 2`/`Shoe 3` assigned by first-use date, not by input order.
2. Mixed: one id with a real name keeps it; the others still get ordinals, and the ordinal numbering counts **all** shoes (so a named shoe still consumes its ordinal slot and the numbering does not shift when a name is later filled in) — assert this explicitly, it is the property that makes the labels stable across config edits.
3. `null` gearMap yields ordinals for every id.
4. Whitespace-only name (`"   "`) falls back to the ordinal.
5. Determinism: two ids sharing an identical earliest date always produce the same assignment across repeated calls (tie broken by id).
6. Z-suffix mixing: an id whose earliest date is `2024-01-15T09:00:00Z` and another whose earliest is `2026-08-06T07:28:22` (no `Z`) order correctly.
7. No output label equals any input `gearId` — assert over the whole returned map.
