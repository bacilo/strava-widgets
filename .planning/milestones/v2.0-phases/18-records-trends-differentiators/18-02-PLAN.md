Create `src/analytics/wma-factors.ts` — **pure and client-safe**: no `fs`, no `fetch`, no Node-only imports, no `document`. It is imported by both the build-time compute step (plan 18-08) and, potentially, browser code.

Exports:
- `export type WmaSurface = 'road' | 'track';`
- `export type AthleteSex = 'male' | 'female';` (structurally identical to the type in `athlete-private.ts`; declared here so this module stays free of any build-only import)
- `export interface WmaFactorTable { schemaVersion: number; surface: WmaSurface; edition: string; source: string; openStandardSec: Record<AthleteSex, Record<string, number>>; factors: Record<AthleteSex, Record<string, Record<string, number>>>; }`
- `export function parseWmaFactorTable(raw: unknown): WmaFactorTable | null` — total, never throws, own-property reads only; rejects unless both sexes carry at least one distance with at least one numeric factor in `(0, 1]` and a positive open standard.
- `export function ageAtDate(birthDateISO: string, onDateISO: string): number | null` — whole years, **UTC only**, computed by comparing `[year, month, day]` triples so a birthday later in the year does not round up. Returns `null` on any unparseable input or a negative result. Both inputs may be date-only (`YYYY-MM-DD`) or full ISO; normalize by taking `slice(0, 10)` and appending `T00:00:00Z` (the same Z-suffix discipline `list.ts`'s `formatActivityDate` documents).
- `export function lookupFactor(table: WmaFactorTable, sex: AthleteSex, distanceKey: string, age: number): number | null` — exact whole-year lookup; **clamps** the age to the table's own min/max age for that distance rather than returning `null` (a 12-year-old or a 100-year-old must still grade); returns `null` when the sex/distance is absent.
- `export function interpolate1kFactor(factor800: number, factorMile: number): number` — log-linear between 800 m and 1609.344 m at 1000 m, exactly as drafted in RESEARCH § Code Examples.
- `export function ageGradePercent(openStandardSec: number, actualSec: number, ageFactor: number): number` — **the one canonical direction**: `(openStandardSec / actualSec / ageFactor) * 100`. Returns `0` when `actualSec <= 0` or `ageFactor <= 0`. Add a JSDoc block stating Pitfall 5's failure signature (multiplying by the factor instead of dividing inverts the age-reward direction) so a future edit cannot silently flip it.
- `export interface AgeGradeResult { percent: number; derived: boolean; surface: WmaSurface; }`
- `export function resolveAgeGrade(road: WmaFactorTable, track: WmaFactorTable, sex: AthleteSex, distance: TargetDistanceKey, age: number, actualSec: number): AgeGradeResult | null` — routes per D-09: `5k`/`10k`/`half`/`marathon` → road table; `400m`/`1mi` → track table; `1k` → track table with the factor from `interpolate1kFactor(lookupFactor(track,sex,'800m',age), lookupFactor(track,sex,'1mi',age))` and the open standard interpolated the same log-linear way between the `800m` and `1mi` open standards. `derived` is `true` **only** for `1k` and `false` for every other distance. Returns `null` when any required lookup is missing.

Create `src/analytics/age-grading.types.ts` defining the published document contract, mirroring `best-effort.types.ts`'s document conventions:
- `export const AGE_GRADING_SCHEMA_VERSION = 1;`
- `export interface AgeGradeEntry { agePercent: number; derived: boolean; }`
- `export interface AgeGradingDocument { schemaVersion: number; generatedAt: string; note: string; enabled: boolean; disabledReason: string | null; editions: { road: string; track: string }; rankings: Partial<Record<TargetDistanceKey, (AgeGradeEntry & { rank: number; activityId: string })[]>>; activities: Record<string, Partial<Record<TargetDistanceKey, AgeGradeEntry>>>; }`

Add a load-bearing header comment on `age-grading.types.ts`: this document is a **published public artifact**; per D-20 it carries only derived percentages. `birthDate`, `sex`, `restingHr`, and the athlete's age in years must never appear as fields — the age is deliberately not published even though it is an input, because publishing it re-exposes the birth year the private-config split (plan 18-01) exists to protect.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| external web source → committed repo data | Factor tables are downloaded from third-party sites and become permanent committed reference data |
| committed factor table → published age-grade percentages | A wrong table silently corrupts every REC-06 number with no runtime error |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-18-WMA-01 | Tampering / integrity | `data/wma/*.json` | mitigate | Values are produced by a committed, re-runnable converter that logs what it parsed; the source URL, licence and edition are recorded in-file and in `data/wma/README.md`; the parsed `male`/`5k`/age-50 factor is cross-checked against an independently published worked example that the executor is forbidden from adjusting |
| T-18-WMA-02 | Spoofing (source authenticity) | conversion inputs | mitigate | Only the two named primary sources (Alan Jones CC0 road project, Howard Grubb WMA 2023 track) are authorized; the executor must stop rather than substitute an unnamed calculator site or values from memory |
| T-18-PII-04 | Information Disclosure | `age-grading.types.ts` | mitigate | The published document type carries only `agePercent` + `derived`; age in years is deliberately excluded so the percentage cannot be inverted back to a birth year |
