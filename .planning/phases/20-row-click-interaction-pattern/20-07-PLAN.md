<objective>
Close CR-02: put the status-badge text back into what a screen reader announces for a whole-row
link, on all three surfaces where this phase made the row itself the anchor.

Purpose: `appendStatusBadges(rowEl, row)` (`list.ts:241`) appends badge spans as direct children
of an element that carries an overriding curated `aria-label` (`list.ts:226-229`), and
`renderRecentPrRow` does the same with its PR-count badge (`overview.ts:108-112`). An
`aria-label` replaces the accessible name computed from descendants, so "No streams",
"Low confidence", "Excluded from records" and "N PR" - this repository's own honesty
disclosures - are announced on the desktop table and on Records, and silently dropped on the
Activities mobile card, Overview Recent Activities and Overview Recent PRs. The
`aria-describedby` wiring inside `appendLowConfidenceBadge` is inert on those surfaces too: its
host span's text is subsumed by the ancestor's label, so the description has no announcement
point. This falsifies this phase's own success criterion 3 ("announced correctly to assistive
tech") and blocks UX-03.

Output: one array of badge texts per row that feeds both the rendered spans and the composed
`aria-label`, a describedby wired onto the anchor with a surface-unique id, unit coverage of the
composition on all three surfaces, and source guards that keep the three call sites from
drifting back apart.
</objective>
