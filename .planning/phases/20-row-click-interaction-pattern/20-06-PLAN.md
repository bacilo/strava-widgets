<objective>
Close CR-01: restore Phase 17 D-08's return-from-detail keyboard focus on the mobile card layout, and
cover it with a test that would have caught the defect.

Purpose: `highlightAndFocus` (`list.ts:963-968`) recovers focus with
`el.querySelector('a')?.focus()`. That was correct when `renderActivityRow` appended a `.cta`
descendant anchor. Plan 20-02 deleted that descendant and made the card row element itself the
`<a>` (`list.ts:222`), so on the card branch `querySelector('a')` returns `null`, the optional
chain silently no-ops, and below the 720px breakpoint - where the card is the only
visible/focusable branch - focus restoration is completely dead. The row still gets
`.activity-table__row--highlight`, so it *looks* restored while keyboard focus stays on the page
`<h1>`. This is the phase's own success criterion 1 ("using `list.ts`'s existing pattern,
propagated rather than reinvented") failing on the half of the established pattern this phase
never re-audited.

Output: a `highlightAndFocus` that resolves the focus target for both row shapes this phase
created, plus a node-environment regression test proven RED before the fix and GREEN after it.
</objective>
