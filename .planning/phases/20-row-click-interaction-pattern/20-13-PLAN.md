<objective>
Implement D-14: the row-click listener refuses navigation on the first click of a double-click, so
a double-click intended as word-select no longer navigates away before the selection completes.

Purpose: `20-REVIEW.md`'s WR-05, independently confirmed by `20-VERIFICATION.md`
(`grep -n "clickCount\|event.detail" src/dashboard/row-navigation.ts` finds nothing). D-12's
`hasTextSelection` guard reads `window.getSelection()` at click time, which protects a drag-select
(mouseup happens with the selection already set) but not a double-click: the browser fires
`click` with `detail` 1, then `click` with `detail` 2, then `dblclick`, and the word selection only
exists from the second event onward. The first click sees a collapsed selection, passes every
guard, and navigates. This matters on exactly the Records PR-table cells that carry short numeric
values a user double-clicks to copy.

Output: one new field on the existing pure predicate, one new refusal class, and the unit coverage
that proves both, all still testable under `environment: 'node'`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser mouse event -> navigation decision | `MouseEvent.detail`, `button`, the modifier keys and the current selection are all attacker-irrelevant but user-intent-bearing inputs; misreading any of them turns a select gesture into a navigation. |
| pure predicate -> DOM listener | The predicate is unit-testable under `environment: 'node'`; the listener that builds its input is not. Everything asserted about the listener is source text, not behaviour. |
