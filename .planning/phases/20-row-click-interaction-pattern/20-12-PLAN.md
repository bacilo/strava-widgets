<objective>
Close the CRITICAL regression `20-VERIFICATION.md` recorded against `list.ts`: the one-shot
return-highlight hint leaks past three of `mount()`'s four render paths and later steals keyboard
focus and scrolls the page on a navigation the user never returned from.

Purpose: `applyReturnHighlight` (`list.ts:1112-1131`) is the only writer that clears
`notedActivityId`, and `mount()` reaches it from exactly one of its render branches
(`list.ts:1322-1324`). The zero-match branch (`:1293-1299`), the load-failure branch
(`:1239-1259`) and the stale-container branch (`:1322`) all skip it, while `detail.ts:665` sets the
id on **every** detail mount. Unexpected focus movement on an unrelated navigation is a WCAG 3.2.x
class defect in the exact mechanism plan 20-06 built to satisfy success criterion 3.

Output: a read-and-consume helper whose consumption is unconditional by construction, a regression
test for the leak sequence, and a source-structure guard that keeps the consume ahead of the load.
</objective>

- `:1227` — `async mount(ctx: ViewMountContext): Promise<void>`, whose four exits are:

Target shape after this plan:

- `export function takeNotedActivityId(): string | null` — returns the current id and sets the
  module state to `null` in the same call, unconditionally.
- `export function applyReturnHighlight(notedId, tableWrapper, cardList, pageItems): void`, with
  `notedId: string | null` first, then `tableWrapper: HTMLElement`, `cardList: HTMLElement`,
  `pageItems: readonly DashboardIndexRow[]` — pure with respect to the module state; it neither
  reads nor writes `notedActivityId`.
- `mount()` calls `takeNotedActivityId()` as its **first statement** and passes the result into
  the `applyReturnHighlight` call at the end of the `else` branch.
</interfaces>

<deviation_from_the_review>
`20-REVIEW.md`'s CR-01 drafts the same two-function split but places the consume "immediately
after the stale-container guard at `list.ts:1264`". That placement does **not** fix the
load-failure branch, which returns at `:1259` — one of the three leaking branches CR-01's own
issue text names. This plan therefore places the consume at the top of `mount()`, before the
`try` that awaits `indexClient.loadIndex()`. The refusal shape and the function bodies are the
review's, unchanged; only the call site moves earlier, and the executor must record this
deviation in the summary.

Consuming the hint on a stale or failed render is the intended semantic, not a loss: the hint is
one-shot by definition, and the alternative is exactly the leak being fixed.
</deviation_from_the_review>
