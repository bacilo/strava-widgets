<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `#/activity/:id` route parameter → fetch URL | Attacker-controllable via a crafted link; the single place a route param becomes a data request |
| `data/activities/<id>.json` fields → stats tiles, gear label, map source | Self-published static data reaching the DOM through an index-signature-widened type, so runtime types are genuinely unknown |
| Dynamically imported chunk URLs → browser module loader | Same-origin Vite-emitted chunks; a failed resolution must degrade rather than break the page |
| `data/config/*.json` over HTTPS → gear label and zone panel | Fetched at runtime; may be a 404, an HTML error page, or malformed |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-URL-05 | Tampering | Route `:id` becoming a fetch URL | mitigate | The preserved `isValidActivityId` chokepoint (`/^i?\d{1,20}$/`, widened in 16-10) runs before any fetch and before any URL construction, and `detail-client.ts` re-validates independently; a malformed id renders the error state with a Browse-Activities CTA and no Retry, and the raw id is logged but never written into the DOM (T-16-VW-02) |
| T-17-VW-01 | Tampering (XSS) | `activity.name`, gear label, prev/next link labels | mitigate | All athlete-authored and config-derived text is written with `textContent`; zero `innerHTML` in `detail.ts` (asserted by grep).
