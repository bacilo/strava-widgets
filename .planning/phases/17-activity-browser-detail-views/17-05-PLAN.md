- `export const PACE_BUCKET_WIDTH_SEC = 15;` (17-UI-SPEC § 4e pins 15 s/km buckets)
- `export interface PaceBucket { minSecPerKm: number; maxSecPerKm: number; label: string; timeSec: number; }`
- `export function computePaceDistribution(stream: CanonicalStream, bucketWidthSec?: number): PaceBucket[]`

Implementation contract:
1. Pre-check with `validateStreamSeries(stream.t, stream.d)` imported from
   `../../analytics/best-effort-utils.js`; return `[]` when it is not ok.
2. Iterate CONSECUTIVE SEGMENTS, not samples: for each `i`, the segment `[t[i], t[i+1]]` has
   duration `Δt` and distance `Δd`. Its pace is `Δt / (Δd / 1000)`. Skip segments where `Δd <= 0`
   or `Δt <= 0` (standstill / duplicate timestamp) so no Infinity pace is ever bucketed. Add the
   segment's full `Δt` to the bucket its pace falls into. This is what makes the histogram
   time-weighted rather than sample-weighted.
3. Bucket index is `Math.floor(paceSecPerKm / bucketWidthSec)`; bucket bounds are
   `index * bucketWidthSec` to `(index + 1) * bucketWidthSec`.

   not import `formatPace` itself: it appends `/km` to one value and this needs a bare range form.
5. Return only non-empty buckets, sorted ascending by `minSecPerKm`.
6. Total function: never throws.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `data/config/athlete.json` (fetched over HTTPS) → zone computation | A static committed file, but it is fetched at runtime and its body must be treated as untrusted structure — a 404 page, a truncated body, or a hand-edit typo all arrive through the same path |
| `data/streams/<id>.json` HR array → zone bucketing | Self-published static data that may be absent, empty, or contain out-of-range values |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-CFG-01 | Tampering | `parseAthleteConfig` | mitigate | Total, never-throwing, all-or-nothing validation: object-shape check, finite `maxHr` in `(0, 260]`, exactly 5 zones, strictly ascending boundaries, own-property reads only (no prototype pollution reachability); any failure returns null so no partially-valid config is ever used |
| T-17-CFG-02 | Spoofing | Fabricated zone boundaries when config is absent | mitigate | `computeHrZoneTimes` returns null rather than deriving zones from observed max HR or the activity's own peak (explicitly forbidden by D-30); the caller omits the panel entirely (D-31) |
| T-17-STR-03 | Tampering | Out-of-range HR values driving array indexing | mitigate | Below-range values clamp to zone 1 and above-range to zone 5; the zone array is always the fixed 5 entries, so no HR value can index outside it |
| T-17-STR-04 | Denial of Service (client) | Non-finite pace from zero-distance segments | mitigate | `validateStreamSeries` pre-check plus a per-segment `Δd > 0 && Δt > 0` guard; a standstill contributes no bucket rather than an Infinity bound |
| T-17-SC | Tampering | npm/pip/cargo installs | accept | No packages installed this phase (17-RESEARCH.md § Package Legitimacy Audit) |
</threat_model>
