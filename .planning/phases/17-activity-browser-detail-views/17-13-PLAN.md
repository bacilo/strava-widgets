<objective>
Build the two DOM section renderers the detail page needs beyond its stats header: the per-km
splits table and the pace-distribution / HR-zone breakdown.

Purpose: keeping these in their own module means plan 17-14 (`detail.ts`) stays an orchestrator
rather than a 700-line file, and means this work can run in parallel with the map and chart modules
in the same wave. Every number these renderers display is already computed and unit-tested in
`detail-splits.ts` and `detail-zones.ts` (plans 17-04 and 17-05) — this module contains no
arithmetic beyond formatting and bar-width percentages.

Both breakdowns render as hand-rolled accessible DOM bars, NOT Chart.js canvases. That is a
deliberate decision recorded here: it keeps this module out of the lazy chart chunk entirely, makes
the numbers readable by assistive tech, and matches the splits table's own `vs. Avg` bar treatment.

Output: `src/dashboard/views/detail-sections.ts`.
</objective>

`export function buildSplitsSection(splits: readonly Split[], activityAvgPaceSecPerKm: number | null): HTMLElement`.

Return a `<section class="card detail-section">` containing an `<h2 class="text-heading">` reading
`Splits`, then a `<div class="splits-scroll">` wrapping a `<table class="splits-table">`.

Seven columns in this exact order with these exact header texts:
`Km | Pace | Elapsed | Avg HR | Avg Cadence | Elev Δ | vs. Avg`

Per row:
- `Km` cell carries `.splits-table__km` (the sticky, opaque, 64px column from plan 17-01). For a
  full split its text is the split number. For the final partial split (`isPartial === true`) its
  text is `{km} ({distance} km, partial)` — e.g. `7 (0.4 km, partial)` — with `distance` shown to
  one decimal, and the cell also carries `.splits-table__partial` for the italic treatment. This is
  what stops a short segment's pace from being misread as a full split (D-28).
- `Pace` via `formatPace(split.paceSecPerKm)` imported from `./list.js`.
- `Elapsed` is the CUMULATIVE elapsed time at the end of that split, rendered with
  `formatDurationHms(split.endTimeSec)` — the column is cumulative, not per-split duration
  (17-UI-SPEC names it "cumulative elapsed time").
- `Avg HR` — rounded integer, or the em dash when `avgHr` is null.
- `Avg Cadence` — rounded integer, or the em dash when `avgCadence` is null.
- `Elev Δ` — signed metres to zero decimals with an explicit `+` for a gain (e.g. `+12 m`,
  `-8 m`), or the em dash when `elevDeltaM` is null.
- `vs. Avg` — a `.pace-bar` containing a `.pace-bar__track`, a `.pace-bar__tick` centred at 50%
  marking the activity's average pace, and a `.pace-bar__fill` extending LEFT from the tick when
  the split is faster than average and RIGHT when it is slower. Compute the fill width as a
  percentage of half the track, capped at 100% of that half so an extreme outlier cannot overflow
  the cell. When `activityAvgPaceSecPerKm` is null, render the em dash instead of a bar. Give the
  cell an `aria-label` stating the signed difference in seconds per kilometre, since a purely
  visual bar is meaningless to assistive tech.

Use the SAME em dash character already defined as `DASH` in `detail.ts`; define it once locally in
this module rather than importing from `detail.ts` (which would create a cycle, since `detail.ts`
imports this module). Add a comment noting both copies must stay identical.

Every cell value is written with `textContent`; bar widths are set via `style.width`. No
`innerHTML` anywhere. The horizontal-scroll behaviour lives entirely in the `.splits-scroll` CSS
from plan 17-01 — do not add any inline style or script that could let the page body scroll
horizontally (D-27's hard requirement).

If `splits` is empty (no stream, or a sub-2-sample stream), return a section containing the heading
and a `<p class="text-body">` reading `No per-kilometre splits for this activity.` — a named state,
not an empty table.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Computed split/bucket/zone values → DOM text and inline bar widths | Values originate from self-published stream data, but flow into `style.width` and into rendered text |
| `data/config/athlete.json`-derived zone labels → DOM text | Hand-maintained committed config whose strings reach the page through `ZoneTime.label` |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-VW-01 | Tampering (XSS) | Every table cell, bucket label, and zone label | mitigate | All text is written with `textContent` and all `aria-label`s with `setAttribute`; zero `innerHTML` in the module (asserted by grep). Zone labels are constructed from numbers validated by `parseAthleteConfig`, never from a raw config string |
| T-17-VW-07 | Tampering | Attacker-influenced value reaching `style.width` | mitigate | Widths are computed as clamped percentages of a known maximum (bar fill capped at 100% of its half-track) and are always numeric; no raw string from data is ever assigned to a style property |
| T-17-CFG-02 | Spoofing | Fabricated HR zones when config is absent | mitigate | This module constructs no zone boundary and no max HR (asserted by grep); it renders `null` as literal absence, so a missing config can never be papered over with a derived value (D-30/D-31) |
| T-17-VW-08 | Denial of Service (usability) | Seven columns forcing the page body to scroll horizontally | mitigate | Scrolling is confined to the `.splits-scroll` wrapper from plan 17-01 with a sticky opaque `Km` column; this module adds no inline width or overflow style that could escape that container (D-27) |
| T-17-SC | Tampering | npm/pip/cargo installs | accept | No packages installed this phase; both breakdowns are hand-rolled DOM bars rather than a new charting dependency (17-RESEARCH.md § Package Legitimacy Audit) |
</threat_model>
