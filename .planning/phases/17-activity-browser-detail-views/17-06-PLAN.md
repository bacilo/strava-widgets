## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Committed repo file → published static asset | The build copies committed JSON into the public GitHub Pages output; anything placed in `data/config/` becomes world-readable |
| Deployed HTTPS URL → browser fetch | The dashboard fetches `data/config/*.json` at runtime; a 404 or an HTML error page can arrive where JSON was expected |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-CFG-03 | Information Disclosure | `data/config/athlete.json` (maxHr, HR zones) | accept | Resting/max HR is personal health data, but every committed stream and activity JSON already publishes per-second HR for the same athlete; this adds no new disclosure surface. `data/config/gear.json` holds shoe model names, which carry no privacy risk. Documented in each file's `note`. Explicitly do NOT add athlete ids, tokens, or any field from `data/tokens.json` to either file |
| T-17-PUB-01 | Spoofing | GitHub Pages serving its 404 HTML page with a 200 status for a missing data path | mitigate | The verifier `JSON.parse`s both bodies and asserts their internal shape (`gear` object, five-entry `hrZones`), so an HTML body fails rather than passing a reachability-only check |
| T-17-PUB-02 | Denial of Service (feature) | New committed data silently absent from the publish dir | mitigate | `copyDataFiles` gains the `data/config` entry AND the verifier gains two `expect200` assertions; the load-bearing rename experiment proves the gate actually fails when the file is missing |
