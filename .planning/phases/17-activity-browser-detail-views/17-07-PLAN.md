<objective>
Add the two browser-side fetch clients for the config files created in plan 17-06, following the
`IndexClient` shape, and the pure gear-resolution ladder that DETAIL-01's gear tile depends on.

Purpose: `data/config/*.json` must be readable by the BROWSER at runtime. The existing
hand-maintained config loader in `src/analytics/best-effort-exclusions.ts` is a Node-only
`FileStore` reader (17-RESEARCH.md Pitfall 8) and is the wrong template. These clients copy the
fetch-once/memoize shape from `index-client.ts` but change the caller contract: a missing or
malformed file resolves to `null` (the `fetchStatsJson` idiom from `overview.ts`), because per
D-31/D-33 absence is a legitimate degraded state, not an error.

Output: `gear-client.ts`, `athlete-config-client.ts`, and their colocated test files.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTPS fetch of `data/config/*.json` → dashboard runtime | The response body is untrusted structure: it may be a 404 HTML page, a truncated file, or a hand-edit typo |
| `gear_id` / `device_name` from `data/activities/<id>.json` → rendered gear label | Values pass through an index-signature-widened `StravaActivity`, so their runtime type is genuinely unknown |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-CFG-04 | Tampering | `parseGearDocument` | mitigate | Requires an own `gear` property that is a non-array object, copies only own string-valued entries into a fresh map, and returns null on any structural failure — no prototype key is reachable and a wrong-shape body never reaches a render site |
| T-17-CFG-05 | Spoofing | HTML 404 page served with a 200 status | mitigate | Both clients wrap `json()` in try/catch and run structural validation afterwards; an HTML body resolves to `null`, which the caller renders as "no data" — and plan 17-06's verifier independently proves the real URLs return parseable JSON so this degradation cannot silently hide a broken deploy |
| T-17-VW-02 | Tampering (XSS) | Gear label rendered into the stats header | mitigate | `resolveGearLabel` returns a plain string; plan 17-14 writes it with `textContent` (T-16-VW-01 lineage). No HTML is produced in this module |
| T-17-CFG-06 | Information Disclosure | Raw internal gear id rendered to the page | mitigate | The resolution ladder has no branch that returns `gearId`; a named test asserts the raw id is never the returned value across at least 6 input combinations (D-32) |
| T-17-DC-01 | Denial of Service (feature) | A transient fetch failure permanently poisoning the client | mitigate | `inFlight` is cleared on failure, copying `index-client.ts`'s documented reset, so a Retry issues a genuine new request |
| T-17-SC | Tampering | npm/pip/cargo installs | accept | No packages installed this phase (17-RESEARCH.md § Package Legitimacy Audit) |
</threat_model>
