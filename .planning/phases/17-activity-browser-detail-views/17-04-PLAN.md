<objective>
Build the two pure computation modules behind the detail page's charts and splits table: per-km
split derivation and chart-series preparation (including Δt-weighted pace smoothing, hover
geometry, and tamper-safe overlay persistence).

Purpose: committed streams are NOT uniformly sampled — a real committed file starts
`t = [0, 1, 5, 10, 14, 16, 18, 20, 22, 24]` (17-RESEARCH.md Pitfall 1). Every naive per-index
average or nearest-sample snap silently misweights. This repo already has the correct technique in
`findBestEffort`; this plan mirrors it rather than re-deriving it, and proves the result under
vitest since neither Chart.js canvases nor Leaflet are testable in a Node environment.

Output: `detail-splits.ts`, `detail-charts-logic.ts`, and their colocated test files.
</objective>

Create `src/dashboard/views/detail-splits.ts` as a pure, DOM-free module exporting:

- `export interface Split { km: number; distanceM: number; durationSec: number; paceSecPerKm: number; isPartial: boolean; startTimeSec: number; endTimeSec: number; avgHr: number | null; avgCadence: number | null; elevDeltaM: number | null; }`
- `export function computeSplits(stream: CanonicalStream): Split[]`

Implementation contract:
1. Call `validateStreamSeries(stream.t, stream.d)` first (import it from
   `../../analytics/best-effort-utils.js`) and return `[]` when it reports `ok: false`. This reuses
   the existing equal-length / minimum-count / finiteness / non-decreasing checks rather than
   re-deriving them.
2. Walk `d` forward once looking for each successive `km * 1000` boundary. At each boundary use the
   exact interpolation formula from `findBestEffort` lines 117–121 — compute the fraction of the
   bracketing segment needed to reach the boundary and interpolate `t` at that fraction. Never snap
   to `t[j]`. This is an O(n) single forward pass, not the two-pointer sliding search.
3. Emit the final partial kilometre (D-28) whenever real distance remains beyond the last full
   boundary: `distanceM` is the true remainder, `durationSec` runs from the last crossing to
   `t[last]`, and `isPartial` is true. Plan 17-13 renders its label as
   `"{n} ({distance} km, partial)"`.
4. Per-split channel aggregation must be Δt-weighted, never a sample-count mean (17-RESEARCH.md
   Pitfall 1). For `avgHr` and `avgCadence`, accumulate `value[i] * (t[i+1] - t[i])` over the
   samples inside the split's `[startTimeSec, endTimeSec]` window, including the fractional first
   and last sub-intervals at the interpolated boundaries, then divide by the split's `durationSec`.
   Return null for a channel the stream omits entirely.
5. `elevDeltaM` is the interpolated `alt` at `endTimeSec` minus the interpolated `alt` at
   `startTimeSec` (linear interpolation between the bracketing samples), or null when `alt` is absent.
6. Total function: never throws for any `CanonicalStream`-shaped input, including zero-length arrays.

Channels and series:
- `export type ChannelKey = 'pace' | 'hr' | 'cadence' | 'elevation';`
- `export const CHANNEL_KEYS: readonly ChannelKey[]` — fixed band order pace, hr, cadence, elevation (D-17).
- `export type XAxisMode = 'distance' | 'time';`
- `export interface SeriesPoint { x: number; y: number; }`
- `export function availableChannels(stream: CanonicalStream): ChannelKey[]` — returns `[]` when
  `validateStreamSeries` fails; otherwise `pace` plus each of `hr`/`cadence`/`elevation` whose array
  is present and non-empty, in `CHANNEL_KEYS` order.
- `export const PACE_SMOOTHING_WINDOW_SEC = 20;` (17-UI-SPEC pins 20 s, inside D-22's 15–30 s range).
- `export function derivePaceSeries(t: number[], d: number[], windowSec?: number): (number | null)[]`
  — for each sample index, take the centred window of real elapsed time `±windowSec/2`, sum the
  actual distance and actual elapsed time across that window using the real `t` values (never a
  fixed sample count), and return `elapsed / (metres / 1000)`. Return null for any window where
  metres or elapsed is 0. This is presentation-only smoothing (D-22): it is never persisted and
  never feeds `computeSplits` or a stats value.
- `export function buildChannelSeries(stream: CanonicalStream, channel: ChannelKey, xAxis: XAxisMode): SeriesPoint[] | null`
  — `x` is `stream.d[i] / 1000` for `'distance'` and `stream.t[i]` for `'time'`; `y` is the smoothed
  pace for `'pace'` (skipping null entries) and the raw channel array value otherwise. Returns null
  when the channel is unavailable. Points are emitted pre-shaped as `{x, y}` so Chart.js can run
  with `parsing: false`.

Hover geometry (feeds both the crosshair and the D-26 map marker):
- `export function distanceFractionAtX(stream: CanonicalStream, xAxis: XAxisMode, x: number): number`
  — converts a hovered x value into a cumulative-distance fraction in `[0, 1]`. For `'time'`, first
  interpolate the cumulative distance at that elapsed time; for `'distance'`, use the value directly.
  Clamped, never NaN.
- `export function pointAtDistanceFraction(coords: readonly [number, number][], fraction: number): [number, number] | null`
  — walks the polyline's cumulative planar segment lengths and linearly interpolates the position at
  `fraction`. Kept in this module (rather than in `detail-map.ts`) precisely because it is
  Leaflet-free and therefore unit-testable under `environment: 'node'`; it is the second half of the
  same hover-sync pipeline. Document the D-26 honesty caveat in the function's doc comment: the
  result is interpolated along a simplified `summary_polyline` by cumulative distance, because
  committed streams carry no lat/lng — it is approximate, not GPS-matched.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `localStorage` → overlay configuration | Fully user/attacker-writable from the browser console or a same-origin script; read on every detail-view open |
| `data/streams/<id>.json` → computation input | Self-published static data, but a malformed or truncated file must degrade, not crash the view |
| Decoded polyline coordinates → hover geometry | Derived from `map.summary_polyline` in a self-published activity file; may be empty or single-point |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-LS-01 | Tampering | `parseOverlayConfig` / `readStoredOverlayConfig` | mitigate | Allow-list every band key and every overlay entry against `CHANNEL_KEYS`, drop self-overlays, de-duplicate, truncate to `MAX_OVERLAYS_PER_BAND`, validate on READ; try/catch every storage call and fall back to `DEFAULT_OVERLAY_CONFIG` |
| T-17-STR-01 | Denial of Service (client) | `computeSplits` / `derivePaceSeries` loop bounds | mitigate | `validateStreamSeries` gates non-finite and decreasing series before any loop; window walks are bounded by array length, and a zero-length or 1-sample stream returns `[]` immediately |
| T-17-STR-02 | Tampering | Division by zero producing Infinity/NaN in pace | mitigate | Every pace/average division guards its denominator and returns `null` rather than propagating a non-finite value into a chart scale or a table cell |
| T-17-GEO-01 | Denial of Service (client) | `pointAtDistanceFraction` on an empty/degenerate polyline | mitigate | Returns null for an empty coordinate array and the sole coordinate for a single-point route; fraction is clamped to `[0, 1]` |
| T-17-SC | Tampering | npm/pip/cargo installs | accept | No packages installed this phase (17-RESEARCH.md § Package Legitimacy Audit) |
</threat_model>
