# Phase 17 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> This phase has no jsdom in its test toolchain (17-RESEARCH.md Pitfall 4) — every rendering/interaction

## Design System

| Property | Value |
|----------|-------|
| Tool | none — shadcn not applicable (carried forward from 16-UI-SPEC.md, not re-asked) |
| Preset | not applicable |
| Component library | none — hand-rolled view-registry modules, one per route (16-D03), extended this phase with `list-logic.ts`, `calendar.ts`, `calendar-logic.ts`, `detail-charts.ts`, `detail-map.ts`, `detail-splits.ts`, `detail-zones.ts` |

| Mapping | Leaflet 1.9.4 + `@mapbox/polyline` 1.2.1 (already installed) + shared `RouteRenderer` (`src/widgets/shared/route-utils.ts`) — lazy dynamic import on first detail-view open (D-25) |
| Font | `-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, sans-serif` — unchanged from Phase 16, `src/dashboard/styles.css` `--font-stack` |

**Why no shadcn (unchanged from Phase 16):** vanilla TypeScript, light DOM, no component framework. Zero new runtime dependencies this phase — Chart.js and Leaflet are already dependencies, only newly *invoked* from the dashboard bundle via lazy `import()`.

## Spacing Scale

Reused verbatim from `src/dashboard/styles.css` — **no new spacing tokens this phase.**

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge/chip inline padding |
| sm | 8px | Compact spacing: chip gaps, table cell vertical padding, chart-band gap |
| md | 16px | Default element spacing: card padding, filter-panel field gaps, calendar cell padding |
| lg | 24px | Section padding: view container padding, card-to-card gaps, gap between stacked chart bands and the section above/below them |
| xl | 32px | Layout gaps: stats-header tile grid gaps (reused from `.stat-grid`) |
| 2xl | 48px | Major section breaks: between detail-page sections (stats header → map → charts → splits → zones) |
| 3xl | 64px | Page-level spacing (unchanged) |

**Exceptions (new this phase):**
- Filter-chip remove control: minimum 24×24px hit area (WCAG 2.5.8 floor), not the 44px floor reserved for the Phase 16 nav toggle — chips are dense and inline by design (D-09).
- Pagination buttons and calendar day-cell buttons: minimum 32×32px hit area (larger than a chip, smaller than the 44px nav-toggle exception, appropriate for a dense grid of ~35–42 cells or up to 7 page buttons).
- Splits-table sticky first column (`Km`) width: fixed 64px, so the scroll affordance (below) has a stable anchor.
- Chart-band height at viewports <380px: **112px** (not 110px — 112 is the nearest multiple of 4 that stays under the 140px default while preserving the 4px-grid discipline every other declared dimension in this document follows: 140, 220, 320, 380, 400, 720, 24, 32, 64 are all clean multiples of 4).

**New breakpoint (Claude's Discretion, CONTEXT.md flagged the exact number as open):** **720px** — the list's table/card switch (D-01's "roughly 700px"). This is distinct from Phase 16's existing 640px nav-collapse breakpoint; the two do not coincide, so between 641px and 720px the nav is expanded but the list is already in card mode. Verified no ~700px breakpoint previously existed in `styles.css` (17-RESEARCH.md Sources).

## Typography

Reused verbatim from `src/dashboard/styles.css` — **exactly 4 sizes, 2 weights, no additions.** Every new surface this phase adds must map onto one of these four roles; do not introduce a 5th size (e.g. no 12px "micro" label anywhere, including calendar run-count markers).

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 400 | 1.5 |
| Heading | 20px | 600 | 1.2 |
| Display | 28px | 600 | 1.2 |

**New usage mappings this phase:**
- **Display (28/600/1.2):** calendar month-total distance figure (D-13); nothing else new.
- **Heading (20/600/1.2):** calendar day-cell distance figure (D-14 — "must be readable without hovering," 20px clears that bar at typical cell sizes ≥64px); section headers within the detail page ("Route", "Pace & Effort", "Splits", "Heart Rate Zones", "Pace Distribution").
- **Body (16/400/1.5):** filter-panel field labels; splits-table body cells (numeric values); calendar multi-run picker list items.
- **Label (14/400/1.5):** table column headers; sort-direction indicator text; filter chips; pagination "Page X of Y"; chart axis tick labels (Chart.js `font.size: 14`); em-dash placeholders for missing data; calendar weekday header row and run-count marker ("×2"); overlay-picker checkbox labels; splits-table partial-row annotation (see Splits Table below — italic is used for emphasis, not a 3rd weight).

One permitted style variant, not a new weight: **italic** on the splits table's final partial-km row label (e.g. "7 (0.4 km, partial)"), still Label/14/400 — italic is a font-style, not a font-weight, so it does not violate the 2-weight rule.

## Color

Reused verbatim from `src/dashboard/styles.css` — **no changes to the base semantic tokens.**

| Role | Light | Dark | Usage |
|------|-------|------|-------|
| Dominant (60%) `--bg` | `#ffffff` | `#1a1a2e` | Page background |
| Secondary (30%) `--surface` | `#f5f5f7` | `#242444` | Cards, table header row, chart-band card wrapper, calendar grid background, filter panel |
| Accent (10%) `--accent` | `#fc4c02` | `#ff6b35` | See extended "Accent reserved for" list below |
| Text `--text` | `#333333` | `#e0e0e0` | Primary text — including calendar day-cell distance figures at every tint level (see Calendar Tint Scale) |
| Text-secondary `--text-secondary` | `#666666` | `#a0a0b8` | Label-role text, em dashes, disabled overlay-checkbox hints |
| Border `--border` | `#e5e5e5` | `#33334d` | Card/table/cell borders, chart gridlines, splits-table pace-bar track |
| Destructive `--destructive` | `#dc2626` | `#f87171` | Reserved, **still not used in Phase 17** — no destructive UI actions in this phase's scope (filter "Clear all" is reversible client-state, not a destructive action; see Copywriting Contract) |

**Accent reserved for (extends Phase 16's list — nothing else may use `--accent`):**
1. Active nav item indicator, theme toggle active icon, primary CTA (Phase 16, unchanged)
2. Loading indicator/spinner (Phase 16, unchanged)
3. Focus-visible outline ring (Phase 16, unchanged)
4. **NEW:** Active sort-column direction arrow in the list table header
5. **NEW:** Calendar distance tint scale (a *derived opacity wash* of this same hex, not a new hue — see below)
6. **NEW:** Route-map polyline and position marker (already `#fc4c02`/`RouteRenderer`'s default — pass the resolved `--accent` value explicitly per theme rather than relying on the hardcoded default, so the route recolors correctly in dark mode)
7. **NEW:** Pace-channel chart color (`--chart-pace`, below, is a literal alias of `--accent` — not a separate color)

Do not use accent for body text, badges, table row hover state, or any non-interactive surface — unchanged from Phase 16.

**Explicitly NOT on this list — pagination current-page fill and the x-axis segmented-control active fill:** the checker measured white text directly on raw `--accent` at ~3.4:1 in light mode and ~2.8:1 in dark mode — both below WCAG AA's 4.5:1 floor for normal-size text. This is a live, shipped contrast defect inherited from Phase 16's `.cta` pattern (`background: var(--accent); color: #ffffff;` in `src/dashboard/styles.css`), and this phase must not propagate it into two new surfaces. Both controls instead use the dedicated `--accent-strong` variant defined immediately below, never raw `--accent`.

### NEW: Accent-strong (contrast-safe active-state fill — pagination + segmented control only)

A darker, more saturated variant of the accent hue, reserved exclusively for the two controls named above. It exists solely because raw `--accent` fails WCAG AA 4.5:1 with white text in both themes (measured above); `--accent-strong` is verified below to clear it with margin.

| Token | Light | Dark |
|-------|-------|------|
| `--accent-strong` | `#b3390a` | `#c2410c` |

**Contrast (white `#ffffff` text on `--accent-strong` fill, WCAG relative-luminance formula — figures below so the manual checkpoint can verify rather than re-derive them):**
- Light: `#ffffff` on `#b3390a` → **5.99:1** (clears AA 4.5:1)
- Dark: `#ffffff` on `#c2410c` → **5.18:1** (clears AA 4.5:1)

**Used by (exhaustive — do not extend `--accent-strong` to any other control without re-verifying contrast):**
1. Pagination current-page button — background `--accent-strong`, text `#ffffff` (Activity List, §1).
2. X-axis segmented-control active option ("Distance"/"Time") — background `--accent-strong`, text `#ffffff` (§4c Charts).

Inactive/rest states are unaffected: pagination non-current-page buttons keep neutral `--surface`/`--text` chrome, and the segmented control's inactive option keeps `--surface` background / `--text-secondary` text — both unchanged from the original draft.

### NEW: Chart channel colors (data-visualization palette, exempt from the 60/30/10 chrome split)

Charts are inherently multi-hue data displays; this small fixed palette is scoped **only** to chart lines/fills/legends and is documented here so it stays consistent across every band, the pace histogram, and any future Phase 18 trend chart that reads the same channels.

| Channel | Token | Light | Dark | Used by |
|---------|-------|-------|------|---------|
| Pace | `--chart-pace` | `#fc4c02` (= `--accent`) | `#ff6b35` (= `--accent`) | Pace band, pace histogram bars, splits-table pace-bar fill |
| Heart Rate | `--chart-hr` | `#e11d48` | `#fb7185` | HR band — **deliberately distinct from `--destructive`** (`#dc2626`/`#f87171`) even though both are red; reusing the destructive token here would violate "destructive reserved for destructive actions only" |
| Cadence | `--chart-cadence` | `#0891b2` | `#22d3ee` | Cadence band |
| Elevation | `--chart-elevation` | `#16a34a` | `#4ade80` | Elevation band |

**Overlay fill rule (D-18/D-19):** an overlay renders as a flat area fill in its own channel color, no border, `z-index` behind the band's primary line:
- 1st selected overlay: 18% opacity fill
- 2nd selected overlay: 10% opacity fill, drawn further back (so two overlapping overlays both stay legible)
- Primary line: 100% opacity, 2px stroke, no point markers except a single synced hover dot

**HR zone colors** (D-29/D-31 panel, fixed across both themes — a recognizable red/orange/yellow/green/blue convention, not a light/dark-adjusted brand color):

| Zone | Color |
|------|-------|
| Zone 1 | `#3b82f6` (blue) |
| Zone 2 | `#22c55e` (green) |
| Zone 3 | `#eab308` (yellow) |
| Zone 4 | `#f97316` (orange) |
| Zone 5 | `#ef4444` (red) |

### NEW: Calendar distance tint scale (D-14 — resolves a contradiction in CONTEXT.md)

CONTEXT.md D-14 calls for "the existing orange accent scale," but 17-RESEARCH.md's direct inspection of `styles.css` (Sources section) confirms only a single `--accent` value exists — no scale. **Decision made here:** derive a 4-step opacity wash of `--accent` for cell backgrounds. This keeps the calendar inside the accent hue (no new hue introduced) while staying legible:

| Day total | Cell background | Text color |
|-----------|-----------------|------------|
| Rest day (0 km) | none (transparent) | `--text-secondary`, plain "–" |
| 0.1–5 km | `--accent` @ 12% opacity | `--text` |
| 5–10 km | `--accent` @ 25% opacity | `--text` |
| 10–15 km | `--accent` @ 40% opacity | `--text` |
| 15 km+ | `--accent` @ 55% opacity (capped — never higher) | `--text` |

**Contrast directive for the executor:** text color never changes to compensate for the tint (one text-color rule, no exceptions) — if a manual contrast check during implementation shows the 55% band falls under 4.5:1 against `--text`, lower the opacity cap, do not darken/lighten the text.

## Surface Contracts

Each surface below is written as a checkable statement, doubling as the manual-verification script for 17-VALIDATION.md's Manual-Only Verifications table.

### 1. Activity List (`#/list`)

**Layout switch:** a real `<table>` renders above **720px** viewport width; a stack of `renderActivityRow` cards (unchanged Phase 16 renderer) renders at or below 720px (D-01).

**Desktop table — 7 columns, in this exact order:**
`Date | Activity | Distance | Moving Time | Pace | Avg HR | Status`

- **Date, Distance, Moving Time, Pace, Avg HR** are sortable — every BROWSE-02 key (D-02). **Activity** and **Status** are not sortable.
- Each sortable `<th>` wraps a full-cell `<button>`; its label carries a trailing direction arrow (▲/▼, inline SVG, `--accent` color) only when that column is the active sort; every `<th>` carries `aria-sort` = `"ascending" | "descending" | "none"`.
- **Default sort direction on first click, per column** (documented so no two columns behave inconsistently): Date, Distance, Moving Time, Avg HR → **descending** first (most/longest/highest first, matching "biggest number first" intuition). Pace → **ascending** first (lower sec/km = faster = surfaced first, the value most users are looking for when sorting by pace). Second click on any column flips its direction; clicking a different column resets to that column's documented first-click default.
- **Initial state before any user interaction:** Date, descending (newest activity first) — matches the existing overview/recent-activities ordering.
- **Activity** cell: the athlete-authored name (`textContent` only, T-16-VW-01) wrapped in a plain-styled `<a href="#/activity/:id">` (body-text appearance, not `.cta` button chrome, to avoid 50 repeated buttons per page) with an `aria-label` combining name + date + distance for context.
- **Status** cell: the existing badges (no streams / no HR / low confidence / excluded from records / PR count) rendered inline via the unchanged `.badge` class, wrapped so they can flow to a second line without breaking row height.
- Whole `<tr>` is clickable (mouse convenience — `cursor: pointer`, hover background lightly darkens `--surface`); keyboard users rely on the Activity-cell anchor, which is already fully operable via Tab + Enter.

**Mobile card mode (≤720px):** unchanged `renderActivityRow` cards, plus a compact **sort `<select>`** above the list replacing the header-click affordance, with options like "Date (newest)", "Pace (fastest)", etc. — each option maps to one (sortKey, direction) pair; changing it updates the same URL query params a header click would (D-03).

**Pagination:** numbered, 50 rows/page (D-05/D-06). Controls: `‹ Prev`, up to 7 numbered buttons (ellipsis beyond that), `Next ›`, plus the always-visible "Page {n} of {total}" label. Current-page button uses the `--accent-strong` fill / white-text treatment (Color § "Accent-strong" — 5.99:1 light / 5.18:1 dark, both clear WCAG AA 4.5:1), not raw `--accent`. Changing sort or any filter resets to page 1 (D-05).

**Return-from-detail (D-08):** navigating back to `#/list` restores page/sort/filters from the URL (no separate storage) and applies a brief highlight to the row for the activity just viewed — background flashes `--accent` at 15% opacity, fading to transparent over 1.5s via CSS transition — and calls `.focus()` on that row's anchor for keyboard users.

**Phase 16 leftover removed:** the `MAX_ROWS = 100` constant and its truncation-notice paragraph are deleted entirely, not hidden (D-06).

### 2. Filter Bar (`#/list`)

**Always visible (D-09):** search input + active-filter chips row, directly under the page heading.

**Collapsible "Filters" panel (D-09):** toggled by the **Filters** button (Copywriting). Contains:
- Date range: two plain date inputs (min/max) + preset chips **"This year"**, **"Last 12 months"**.
- Distance range: two numeric inputs (km, min/max) + preset chips **"5K"**, **"10K"**, **"HM+"**, **"Marathon+"** (each sets a min/max pair, e.g. HM+ = min 21.0 km, no max).
- Pace range and Duration range: plain numeric min/max inputs only (no presets specified — D-10 does not name pace/duration presets, and none are invented here).
- Open/closed state is a **plain in-memory boolean, not persisted** across sessions and **not** written to the URL (only sort/dir/page/filter *values* are, per D-07) — Claude's Discretion, decided here for simplicity: every fresh visit lands with the panel closed, but toggling it does not reset while paginating/sorting within the same session.

**Live result count (D-11):** a Label-typography line ("{n} activities" — reusing the existing count-line pattern from `list.ts`) updates as filters change: immediately for chips/presets, debounced 200ms for the free-text search input and numeric range inputs.

**Chips (D-12):** one pill per active filter. Exact token pair, pinned for both themes so contrast is verifiable without re-deriving it during implementation:
- Background: `--surface` (`#f5f5f7` light / `#242444` dark)
- Text: `--text` (`#333333` light / `#e0e0e0` dark) — the same pairing already relied on throughout the app by `.activity-row` and `.card` content; not a new contrast pair.
- Border: `1px solid var(--accent)` — distinguishes an *active* filter pill from the neutral `.badge`'s `1px solid var(--border)`, mirroring the existing `.app-nav__link[aria-current="page"]` accent-border precedent (`src/dashboard/styles.css` lines 130–135) rather than inventing a new visual language.
- Shape/padding: `border-radius: 999px` (a true pill, vs. `.badge`'s 4px), `padding: 4px 8px` (`--space-xs` block / `--space-sm` inline).

Each chip's remove control is a 24×24px minimum hit-area `<button>` containing the × icon (inline SVG, `--text-secondary` color). Because the icon has no visible text label, it carries an explicit accessible name: **`aria-label="Remove {constraint} filter"`**, e.g. `aria-label="Remove 10–25 km filter"`, `aria-label="Remove 2024 filter"`, `aria-label="Remove name: hills filter"` — the chip's own visible text (e.g. "10–25 km ×") is decorative to assistive tech; the button's `aria-label` is the authoritative accessible name so the executor does not have to invent one per chip type.

**Clear all** appears once 2+ chips are present, right-aligned in the chips row.

**Zero-match state:** see Copywriting Contract — renders in place of the table/cards, never a blank table (D-12).

### 3. Calendar (`#/calendar`)

**Grid:** standard 7-column (Sun–Sat) month grid, `<table>` or CSS grid of `<button>` day cells including leading/trailing blank cells for days outside the month (rendered as empty, non-interactive, no border) so week rows always align.

**Header:** month-total Display-typography figure ("142.3 km") + Label caption ("across 18 runs") (D-13), with `‹ {Prev Month}` / `{Next Month} ›` and the "Jump to month" control on the same row or wrapping below it on narrow screens.

**Day cell anatomy, top to bottom:**
1. Day-of-month numeral, Label typography, top-left.
2. Distance figure OR "–" for rest days, Heading typography, centered (D-14 — must be legible without hover).
3. Run-count marker "×N" for multi-run days only, Label typography, bottom-right (D-15).

**Cell tinting:** per the Calendar Distance Tint Scale table above. **Never filtered** by the list's active filters (D-16) — the calendar has its own independent URL contract, `#/calendar?month=YYYY-MM` (D-13), and its own in-memory data derivation from the same `IndexClient` rows, with no shared filter state.

**Interaction:** single-run day → clicking navigates straight to `#/activity/:id`. Multi-run day → clicking opens the compact per-run picker (Copywriting Contract). Every day cell (including rest days) is a real `<button>` for consistent Tab order, even though rest-day cells have no click action (they're simply non-interactive buttons with no href/handler — `aria-disabled="true"` on rest-day cells so screen readers don't announce a false affordance).

**Month-boundary and leap-year correctness:** verified by `calendar-logic.test.ts` (17-VALIDATION.md Wave 0); manually confirm at least one month with a Sunday-starting 1st, one with a Saturday-starting 1st, and February in a leap year during the browser checkpoint.

### 4. Activity Detail (`#/activity/:id`)

Section order, top to bottom (Claude's Discretion — CONTEXT.md left this open):
**Heading + date → Stats header → Route map → Charts (stacked bands) → Splits table → Pace distribution / HR zones → Back-to-Activities CTA.**

#### 4a. Stats header

Tile grid reuses the existing `.stat-grid` CSS (`repeat(auto-fit, minmax(200px, 1fr))`) — unchanged, no new layout code needed. Tiles, in this order: **Distance, Moving Time, Pace, Elevation Gain, Avg HR, Max HR, Cadence, Gear.**

**Gear tile resolution (D-32/D-33), most-common-case first (708/1868 activities have no `gear_id` — 17-RESEARCH.md Pitfall 2):**
1. `gear_id` present and mapped in `data/gear.json` → render the mapped name.
2. `gear_id` present but unmapped, or `gear_id` absent → fall back to `device_name` if present → render that.
3. Both absent → **omit the tile entirely.** Never render an empty-labelled tile, never render a raw `g16649854` id.

**Grid reflow when a tile is omitted:** no placeholder box, no explicit handling needed — `auto-fit` already reflows remaining tiles to fill the row when a grid child is simply absent. This is the entire "reflow contract": omitting a DOM node is sufficient, verified visually during the browser checkpoint (confirm no gap/empty cell where Gear would have been).

**Missing HR/cadence/elevation tiles** individually render the em dash per the existing `formatOrDash` pattern in `detail.ts` (unchanged) — they are not omitted like Gear, since distance/time/pace/elevation/HR/cadence are all "named" in DETAIL-01 and a dash communicates "not recorded" more precisely than omission for a metric the user would expect to see.

#### 4b. Route map

**Data source:** `map.summary_polyline` from the already-fetched `data/activities/<id>.json` (D-23) — zero extra requests.

**Three states:**
1. **Polyline present and decodable** → render via `RouteRenderer.renderRoute`, passing the resolved `--accent` value (not the hardcoded `#fc4c02` default) as `options.color`, so the line matches the active theme.
2. **`activity.map` entirely absent** → "No route recorded" empty state (Copywriting).
3. **`activity.map` present but `summary_polyline` missing/empty** (the 27-activity case) → "Route unavailable" empty state — **visibly distinct copy from state 2**, per 17-RESEARCH.md finding #3.

**Hover sync (D-26):** hovering any chart band shows a shared vertical crosshair + tooltip across every band at the same x-position, plus a position marker on the map. Marker = `L.circleMarker({ radius: 6, fillColor: resolved --accent, color: resolved --bg, weight: 2, fillOpacity: 1 })` (Pitfall 6 — circleMarker avoids the Leaflet default-icon-path bundling break). **Honesty caveat, must be visible somewhere near the map (Label typography, `--text-secondary`):** "Position is estimated from distance along the route, not GPS-matched" — because committed streams carry no lat/lng (D-26).

**Map panel dimensions:** min-height 220px on mobile, 320px on desktop; full width of its container; Leaflet fills it (no fixed aspect ratio).

#### 4c. Charts — stacked bands (D-17..D-22)

**Up to 4 bands, each its own Chart.js line chart, vertically stacked with `--space-lg` (24px) gaps:** Pace, HR, Cadence, Elevation, in that fixed order top to bottom. **A channel absent from the stream simply omits its band** — no placeholder, no broken shared axis (D-17).

**Per-band chrome:**
- Card wrapper: `.card` styling (unchanged — `--surface` background, `--border` border, 8px radius).
- Fixed height **140px** per band (**112px** if viewport <380px — the only band-height concession to narrow screens; 112 is a clean multiple of 4, keeping the grid discipline every other declared dimension in this document follows).
- Y-axis: own auto-scaled range per band, ticks in Label typography, axis/gridlines in `--border` (gridlines at reduced ~40% opacity, horizontal only — no vertical gridlines, since the crosshair already provides the vertical reference).
- X-axis tick labels: rendered **only on the bottom-most visible band** (reduces repeated labels across 2–4 vertically-aligned charts); all bands still share the same x-scale domain so the crosshair aligns correctly.
- Primary line: full-opacity 2px stroke in that channel's `--chart-*` color (Color section), no point markers except a single hover dot.

**X-axis toggle (D-21):** a 2-option segmented control ("Distance" / "Time") above the stacked bands — active option uses the `--accent-strong` fill / white-text treatment (Color § "Accent-strong" — 5.99:1 light / 5.18:1 dark, both clear WCAG AA 4.5:1), not raw `--accent`; inactive option uses `--surface`/`--text-secondary`. Default: **Distance.**

**Overlay picker (D-18/D-19):** each band has its own small "Shade behind" checkbox row listing the *other* 3 channels (a band cannot overlay itself). Checking one renders it as an 18%-opacity filled area on that band's own auto-scaled, undrawn axis (no competing tick labels — tooltip carries the true value + unit). A 2nd checked overlay renders at 10% opacity, drawn behind the first. Checking a 3rd is blocked — remaining checkboxes disable with the **"Up to 2"** inline hint (Copywriting).

**Persistence (D-20):** overlay selections persist to `localStorage` (key pattern mirrors `theme.ts`'s tamper-guard: allow-list valid channel names on read, cap at 2, fall back to no-overlay on any parse failure), scoped per-band, applies across activities and sessions. Not written to the URL.

**Smoothing/decimation (D-22):** pace line uses a 20-second rolling window (within the documented 15–30s range) before Chart.js's built-in LTTB `Decimation` plugin caps drawn points at roughly 500 per band (a concrete default — tune during implementation if a real band visibly over/under-simplifies). Raw values still feed the splits table and stats header; smoothed values are display-only, never persisted, never computed from.

#### 4d. Splits table (D-27/D-28)

**7 columns, fixed order:** `Km | Pace | Elapsed | Avg HR | Avg Cadence | Elev Δ | vs. Avg`

- **Responsive strategy (Claude's Discretion — decided here):** a horizontal-scroll wrapper (`overflow-x: auto`) contained within the splits `.card`, **not** column-dropping. The `Km` column is `position: sticky; left: 0` with a `--surface` background (avoiding scroll-through transparency) so scrolling right never loses the row's identity. The page body itself never scrolls horizontally (D-27's hard requirement) — only this one wrapper does.
- **Missing-channel cells** (Avg HR / Avg Cadence when the stream lacks that channel): em dash, unchanged pattern.
- **`vs. Avg` column:** a horizontal bar — track background `--border`, a thin `--text-secondary` center tick marking the activity's average pace, filled bar in `--chart-pace` extending left (faster than average) or right (slower) from that tick.
- **Final partial km (D-28):** its `Km` cell reads "{n} ({distance} km, partial)" in italic Label typography (Typography section) so it is visually distinguishable at a glance from a full split, and the table's total still sums to the real activity distance.

#### 4e. Pace distribution / HR zones (D-29..D-31)

**Pace-distribution histogram — always renders** (DETAIL-05's own-merit half, D-29): bar chart, x-axis = 15-second-per-km-wide pace buckets (e.g. "4:00–4:15/km"), y-axis = minutes spent, bars in `--chart-pace`.

**HR-zone breakdown — renders additionally, only when BOTH `data/athlete.json` config exists AND the activity has an HR stream** (D-29/D-31): 5 bars (or a single stacked bar), one per zone, colors per the fixed HR Zone Colors table, each labelled "Zone {n} ({bpm range})" with minutes + percentage of total moving time.

**Absence is a state, not a fallback UI:** when config or HR is missing, **the zone panel does not render at all** — no empty box, no "coming soon," no fabricated zones (D-31). This is the one place in this phase where "render nothing" is the correct, spec-compliant outcome — verify by opening a no-HR activity and confirming there is no empty panel shell where the zone breakdown would be.

### 5. Cross-Surface

**Navigation:** browser back/forward works natively via hash history (Phase 16, unchanged) and is the primary way list state (D-08) round-trips. The detail page's explicit "‹ Back to Activities" CTA is a fallback for users who deep-link/bookmark directly into a detail view with no prior list history in this session — it always targets a plain `#/list` (no filters), which is an acceptable, documented simplification (Claude's Discretion): it is not expected to reconstruct a filter state it never saw.

**Prev/Next activity navigation (Claude's Discretion, recommended, non-blocking):** two small Label-typography links near the detail heading — "‹ Newer" / "Older ›" — navigate to the chronologically adjacent activity in the *full, unfiltered* archive (the detail view has no filter context of its own). Omit either link at the archive's start/end rather than disabling it.

**Focus management on view change:** after every view's `mount()` completes, focus programmatically moves to that view's `<h1>` (add `tabindex="-1"` if it isn't natively focusable) so assistive-tech users get an announced context change on every hash navigation — list, calendar, detail, and overview alike.

**Keyboard operability:**
- Sort headers: real `<button>` per header cell, Enter/Space triggers, global `:focus-visible` ring applies (unchanged CSS rule).
- Filter inputs, chip-remove buttons, overlay checkboxes, the x-axis segmented control, pagination buttons: all native interactive elements, all keyboard-operable by default.
- Calendar day cells: real `<button>` elements in DOM (row-major) tab order; arrow-key roving-tabindex navigation is a nice-to-have, not required this phase.
- Chart hover-crosshair and map hover-marker are accepted as mouse/touch-only (Chart.js/Leaflet's inherent interaction model) — this is a documented limitation, not a defect, consistent with D-26's own "approximate, not survey-exact" framing.

**Responsive summary at narrow widths:**
| Surface | Behavior below its breakpoint |
|---------|-------------------------------|
| List | Card mode + sort `<select>` below 720px (D-01/D-03) |
| Filter panel | Same collapsible behavior at every width; chips wrap to multiple lines |
| Calendar | Grid cells shrink but never introduce horizontal scroll; weekday header abbreviates to single letters below ~400px; month/year jump stacks under the prev/next row if needed |
| Stats header | `.stat-grid`'s existing `auto-fit` reflows automatically; no new code |
| Chart bands | Fixed 140px height down to 380px viewport width, then 112px below that |
| Splits table | Horizontal-scroll wrapper with sticky `Km` column (never page-level scroll) |
| Map | min-height drops from 320px (desktop) to 220px (mobile), full width either way |
