<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Free-text search input → chip label → DOM | The user's own typed string is echoed back into a visible chip and into an `aria-label`; a shared URL makes it attacker-supplied |
| Hash query filter values → numeric comparisons and DOM | Attacker-controllable via a crafted link (`?dmin=Infinity`, `?pmax=abc`, `?q=<script>`) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-VW-01 | Tampering (XSS) | Chip labels containing the `q` search string, and the chip-remove `aria-label` | mitigate | Labels are set with `textContent` and `setAttribute`, never via an HTML string; the file contains zero `innerHTML` assignments (asserted by grep). `parseListQuery` additionally trims and truncates `q` to 200 characters before it reaches a label |
| T-17-URL-02 | Denial of Service (client) | Numeric range values from the query string | mitigate | Consumed only through `parseListQuery`'s `Number.isFinite` guards (plan 17-02, unit-tested); an unparseable bound drops that single filter rather than producing a `NaN` comparison that silently empties the list |
| T-17-VW-05 | Denial of Service (feature) | Debounced update firing into a torn-down view | mitigate | The debounce timer id is held on the view factory and cleared in `unmount()`, and every update path re-enters through `navigateTo` + the existing `mountedContainer` stale guard |
| T-17-VW-06 | Repudiation (usability) | Zero matches rendering as a blank table | mitigate | The empty state replaces the table/card region entirely, names the situation, and offers a one-click clear even at a single active filter (D-12) |
| T-17-SC | Tampering | npm/pip/cargo installs | accept | No packages installed this phase (17-RESEARCH.md § Package Legitimacy Audit) |
</threat_model>
