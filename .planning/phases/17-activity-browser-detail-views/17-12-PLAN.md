Band construction:
1. Compute `availableChannels(stream)`. Render one `.chart-band` per available channel in
   `CHANNEL_KEYS` order (pace, hr, cadence, elevation). A channel absent from the stream simply
   omits its band — no placeholder card, no empty canvas, and critically no broken shared axis
   (D-17). If `availableChannels` returns an empty array, render nothing and return a no-op handle.
2. Each band is a `.chart-band` containing a `.chart-band__header` (a `.text-label` channel title
   plus the overlay picker from Task 2) and a `.chart-band__canvas-wrap` holding a `<canvas>` with
   an `aria-label` describing the channel — the height is fixed by the CSS from plan 17-01 (140px,
   112px below 380px viewport width), so do NOT set inline canvas dimensions; use Chart.js's
   `responsive: true` and `maintainAspectRatio: false`.
3. Every band's dataset comes from `buildChannelSeries(stream, channel, xAxisMode)` and is fed with
   `parsing: false` since the points are already `{x, y}`-shaped.
4. Scales: a single `linear` x scale whose min and max are IDENTICAL across all bands (compute the
   shared domain once from the first available series) so the crosshair aligns; a per-band `linear`
   y scale with its own auto-scaled range. X-axis tick labels render only on the BOTTOM-MOST
   visible band — set `ticks.display: false` on every band above it while keeping the same domain.
   Gridlines: horizontal only (`grid.display: true` on y, `false` on x) in the resolved `--border`
   colour at ~40% opacity, since the crosshair already provides the vertical reference. Tick font
   size 14 (Label typography — no fifth size).
5. Primary line: 2px stroke in that channel's resolved `--chart-*` colour, `pointRadius: 0`,
   `pointHoverRadius: 4`, `fill: false`.
6. Decimation (D-22): `plugins.decimation = { enabled: true, algorithm: 'lttb', samples: 500 }`.
7. X-axis toggle (D-21): render one `.segmented` control ABOVE the `.chart-stack`, with two
   `.segmented__option` buttons labelled `Distance` and `Time`. The active one carries
   `.segmented__option--active` (the `--accent-strong` fill, the only place besides pagination
   permitted to use it) and `aria-pressed="true"`. Default is `Distance`. Switching mode rebuilds
   every band's data from `buildChannelSeries(..., newMode)` and updates the shared x domain; it is
   in-memory only for the session and is deliberately NOT persisted and NOT written to the URL
   (only overlay config persists, per D-20).
8. `destroy()` calls `.destroy()` on every Chart instance, removes listeners, and is safe to call
   twice — plan 17-14 calls it when a fast activity-to-activity navigation supersedes an in-flight
   mount.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `localStorage` overlay config → chart dataset construction | Fully user/attacker-writable from the console or any same-origin script; read on every detail-view open |
| `data/streams/<id>.json` channel arrays → chart scales and tooltips | Self-published static data that may be absent, empty, or contain out-of-range values |
| Dynamically imported chunk URL → browser module loader | Same-origin, emitted by Vite; a failed resolution must degrade rather than hang |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-LS-01 | Tampering | Stored overlay config driving dataset creation | mitigate | All reads go through `readStoredOverlayConfig`/`parseOverlayConfig` (plan 17-04, unit-tested): channel names allow-listed against `CHANNEL_KEYS`, self-overlays dropped, entries de-duplicated and truncated to `MAX_OVERLAYS_PER_BAND`, every storage call try/catch-wrapped. No second validation path exists in this module (asserted by grep) |
| T-17-LS-02 | Denial of Service (client) | A tampered config requesting hundreds of overlay datasets | mitigate | The cap is enforced on READ, so at most 2 overlay datasets plus 1 primary can ever exist per band, and at most 4 bands exist |
| T-17-VW-01 | Tampering (XSS) | Band titles, picker labels, tooltip strings | mitigate | All DOM text is set with `textContent`; zero `innerHTML` in the module (asserted by grep). Tooltip content is produced by Chart.js callbacks returning plain strings rendered into its own canvas, never into HTML |
| T-17-STR-02 | Tampering | Non-finite values reaching a chart scale | mitigate | Series come exclusively from `buildChannelSeries`/`derivePaceSeries`, which return `null` rather than `Infinity`/`NaN` for degenerate windows (plan 17-04, unit-tested); null points are skipped rather than plotted |
| T-17-CHT-01 | Denial of Service (client) | Rendering ~thousands of points per band on a long activity | mitigate | Chart.js's built-in LTTB `Decimation` plugin caps drawn points at 500 per band, and `parsing: false` avoids a per-point normalization pass |
| T-17-CHT-02 | Denial of Service (feature) | Lazy chunk failing to load | mitigate | The dynamic import is awaited inside plan 17-14's try/catch, which renders the "Couldn't load the charts" state with a working Retry |
| T-17-SC | Tampering | npm/pip/cargo installs | accept | No packages installed this phase; `chart.js@4.5.1` is a pre-existing, in-production dependency and the crosshair is a local inline plugin rather than a new package (17-RESEARCH.md § Package Legitimacy Audit) |
</threat_model>
