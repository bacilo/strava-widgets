`leaflet/dist/leaflet.css`, and `../../widgets/shared/route-utils.js`. The lazy boundary is the
MODULE itself — plan 17-14 reaches it only via `await import('./detail-map.js')`, and Vite's
code-splitting therefore puts Leaflet and its stylesheet into that async chunk rather than the SPA
entry. Placing the boundary at the module edge (rather than at `await import('leaflet')` inside a
function) is what guarantees Leaflet can never leak into the main chunk through a stray top-level
reference. Add a prominent file-header comment stating this, stating that nothing outside
`detail.ts`'s dynamic import may import this module statically, and citing D-25 plus
17-RESEARCH.md Assumption A1 (Vite's async-CSS `<link>` injection is documented but not previously
exercised in this repo, so it must be confirmed in a real browser — plan 17-15).

`single-run-map`'s `import leafletCSS from 'leaflet/dist/leaflet.css?inline'` plus `<style>`
injection — that variant exists only because Shadow-DOM widgets cannot use a `<link>`, and the

Behaviour:
1. Build a `.route-map__canvas` element inside `container`, create the map with
   `L.map(canvasEl)`, add basemaps with `RouteRenderer.addBasemapSwitcher(map)` (reusing the
   existing CARTO/OSM layer set rather than adding a new tile source), and call
   `map.invalidateSize()` inside a `requestAnimationFrame` so Leaflet recalculates tile positions
   after layout — the same sequence `single-run-map` uses.
2. Render the route with `RouteRenderer.renderRoute(map, routeData, { color: options.accentColor, weight: 4, opacity: 1.0, showPopup: false, fitBounds: true })`.
   `showPopup` MUST be false: `formatPopupContent` interpolates the route name into an unescaped
   HTML template string, which is the exact anti-pattern T-16-VW-01 forbids in this dashboard.
   Pass the resolved `--accent` value explicitly (17-UI-SPEC § 4b) rather than relying on
   `DEFAULT_OPTIONS`'s hardcoded `#fc4c02`, so the route recolours in dark mode.
3. Build `routeData` as a `RouteData` from `options`. `RouteData.id` is typed `number`; derive it
   with `Number.parseInt` on the numeric portion of the activity id and fall back to `0` when the
   id is `i`-prefixed (intervals.icu era) — the field is unused by `renderRoute` and must not
   become a reason to widen the shared type.
4. Position marker: create one `L.circleMarker` with
   `{ radius: 6, fillColor: options.accentColor, color: options.bgColor, weight: 2, fillOpacity: 1 }`
   (17-UI-SPEC § 4b). `setPositionByFraction(fraction)` decodes the polyline once at mount into a
   coordinate array, then calls `pointAtDistanceFraction(coords, fraction)` (imported from
   `./detail-charts-logic.js` — pure and Leaflet-free, already unit-tested by plan 17-04) and moves
   the marker there. Passing `null` removes the marker from the map. Never re-decode the polyline
   per hover event.
5. `destroy()` calls `map.remove()`, drops all references, and is safe to call twice.
6. Render the honesty caveat (D-26) as a `.route-map__caveat` element below the canvas reading
   `Position is estimated from distance along the route, not GPS-matched.` — committed streams carry
   no lat/lng by design, so the marker is interpolated by cumulative distance along the simplified
   `summary_polyline`. This line is mandatory whenever the marker feature is present.

Do NOT fetch anything in this module. The polyline arrives as a parameter from the activity detail
JSON the view already fetched (D-23). Explicitly do not fetch `data/routes/route-list.json`
(2.4 MB for one route, missing ~28 activities) and do not add a per-activity route pipeline output.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `activity.map.summary_polyline` → `@mapbox/polyline` decode | Self-published static data, but a truncated or hand-mangled value reaches a decoder inside the rendering path |
| Third-party tile servers (CARTO basemaps, OSM) → map imagery | External hosts outside this project's control, contacted on every detail view with a route |
| Dynamically imported chunk URL → browser module loader | The chunk URL is emitted by Vite and served from the same origin; a failed resolution must degrade, not hang |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-POLY-01 | Tampering | `polylineCodec.decode` inside `RouteRenderer.renderRoute` and the marker decode | mitigate | No new decode path is introduced (the existing, already-exercised `RouteRenderer` is reused); the whole mount is wrapped in try/catch rendering the `Couldn't load the route map` state, so a mangled polyline degrades to an omitted map rather than a thrown error that breaks the page |
| T-17-VW-01 | Tampering (XSS) | Leaflet popup content | mitigate | `showPopup: false` is passed explicitly so `RouteRenderer.formatPopupContent` — which interpolates the route name into an unescaped HTML template string — is never invoked from the dashboard. Asserted by grep |
| T-17-MAP-01 | Information Disclosure | Third-party tile requests revealing route locations to CARTO/OSM | accept | The reused `addBasemapSwitcher` contacts the same tile hosts every existing map widget in this project already uses; the route data itself is already published publicly. No new host is introduced |
| T-17-MAP-02 | Denial of Service (feature) | Lazy chunk failing to load (offline, cache miss, bad deploy) | mitigate | The dynamic import is awaited inside plan 17-14's try/catch and this module exposes an `error` state with a working Retry, mirroring `detail.ts`'s existing fetch-failure pattern |
| T-17-MAP-03 | Denial of Service (client) | Re-decoding the polyline on every hover event | mitigate | The coordinate array is decoded exactly once at mount and reused by `setPositionByFraction`; `pointAtDistanceFraction` clamps its fraction to `[0, 1]` and returns null for a degenerate route |
| T-17-SC | Tampering | npm/pip/cargo installs | accept | No packages installed this phase; `leaflet@1.9.4` and `@mapbox/polyline@1.2.1` are pre-existing, in-production dependencies (17-RESEARCH.md § Package Legitimacy Audit) |
</threat_model>
