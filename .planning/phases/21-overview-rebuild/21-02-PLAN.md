<objective>
Turn `renderActivityRow` into a renderer that three simultaneously-visible surfaces can safely
share, and give it D-06's two-line hierarchy.

Purpose: D-05 retires `renderRecentPrRow` into this function, which means Overview will call it
twice on one page render. `renderActivityRow` hardcodes its element-id prefix as
`activity-card-${row.id}` (`list.ts:328`), a scheme designed for "one row rendered once in one of
two CSS-hidden alternate layouts". A PR-carrying, low-confidence activity that also sits in the
last ten activities would render the same `.sr-only` description `id` twice in the same document —
invalid HTML with an ambiguous `aria-describedby` target. That collision is a bug THIS phase
introduces, so it is fixed here, before the call site that triggers it exists (plan 21-04).

D-06's two-line shape lands in the same plan because it is the same function: the flat
`flex-wrap: wrap` sibling list of name, meta and badge spans is the literal mechanism producing
OVR-01's "three stacked divs" complaint. The CSS half lands in plan 21-03 against the class
contract this plan establishes.

Output: `renderActivityRow(row, surface)` emitting
`a.activity-row > (div.activity-row__header > div.activity-row__name + div.activity-row__badges) + div.activity-row__meta`,
with per-surface element-id scoping.
</objective>

```typescript
// src/dashboard/views/list.ts
/** Every surface that renders a `.activity-row`, in one place. */
export type RowSurface =
  | 'activity-card'          // Activities screen mobile card (existing id prefix, unchanged)
  | 'activity-table'         // Activities screen desktop table (existing id prefix, unchanged)
  | 'overview-prs'           // Overview "Recent PRs" card (new, plan 21-04)
  | 'overview-activities';   // Overview "Recent Activities" card (new, plan 21-04)

export function rowIdPrefix(surface: RowSurface, rowId: string): string;

export function renderActivityRow(
  row: DashboardIndexRow,
  surface?: RowSurface   // defaults to 'activity-card'
): HTMLElement;
```

DOM contract (class names are frozen for downstream phases):

```
a.activity-row
  div.activity-row__header
    div.activity-row__name        <- row.name via textContent
    div.activity-row__badges      <- every span.badge and the .sr-only description span
  div.activity-row__meta          <- date · distance · duration · pace
```

`.activity-row`, `.activity-row__name`, `.activity-row__meta` and `.badge` keep their existing
names (17-UI-SPEC class contract). `.activity-row__header` and `.activity-row__badges` are new.
