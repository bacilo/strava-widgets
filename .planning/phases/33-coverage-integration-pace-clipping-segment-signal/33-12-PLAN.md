Standing process facts this plan operates under:
- Nightly CI (`git-auto-commit-action`) commits to origin/master. Expect a non-fast-forward push
  rejection; resolve with `git merge origin/master`, NEVER a rebase — rewriting a long local
  history for an auto-generated data commit is the mistake 16-14 recorded.
- Never place a skip-ci token anywhere in a commit message body: quoting it suppresses the whole
  daily-refresh run (recorded project hazard).
- `data/streams/` immutability is gated by `npm run compute-stream-checksums`, which must report
  `added N` for genuinely new streams and must never report a digest mismatch.
- `data/stats/` and `data/dashboard/` are BOTH gitignored. `npm run compute-dashboard-index`
  therefore produces local, uncommitted documents — which is exactly what the served build in
  plan 33-13 reads, and why that build must be produced on this checkout after the merge.
- `npm test` is the nightly deploy gate and runs `fileParallelism: false`.
- Stale local artifacts fail the post-merge gate on schema-widening waves: regenerate `data/` and
  `build-widgets` on the primary checkout before concluding a red suite means a merge conflict.
</interfaces>
