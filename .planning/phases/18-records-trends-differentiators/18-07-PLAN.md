Create `src/analytics/compute-training-load.ts` following `compute-best-efforts.ts`'s structure exactly.

`export interface ComputeTrainingLoadOptions { activitiesDir?: string; streamsDir?: string; streamsManifestPath?: string; athleteConfigPath?: string; athletePrivatePath?: string; statsDir?: string; }` — defaults `'data/activities'`, `'data/streams'`, `'data/streams/manifest.json'`, `'data/config/athlete.json'`, `'data/private/athlete-private.json'`, `'data/stats'`.

`export async function computeTrainingLoad(options): Promise<TrainingLoadDocument>`:

1. **Required input:** the stream manifest. A missing manifest throws with a message naming `npm run backfill-streams`, matching how `compute-dashboard-index` treats it.
2. **Required-for-anything input:** the public `data/config/athlete.json`, validated through `parseAthleteConfig`. If it is absent or invalid there are no zone boundaries, so **no** Edwards series is possible — write a document with `models: { edwards: false, banister: false }`, an empty `days` array, and a `banisterDisabledReason` naming the missing zones, then return. Do not throw: the non-blocking-failure convention says bad data is reported, never halts the pipeline.
3. **Optional input:** `loadAthletePrivateConfig`. When it returns `null`, or when `restingHr` is `null`, or when `sex` is absent, set `models.banister = false` and `banisterDisabledReason` to a message naming `data/private/athlete-private.json` and the exact missing field(s). Edwards must still run (D-14: its only input is the five bpm boundaries already in the public config). **Never substitute a default resting HR** — an invented 60 bpm would silently reshape every Banister value.
4. Sweep `manifest.activities`. For each entry with `available === true` and `channels.hr === true`, read `data/streams/<id>.json`, call `computeActivityTrimp(stream, zones, banisterInputs)`. Wrap each activity in a `try/catch` that `console.warn`s `  ${id}: ${message}; skipping` and continues, incrementing an `activitiesUnreadable` counter.
5. Determine each activity's calendar day from the **activity record's** `start_date_local` (read `data/activities/<id>.json`), normalized with the Z-suffix rule (append `Z` when absent) and reduced to `YYYY-MM-DD`. Do **not** use the stream file — a `CanonicalStream`'s `t` array starts at 0 and carries no wall-clock date. An unreadable activity record warns and skips.
6. Accumulate three per-day maps: Edwards TRIMP, Banister TRIMP, and `{ runs, runsWithHr }` counts. **Every** activity in the manifest contributes to `runs` — including ones with no stream and ones with no HR channel — because D-15 requires the no-HR days be visible, and a day that is absent from the counts is indistinguishable from a rest day.
7. Build the spine from the earliest to the latest activity day (D-16: the underlying series covers the full archive; the *displayed* window is a client concern). Run `computeCtlAtlTsb` once per model. Assemble `days` by zipping the two model series with the per-day counts; `banister` is `null` on every entry when the model is disabled.
8. Round every emitted number to 2 decimals — the archive spans ~5,500 days and unrounded floats would roughly triple the published file for no readable precision. Log the resulting file size.
9. Write `{ schemaVersion: TRAINING_LOAD_SCHEMA_VERSION, generatedAt, note, timeConstants: { ctlDays: CTL_TAU_DAYS, atlDays: ATL_TAU_DAYS }, models, banisterDisabledReason, firstDate, lastDate, totals, days }` to `<statsDir>/training-load.json` via `fileStore.writeJson`, and return it.
10. Log a summary line: days in spine, activities considered, with HR, without HR, unreadable, and whether Banister was produced.

If plan 18-03's `TrainingLoadDocument` needs an additional field to express any of the above (for example a per-day `runsWithoutHr` convenience), add it to `src/analytics/training-load.types.ts` here rather than inventing an untyped shape — but keep the header comment's prohibition on identity fields intact.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `data/private/athlete-private.json` → build step → published JSON | `restingHr` and `sex` enter the Banister computation; only aggregate scalars may leave |
| committed HR streams → published daily series | Per-sample bpm is aggregated away at build time |
| CI runner → published artifact | The private file does not exist in CI, so the published output must be valid without it |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-18-PII-06 | Information Disclosure | `data/stats/training-load.json` | mitigate | Only per-day scalars and run counts are emitted; asserted by `grep -cE '"restingHr"\|"birthDate"\|"sex"' data/stats/training-load.json` returning `0`, and enforced upstream by plan 18-01's `assertNoPrivateArtifacts` build guard |
| T-18-LOAD-03 | Spoofing (fabricated input) | missing `restingHr` | mitigate | Banister is disabled and named rather than run against a substituted default; test case 3 pins this, and the acceptance criteria require inspecting every literal `60` in the source |
| T-18-LOAD-04 | Repudiation (invisible absence) | no-HR activities | mitigate | Every manifest activity increments the day's `runs` even when it has no stream or no HR channel; test case 7 and the live-archive assertion both pin it |
| T-18-DOS-03 | Denial of Service | 1,687 stream file reads | accept | Build-time only, never in the browser (D-20); the step already runs in the same CI job as `compute-best-efforts`, which sweeps the same archive |
| T-18-AVAIL-01 | Denial of Service (pipeline) | missing optional inputs | mitigate | Only the stream manifest throws; every other missing input degrades with a warning, so the nightly `compute-all-stats` chain cannot be turned red by an unfilled config file |
| T-18-SC | Tampering | npm/pip/cargo installs | mitigate | Zero package installs authorized. An executor that concludes an install is necessary must stop and run the Package Legitimacy Gate |
