Create `src/analytics/trimp.ts` — pure, client-safe (no `fs`, no `fetch`, no DOM). Exports:

- `export function zoneForHr(hr: number, zones: readonly AthleteHrZone[]): 1|2|3|4|5` — returns the zone whose `[minBpm, maxBpm]` contains `hr`, treating `maxBpm === null` as open-ended (zone 5). A bpm **below** zone 1's floor returns `1` rather than throwing or being dropped: per D-15 the run still happened, and a warm-up sample below the zone floor is not absence of training. Import the `AthleteHrZone` type from `../dashboard/views/detail-zones.js` (type-only import; that module is already pure and DOM-free).

- `export function edwardsTrimp(t: readonly number[], hr: readonly number[], zones: readonly AthleteHrZone[]): number` — `Σ over consecutive segments of (Δt_minutes × zoneWeight)`, where `Δt_minutes = (t[i+1] - t[i]) / 60` and the zone is evaluated at `hr[i]`. **Never** `duration / sampleCount` — this is Pitfall 2, and `t` is decimated. Skip any segment with a non-positive `Δt` or a non-finite `hr[i]`. Return `0` (never `NaN`, never throw) when the arrays are empty, differ in length, or fail `validateStreamSeries`-style sanity. Add a JSDoc block naming Pitfall 2 and its warning sign (TRIMP that does not scale sensibly with duration).

- `export function banisterTrimp(t, hr, restingHr: number, maxHr: number, sex: 'male' | 'female'): number` — `Σ (Δt_minutes × HRr × a × e^(b·HRr))` with `[a, b] = [0.64, 1.92]` for male and `[0.86, 1.67]` for female, `HRr = clamp((hr[i] - restingHr) / (maxHr - restingHr), 0, 1)`. Returns `0` when `maxHr - restingHr <= 0`. Same per-segment `Δt` discipline and same total/never-throws contract.

- `export interface ActivityTrimp { edwards: number; banister: number | null; sampleCount: number; hrSamplePairs: number; }` and `export function computeActivityTrimp(stream: CanonicalStream, zones, banisterInputs: { restingHr: number; maxHr: number; sex: 'male'|'female' } | null): ActivityTrimp | null` — returns `null` when `stream.hr` is absent or empty (D-15: no HR contributes nothing, and the caller records the absence rather than substituting an estimate). `banister` is `null` when `banisterInputs` is `null`.

Create `src/analytics/trimp.test.ts`. Required cases:
1. **Decimation invariance (Pitfall 2):** two synthetic streams representing the *same* 30 minutes at the *same* constant HR — one sampled every 1 s (1800 samples), one decimated to every 60 s (30 samples). `edwardsTrimp` must return the same value within 1 %. A sample-counting implementation fails this by a factor of ~60.
2. **Non-uniform weighting:** a stream with segments of 60 s in zone 1 and 600 s in zone 5 yields `60/60*1 + 600/60*5 = 51`, asserted exactly. Swapping the two durations yields a different value, asserted.
3. `zoneForHr` boundary behaviour: exactly `minBpm` and exactly `maxBpm` of each zone land in that zone; `maxBpm === null` on zone 5 makes any high value zone 5; a value below zone 1's `minBpm` returns `1`.
4. Banister monotonicity: for the same duration, a higher constant HR yields a strictly larger value; `hr === restingHr` yields ~`0`; `hr` above `maxHr` is clamped and does not exceed the value at exactly `maxHr`.
5. Banister sex coefficients: the male and female coefficients produce different values for identical inputs, and both are finite and positive.
6. Degenerate inputs: empty arrays, mismatched lengths, a single sample, all-zero `Δt`, `maxHr === restingHr` — every one returns `0` and none throw.
7. `computeActivityTrimp` returns `null` for a `CanonicalStream` with no `hr` field, and returns `banister: null` when `banisterInputs` is `null` while `edwards` is still positive (D-14: Edwards must work without any identity input).

Create `src/analytics/training-load.ts` — pure, client-safe. Exports:

- `export const CTL_TAU_DAYS = 42;` and `export const ATL_TAU_DAYS = 7;` (D-16)
- `export function buildDailySpine(firstISO: string, lastISO: string): string[]` — every `YYYY-MM-DD` from first to last inclusive, stepping by `setUTCDate(+1)`, UTC only. Returns `[]` when either input is unparseable or `last < first`. This is the fix for Pitfall 3: **the spine is calendar days, not activity days.**
- `export function decayStep(prev: number, todayLoad: number, tauDays: number): number` — `prev + (todayLoad - prev) * (1 - Math.exp(-1 / tauDays))`. Use the exact exponential form, not the `/tau` linear approximation.
- `export interface DailyLoadPoint { date: string; trimp: number; ctl: number; atl: number; tsb: number; }`
- `export function computeCtlAtlTsb(dailyTrimpByDate: ReadonlyMap<string, number>, firstISO: string, lastISO: string): DailyLoadPoint[]` — walks `buildDailySpine`, and for each day: **captures `tsb = ctl - atl` from the values carried in from the previous day BEFORE applying today's decay step**, then updates `ctl` and `atl` with today's load. Days absent from the map contribute `trimp: 0` and still decay. Add a JSDoc block stating Pitfall 4 explicitly: the emitted `tsb` for date D is derived from D-1's CTL and ATL, and a future edit that moves the capture below the update inverts the metric's meaning.

Create `src/analytics/training-load.types.ts` — the published document contract, mirroring `best-effort.types.ts`'s document conventions:
- `export const TRAINING_LOAD_SCHEMA_VERSION = 1;`

- `export interface TrainingLoadDocument { schemaVersion: number; generatedAt: string; note: string; timeConstants: { ctlDays: number; atlDays: number }; models: { edwards: boolean; banister: boolean }; banisterDisabledReason: string | null; firstDate: string; lastDate: string; totals: { daysInSpine: number; activitiesConsidered: number; activitiesWithHr: number; activitiesWithoutHr: number; activitiesUnreadable: number }; days: DailyLoadEntry[]; }`

Header comment on `training-load.types.ts`, load-bearing: this is a **published public artifact**. Also state 18-UI-SPEC § 11's data-contract expectation: **both** the Edwards and Banister series live in this one document so the model toggle is a pure client-side re-render with no refetch.

Create `src/analytics/training-load.test.ts`. Required cases:
1. **Decay across a gap (Pitfall 3):** a map with a single 100-TRIMP day followed by 60 empty days. Assert the spine has 61 entries, that `ctl` on the last day is strictly less than on the first, that it is greater than `0`, and that it matches `100 * alpha * (1 - alpha_ctl)^60`-style monotone decay by asserting strict day-over-day decrease across the whole tail. An activity-indexed implementation produces a flat line here.
2. **ATL decays faster than CTL:** after the same gap, `atl < ctl` and `atl` is within a small epsilon of `0` by day 60 while `ctl` is not.
3. **TSB day-offset (Pitfall 4):** on the very first day of the spine, `tsb === 0` regardless of that day's load (nothing preceded it). On day 2, `tsb` equals `ctl[0] - atl[0]` exactly. Assert both. An implementation using today's values fails the first assertion whenever day 1 has load.
4. **Spine continuity:** `buildDailySpine('2024-02-27','2024-03-02')` returns exactly `['2024-02-27','2024-02-28','2024-02-29','2024-03-01','2024-03-02']` (leap year). `buildDailySpine('2023-12-30','2024-01-02')` crosses the year boundary correctly. Reversed inputs and malformed inputs return `[]`.
5. **Steady state:** a constant 50-TRIMP-per-day load over 400 days drives `ctl` and `atl` both toward ~`50`, and `tsb` toward ~`0`. Assert with a tolerance of 1.
6. **Time constants:** `decayStep(0, 100, 7)` is strictly greater than `decayStep(0, 100, 42)` (the 7-day constant responds faster).
