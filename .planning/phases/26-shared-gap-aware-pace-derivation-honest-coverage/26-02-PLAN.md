histogram beside it.

Add the D-16 entry point:
`derivePaceWithCoverage(stream: CanonicalStream, options?: { windowSec?: number; pauseRule?: PauseRule; clipAtGaps?: boolean }): PaceDerivationResult`
where `interface PaceDerivationResult { paceSeries: (number|null)[]; coverage: PaceCoverage; windowSec: number }`.
It calls `classifyGaps` once, computes `windowSec` as `options.windowSec ?? adaptiveWindowSec(t, d)`,
calls `derivePaceSeriesGapAware`, and returns all three together. On an invalid stream it returns
`{ paceSeries: [], coverage: <the zeroed PaceCoverage>, windowSec: PACE_WINDOW_FLOOR_SEC }` and
never throws. Document in its doc comment that this is D-16's structural guarantee — no caller may
obtain pace without coverage — and D-17's boundary: the returned series is presentation-only, is
never persisted, and never feeds `computeSplits`.

Add `paceHistogramSamples(t: readonly number[], paceSeries: readonly (number|null)[]): Array<{ paceSecPerKm: number; timeSec: number }>`:
for `i` in `[0, n-2]`, `dt = t[i+1] - t[i]`; skip when `dt <= 0` or `paceSeries[i] === null`
(a null index is already accounted as excluded by `classifyGaps` — it is not a silent drop); else
emit `{ paceSecPerKm: paceSeries[i], timeSec: dt }`. This reproduces `computePaceDistribution`'s
existing Δt weighting exactly so plan 26-04's histogram is weight-identical to today's, and it is
the shared primitive plan 26-09's residual script measures fast mass with.
