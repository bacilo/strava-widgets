<interfaces>
Known local traps, each of which has cost this project a round before:
- Staged builds serve a stale `index.html` and a stale `index.json` from earlier checkpoints. A
  **hard reload** is required after every rebuild or fixture change; pointing the browser at
  `127.0.0.1` alone is not sufficient.
- The viewport for these checks clamps to the 500-941 px band.
- Gestures require a human; a headless agent cannot produce them. There is no jsdom or headless
  browser in this repo, which is exactly why this checkpoint exists.
- A checkpoint row that only compares the page against itself proves nothing. Every row below
  reconciles against an independently-derived value or states a position, per this project's
  own `checkpoint-rows-must-assert-extent` lesson.
- Rows can be unsatisfiable in both directions — vacuous (can never fail) or unpassable (can never
  pass). Task 1 checks both directions for every row before a human is asked to look.

Activities in play:
- `4556693525` — the pinned worked exemplar for the coverage caption (row 1).
- The gap-crossing-split activity selected and verified by plan 26-06 (row 2); its id, flagged km
  and exact legend string are recorded in `26-VALIDATION.md` and in `26-06-SUMMARY.md`.
- `5059204779` — the PACE-07 singleton (rows 3, 4, 5, 6).

Verdict vocabulary, from this project's Phase 20 precedent: PASS, FAIL, BLOCKED (evidence could not
be gathered), NOT EXERCISABLE (the state is unreachable in the current dataset). A row without
sufficient evidence is BLOCKED, never PASS — that rule is non-waivable and holds against any
pressure to record a pass on incomplete evidence.
</interfaces>
