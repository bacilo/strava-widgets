Create the shared gap-aware derivation module's first half: the single-pass segment classifier and
the exact coverage accounting that every later consumer reads from.

Purpose: COV-01's "sums exactly" is only an identity if every second of the stream's span lands in
exactly one named category. Today `computePaceDistribution` silently drops 964 of 4556693525's
3,394 seconds through a `dd <= 0` skip. This plan makes that drop impossible by construction and
pins both the dropped-seconds defect and the absolute-pause-threshold trap as permanent negative
tests.

Output: `src/analytics/pace-derivation.ts` (classification + coverage half) and
`src/analytics/pace-derivation.test.ts`.

From `src/streams/stream.types.ts`:
`CanonicalStream` = `{ schemaVersion: 1; id: string; source: 'fit'|'gpx'|'intervals'; distanceSource: 'native'|'geo'; sampleCount: number; channels: StreamChannels; t: number[]; d: number[]; hr?: number[]; cadence?: number[]; alt?: number[] }`.
`t` is seconds since the first sample, integer, starting at 0. `d` is cumulative metres,
non-decreasing, rounded to 0.1 m. There is **no** `elapsed_time` field (this is why D-06 exists).

From `src/analytics/best-effort-utils.ts`:
`export function validateStreamSeries(t: number[], d: number[]): PlausibilityResult` where
`PlausibilityResult` is `{ ok: true } | { ok: false; reason: string }`. It already rejects length
mismatch, `n < 2`, and non-finite values, and it never throws.

From `src/dashboard/views/detail-zones.ts:61-93` (the located defect, read it in full):
`computePaceDistribution` loops `i` over `[0, t.length - 2]`, computes `dt = t[i+1] - t[i]` and
`dd = d[i+1] - d[i]`, and executes `if (dt <= 0 || dd <= 0) continue;` before bucketing `dt` at
`dt / (dd / 1000)`. That `continue` is the silent drop COV-01 exists to eliminate.

Export these constants with the stated values and a one-line justification comment citing
26-RESEARCH.md's measurement for each:
- `RECORDING_GAP_ABS_THRESHOLD_SEC = 10` (unchanged; PROJECT.md's existing 1,233-activity cohort)
- `PAUSE_GAP_P90_MULTIPLIER = 5` (K=4 is the minimum reaching 0.00% pause on all four measured
  profiles; K=5 ships with a full extra multiple of headroom)

Export these types:
- `type GapKind = 'recording-gap' | 'pause'`
- `interface GapInterval { startSec: number; endSec: number; kind: GapKind }`
- `interface PaceCoverage { spanSec: number; coveredSec: number; recordingGapSec: number; pauseSec: number; gapIntervals: GapInterval[] }`
- `type PauseRule = { kind: 'scale-relative'; multiplier: number } | { kind: 'absolute'; thresholdSec: number }`

Export these functions:
- `quantile(sortedAsc: readonly number[], q: number): number` — R-7 linear interpolation
  (`pos = (len - 1) * q`, interpolate between `floor(pos)` and `ceil(pos)`), matching numpy/D3's
  default. Return `NaN` on an empty array. This is deliberately the SAME quantile implementation
  Phase 28's ceiling will reuse; do not substitute a nearest-rank variant.
- `advanceIntervals(t: readonly number[], d: readonly number[]): number[]` — walk `i` from 1;
  whenever `d[i] > d[i-1]`, push `t[i] - lastAdvanceT` and set `lastAdvanceT = t[i]`, seeded with
  `lastAdvanceT = t[0]`. Return the intervals sorted ascending, ready for `quantile`.
- `classifyGaps(t: readonly number[], d: readonly number[], options?: { pauseRule?: PauseRule }): PaceCoverage`

`classifyGaps` contract:
1. If `validateStreamSeries(t as number[], d as number[])` is not `ok`, return
   `{ spanSec: 0, coveredSec: 0, recordingGapSec: 0, pauseSec: 0, gapIntervals: [] }`. Never throw.
2. `spanSec = t[n-1] - t[0]`.
3. Default `pauseRule` is `{ kind: 'scale-relative', multiplier: PAUSE_GAP_P90_MULTIPLIER }`.
   Resolve it to a single `pauseThresholdSec`: for `scale-relative` it is
   `multiplier * quantile(advanceIntervals(t, d), 0.9)`; for `absolute` it is `thresholdSec`.
   If the advance-interval array is empty (a stream that never advances), treat the threshold as
   `Infinity` so nothing is classified as pause rather than everything.
4. Precompute maximal distance-flat runs: a maximal span of consecutive indices `i..j` such that
   `d[k+1] - d[k] <= 0` for every `k` in `[i, j-1]`. That run's duration is `t[j] - t[i]`.
5. Classify each segment `[t[i], t[i+1]]` for `i` in `[0, n-2]` by strict priority — never as two
   independent overlapping checks (26-RESEARCH.md Pitfall 3: independent checks double-count and
   break the exact-sum identity):
   - `dt = t[i+1] - t[i] > RECORDING_GAP_ABS_THRESHOLD_SEC` → `recording-gap`
   - else if the segment belongs to a flat run whose duration exceeds `pauseThresholdSec` → `pause`
   - else → `covered`
6. Accumulate `dt` into `recordingGapSec` / `pauseSec` / `coveredSec` accordingly, and merge
   adjacent same-kind non-covered segments into `gapIntervals` entries with real `startSec`/`endSec`
   times (not indices), ordered ascending by `startSec`.
7. The three category sums must equal `spanSec` by construction — every segment is counted exactly
   once and no segment is skipped.

Every function in this file must be total. Use `null`/neutral returns, never `?? 0` or `|| 0`
coercions that would turn "insufficient data" into a plausible-looking zero.
