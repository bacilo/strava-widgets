<agenda_design>
Read this before writing Task 1's table rows — it is why this plan has the shape it does.

**What 19-09 did.** Four rows, one `<resume-signal>` asking for "approved" or a per-row failure description, and one verdict returned covering all four. The record is honest about it: every row's Re-verification cell says the verdict "was given as a single overall verdict covering all four re-verification rows together, not as a per-row or per-sub-check report." That is a *recording* failure enabled by an *agenda* design — nothing in the plan made a blanket answer structurally insufficient.

**What changes here, concretely:**

1. **Per-row verdict tokens.** Each of rows 14-19 must carry a literal `VERDICT: PASS` or `VERDICT: FAIL` in its own Observation cell. Six tokens, six rows. Task 2's gate counts them and fails if any row lacks one.
2. **Row-specific content anchors.** A verdict token alone can still be pasted six times, so each row additionally requires its own named artifacts to appear in its own cell — a middle option's label for a segmented row, "rest day" for the calendar row, both route names for the nav row. One blanket paste cannot satisfy six different anchor sets. The gate asserts each anchor per row.
3. **Both themes, per row, explicitly.** Every row involving a rendered colour or ring requires the words `light` and `dark` in its own observation. Light is the tighter case for the ring (3.40:1 versus dark's 6.02:1); dark is the tighter case for the segmented notches (`#242444` on `#1a1a2e`). Neither theme covers for the other.
4. **Objective probes gate the rows that depend on them.** 19-09's Step 0 probe was the one genuinely solid piece of evidence in that session, because it was machine-read rather than judged. The three probes here follow that pattern, and a failing probe stops the checkpoint rather than being noted in passing.
5. **A no-regression row of its own.** The three fixes touch a global stacking ladder, a shared option class and a global disabled rule. Row 19 exists so the controls that must look *unchanged* get their own verdict instead of an assumption.

**What deliberately does not change:** the developer is not asked for more words. Each row's required content is small and specific — one control's shape, one ring's visibility, one nav's paint order. The previous checkpoint asked for a broad sweep and got a broad answer.
</agenda_design>

- **Middle options of segmented controls were rounded (CR-02).** The `button` baseline sets `border-radius: 4px` on every button in the dashboard. `.segmented__option` never cancelled it, and only the first and last options overrode it — so every *middle* option of a 3-or-more-option group got 4px on all four corners instead of square joints. Since plan 19-04 removed the container's `overflow: hidden`, nothing clipped them square any more, so the page background showed through a notch at every internal join, and an active middle option rendered as a fully-rounded accent pill inside the group. Three shipped controls are affected, all on Trends: the 5-tab bar, the Weekly/Monthly/Yearly group, and the 3mo/12mo/All group. The detail view's two-option toggle — the only segmented control the previous checkpoint's row 12 named — was never affected, which is why this shipped. `.segmented__option` now declares `border-radius: 0`, and only the end children re-round their outer corners.
- **The focus ring was being dimmed on calendar rest days (CR-03).** Rest days are real, focusable buttons that carry `aria-disabled` rather than the `disabled` attribute, deliberately, so they stay in the Tab order. The disabled treatment applies `opacity: 0.6` to them — and `opacity` dims an element's `box-shadow` along with everything else, including the focus ring. Measured, the ring dropped to about 2.19:1 in light and 2.93:1 in dark, against the 3:1 non-text contrast floor this phase's own comment says the design clears. The element now returns to full opacity while it is focus-visible. It still reads as disabled at rest and while focused: the muted label colour, the default cursor and the hover exclusion are all unchanged. Only the dimming is dropped, and only while focused.
