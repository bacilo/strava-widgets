### WR-01: Tie-break depends on directory order and disagrees with reconcile's "earlier wins"

**Files modified:** `src/exports/near-match.ts`, `src/exports/near-match.test.ts`
**Commit:** cc102646
**Status:** fixed: requires human verification (logic change)
**Applied fix:** When two candidates are equally close, `findNearMatch` now picks the one with the earlier epoch, which is reconcile's rule. It no longer keeps whichever candidate came first in the list. The doc comment states this. I renamed the old row to "earlier epoch on a tie". I also added a row that lists the later candidate first (`late` at E+10, then `early` at E-10) and expects `early`.
**Mutation check:** I replaced the tie clause with `false`, which restores the first-in-list rule. Only the new row failed (1 failed, 25 passed). The old tie row kept passing, which confirms the reviewer's point that it could not tell the two rules apart.

### WR-02: reconcile.ts keeps its own copy of the window comparison

**Files modified:** `src/exports/reconcile.ts`, `src/exports/reconcile.test.ts`, `src/exports/near-match.test.ts`
**Commit:** 9e15cbb0
**Status:** fixed: requires human verification (logic change)
**Applied fix:** I used the first option. reconcile keeps its `lowerBound` lookup, so it stays fast. It now passes the two neighbouring archive epochs to `findNearMatch(run.startEpoch, neighbours, tolerance)`. The window, the signed `deltaS` and the tie-break therefore all come from near-match.ts. I added `reconcile.ts` to the guard's `needsCall` list, with a row that removes the call. I also added a behavioural row in reconcile.test.ts: near at -120, missing at -121, and a tie where the archive is listed later-first resolves to `early`.
**Behaviour note:** The old code treated a sub-second offset (0 < |d| < 1) as near. `findNearMatch` does not. Epochs come from `Math.floor(... / 1000)` and are always integers, so this cannot happen with real data.
**Mutation checks:**
- Passing `tolerance - 1` to the call failed 2 reconcile rows: the existing +120 row and the new -120 row.
- Renaming the call to `other(` failed the structural guard row.
