Project checkpoint hazards, each of which has cost this project a round before:

- `build-widgets` skips work based on mtime and silently no-ops on a locally-edited `dist/` file.
  Verify the SERVED digest, computed from FETCHED bytes — never the build log.
- Serving from `127.0.0.1` alone is NOT sufficient. Checkpoints here have served a stale `index.html`
  and a stale `index.json` from a staged build. Hard-reload after every fixture edit.
- The browser viewport clamps to 500..941. Do not draft a row requiring a width outside that.
- Gestures need a human. Do not draft a row an agent could claim to have performed.
- A row must assert reachable EXTENT against an independently derived value. Two code paths sharing
  an implementation agreeing with each other is not evidence (Phase 23 CR-01; Phase 26's Round 3
  R3-1 is the shape that worked — a captured tick array bracketing a hand-derived series maximum).
- A row that cannot fail is as broken as one that cannot pass. Check both directions before running
  it. Phase 24's R26 went vacuous mid-round because its discriminator was cleared by an earlier
  mandatory step.
- Verdict vocabulary is four-state, per Phase 20: PASS, FAIL, BLOCKED (evidence not supplied or
  supplied at the wrong condition), NOT EXERCISABLE (the state does not exist in the current data).
  BLOCKED and NOT EXERCISABLE are not failures and are not passes.
