<objective>
Close CR-01. Apply the personal ceiling to every effort that is not already demoted by an absolute
guard, including owner-excluded efforts. Excluded efforts still stay out of the ceiling's derivation
population. Replace the pinned-fixture test's missing-file dodge with a test that uses the real
committed exclusion entry for 4556693525, and show that test failing first.

Purpose: 28-VERIFICATION.md gaps 1 and 2. Thirteen shipped efforts are over their ceiling but carry
`demotion: null`, and the pinned D-04 fixture is one of them. The `demotion: null` contract in
`best-effort.types.ts` ("no guard rejected this") is currently false for those 13.

Representation decision, stated once here and referenced by every later plan:

- An effort that is both owner-excluded and over the ceiling carries `excludedFromRecords: true`
  (the owner's intent) and `demotion: { guard: 'ceiling', reason }` (the machine's judgment),
  following D-10's two separate fields.
- It gets one `rejected` row.
- Its `wasPRAtTheTime` stays false, and it stays absent from `rankings` and from `byDistance`.
- The detail view's existing `prFlagBadgeSpecs` emits two separate badges, in the order
  `Demoted — {ceiling reason}` then `Excluded — {owner reason}`, each with its own
  `aria-describedby`. The badge rendering needs no code change for this; plan 28-13 pins it with a test.
- Precedence rule: if an absolute guard already demoted the effort, that demotion stands, and the
  ceiling is not evaluated for it. This matches the non-excluded path, where absolute-demoted efforts
  never enter `byDistance`.

Output: the fixed compute step, four new regression tests, and corrected stale comments (IN-01 in
these files; WR-06 comment half). This plan does not regenerate `data/stats/`; plan 28-14 does that.
