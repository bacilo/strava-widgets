<objective>
Build the independent verifier: a script that opens the SHIPPED documents, counts demoted efforts
with its own arithmetic, reports the impossible-sample cohort against a live denominator, and refuses
to import any of the code that produced the numbers it is checking.

Purpose: ROADMAP criterion 5 requires the diff's record count to reconcile with an independently
derived count, and criterion 3 requires the guard's effect to be reported across the full cohort
rather than the pinned fixture alone. Two numbers produced by the same code agreeing proves only that
the code is deterministic — which is criterion 1's job. This is the same discipline Phase 27's
`compute-pace-quality-recount.mjs` established under its D-03.

Output: `scripts/compute-pr-ceiling-recount.mjs`, its test, and an npm script. This script writes no
files, ever.
</objective>

<interfaces>
The only two read targets, both shipped and both opened with `readFileSync` plus `JSON.parse`:

- `data/stats/best-efforts.json` — `activities[id].efforts[j]` carries `distance`, `durationSec`,
  `wasPRAtTheTime`, `excludedFromRecords` and
  `demotion: { guard: 'world-record' | 'max-speed' | 'ceiling'; reason: string } | null`;
  `rankings[distance]` carries the top-10 rows with `activityId` and `durationSec`;
  `rejected[]` carries `{ activityId, distance, reason }`; `totals` carries `effortsDemoted` and
  `effortsRejected`; `ceilings[distance]` carries the derivation record.
- `data/dashboard/index.json` — per-row `quality.impossibleSamples.count`, an integer, shipped by
  Phase 27. `activities` is the row array; the archive denominator is its length, recomputed at run
  time.

Distance keys must be obtained from the documents themselves — `Object.keys(doc.rankings).sort()` —
not imported from `best-effort.types.js`, so the recount shares no vocabulary module with the code
it checks.

FORBIDDEN imports, deliberately, per D-15: `dist/analytics/best-effort-ceiling.js`,
`dist/analytics/compute-best-efforts.js`, `dist/analytics/best-effort-utils.js`,
`dist/analytics/best-effort.types.js`, and their `src/` equivalents. A verifier that pulls in the
classifier that produced the numbers it is checking agrees with itself by construction.

The precedent to copy near-verbatim, `scripts/compute-pace-quality-recount.mjs` (283 lines):
- its header comment stating the forbidden-import rule and the single read target;
- `readShippedIndex(indexPath)` returning `{ ok: false, reason }` or `{ ok: true, doc }` — copy this
  result-object shape rather than throwing;
- `recountComposite(doc)` recomputing its own verdict per row from raw fields and collecting NAMED
  disagreement lists rather than asserting a single boolean;
- `evaluateReport(report, expected)` returning `{ pass, problems }` with no `process.exit` inside it;
- `parseExpectFlag(argv)` implementing the `--expect <n>` pattern, which exists so a count can be
  pinned by the operator without being hardcoded in the script;
- `main()` behind the self-execution guard, printing a labelled block and setting
  `process.exitCode = 1` on failure.

Two populations that must never be conflated, stated explicitly in 28-RESEARCH.md:
PR-05's cohort is "activities carrying at least one impossible SAMPLE anywhere in their stream" — a
stream-level, per-sample-pair check against the 100m world-record floor of 10.44 m/s. The demoted
population is "efforts at one of the seven target distances rejected by a guard" — an effort-level
check. A sample can be impossible mid-run without ever landing inside a swept target window. Report
both numbers and their overlap; do not treat them as interchangeable.

The pinned regression activity (D-04): `4556693525`, whose 400m effort is 45.2s / 8.85 m/s. The
44.0s / 9.09 m/s figure in PR-05 and in the original ROADMAP criterion 3 matched no record and was
corrected on 2026-09-10.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| shipped JSON on disk → the recount | Both read targets are machine-written but locally editable and may be absent, truncated, or shaped differently than expected after a schema change. |
| operator-supplied `--expect` values → the verdict | An integer from the command line decides whether the script passes. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-28-08-A | Denial of Service | `readShippedJson` on a missing or truncated document | mitigate | Returns `{ ok: false, reason }` naming the path and the underlying message; `main()` reports and sets `process.exitCode = 1` rather than throwing, copying the analog verbatim. |
| T-28-08-B | Tampering | the verifier being made to agree with the classifier | mitigate | The zero-import guard is a test that strips comments before searching and carries a self-test proving the stripper works, so neither a new import nor a header rewording can quietly defeat it. |
