floor — by measuring the live archive, and record both with the evidence that justifies them in a
regenerable, provably idempotent markdown artifact.

production code hard-codes a number, so plan 28-03 implements a constant with a citation rather
than inventing one.

    2. `nearestRankPercentile(sortedAscending, fraction)` is deterministic and interpolation-free:
       the index is `Math.ceil(fraction * n) - 1` clamped to the range 0 to n-1, returning `null`
       for `n === 0`. Because there is no interpolation the value is always an observed data point
       and cannot move under a floating-point tie-break. Document why: PR-01 requires the derived
       value be reproducible byte-for-byte across runs.

    3. `describeDistribution(population)` returns `{ n, p50, p90, p99, p995, max, maxOverP90 }`, each
       via `nearestRankPercentile` over an ascending copy sorted by `speedMps` with `activityId` as
       the tie-break so the sort is total.

    4. `partitionMechanismClean(populations)` splits the seven distances into `mechanismClean` and
       `mechanismVulnerable` by a criterion stated independently of any ratio being measured: a
       distance is mechanism-clean when `TARGET_METERS[key] >= 5000`. The justification must appear
       verbatim as a header comment and again in the artifact — the corruption mechanism is a single
       aliased distance advance landing inside the swept window; Phase 26 measured per-activity
       distance-advance intervals with medians of 2s, 16s, 24s and 60s, and at this archive's roughly
       3.4 m/s bulk pace a 60s advance displaces about 200 m, so a target of at least 5,000 m bounds
       single-jump inflation below about 4% while a 400 m target admits up to 50%. The partition is
       therefore fixed by target length, never by observed spread.

    5. `deriveCeilingMultiplier(populations)` returns `{ k, argmaxDistance, perDistance }` where `k`
       is the maximum of `max / p90` over the mechanism-clean distances that also clear the minimum
       population floor, rounded UP to two decimals with `Math.ceil(x * 100) / 100`. Rounding up is
       direction-safe: it can only admit more efforts, never demote more. `perDistance` carries every
       distance's `max`, `p90` and ratio so the argmax is auditable. This function must NOT accept,
       read, or be influenced by any demotion count — the anti-quota guarantee is structural, not a
       promise.

    6. `deriveMinimumPopulation(minPointsAboveBoundary = 10)` returns the smallest integer `n` such
       that `n - Math.ceil(0.90 * n) >= minPointsAboveBoundary`, together with the arithmetic that
       produced it. The mechanism, stated in the header comment and the artifact: the p90 boundary is
       a bulk descriptor only when enough observations lie strictly above it that no single artifact
       can move where it falls; ten is the smallest count at which one contaminated point is a
       bounded minority of the points above the boundary. Report the computed `n`; do not hard-code
       it.

    7. `applyCeiling(populations, k, minPopulation)` returns per distance
       `{ ceilingMps, eligible, n, demotedCount, demotedTop10Count }`, where `ceilingMps` is `null`
       when `n < minPopulation` (D-02's fail-open) and otherwise `Math.ceil(k * p90 * 1e4) / 1e4`,
       and an effort is demoted when `speedMps > ceilingMps` STRICTLY. Strict comparison plus upward
       rounding is what keeps the argmax distance's own maximum admitted.

    8. `compareRiegelGate(populations)` is a REPORTED FINDING only, per D-01's "offered as evidence,
       not a shortlist". Using `riegelPredict` and `fitRiegelExponent` from `dist/analytics/riegel.js`,
       project a ceiling down from the fastest 10k effort and report, per distance, how many efforts a
       Riegel gate would demote that `applyCeiling` does not, and vice versa. Record that 400m is
       outside Riegel's calibrated range and report no Riegel number for it. This function's output
       feeds the artifact's evidence section and must NOT feed `deriveCeilingMultiplier`.
