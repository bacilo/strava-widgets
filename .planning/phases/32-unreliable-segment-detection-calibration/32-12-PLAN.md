<objective>
Replace the two structurally vacuous import-time side-effect guards with a mechanism that can
actually observe the call they claim to forbid, and prove it by watching it catch a module that
genuinely reads at import time.

Purpose: this is GAP 2. Both guards do `vi.spyOn(fs, 'readFileSync')` on the default `fs` namespace
object and then dynamic-import a script that consumes `fs` through a NAMED import. Node binds
builtin named exports when the namespace is created, so the property replacement comes too late and
the spy never fires. The verifier proved this with a control probe: a module that genuinely read a
file at import time, behind the identical spy-plus-cache-bust pattern, read the file while the spy
recorded zero calls. `expect(spy).not.toHaveBeenCalled()` cannot fail under any script behaviour.

Mechanism chosen: `vi.mock('fs', factory)` with an `importActual` passthrough that records calls.
Justified because (a) it was measured during planning to intercept BOTH the named-import and the
default-import idiom, and to import both real scripts cleanly with zero recorded calls, so it is
falsifiable AND non-vacuous; (b) it requires NO change to either production script, which keeps the
recount's D-15 zero-import guarantee and 32-CALIBRATION.md's byte-identical regeneration untouched;
(c) unlike switching the scripts to a default-import idiom, it catches both idioms, so a future edit
back to named imports cannot silently re-open this hole.

Output: one new guard file covering both scripts and both idioms, two committed control probes, and
the two vacuous blocks deleted.
</objective>
