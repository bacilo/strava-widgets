<objective>
Close Finding 10 (the root cause of R11 and R16) and Finding 1 (the root cause of R8), and add the
regression tests that would have caught both under this repository's node-environment Vitest setup.

Finding 10: `buildZoomPluginOptions()` in `chart-zoom.ts` returns `onZoomComplete` and
`onPanComplete` as **top-level siblings** of the `zoom` and `pan` option objects
(`chart-zoom.ts:167-168`). `chartjs-plugin-zoom@2.2.0` reads them from **inside** those objects, at
`state.options.zoom.onZoomComplete` (`node_modules/chartjs-plugin-zoom/dist/chartjs-plugin-zoom.esm.js`
lines 388, 616, 630, 649, 665, 674, 677, 767) and `state.options.pan.onPanComplete` (line 800). The
plugin therefore never sees either callback and `settle()` never runs on any gesture — so a real
⌘+wheel moved the rendered ticks to `11 Aug 2011` … `13 Aug 2026` while the canvas `aria-label`
stayed `Weekly distance chart, Aug 2025 to Aug 2026` and Reset never appeared, and a real +576px
drag moved the ticks to `22 Nov 2024` … `22 Nov 2025` with the same frozen label. Because `settle()`
is also the only thing that propagates a range to a sibling `ZoomMember`, this is likewise why D-02
lockstep holds on the button path and breaks on the gesture path (Finding 4, superseded).

Finding 1: the `+`/`−` handlers call `chart.zoom(ZOOM_FACTOR)` with `ZOOM_FACTOR = 1.5`, but the
plugin's `linearZoomDelta` computes `newRange = range * (zoom - 1)` and **removes** that much, so
1.5 halves the window instead of dividing it by 1.5. The `←`/`→` handlers hand a pixel delta to
`chart.pan()`, whose `panNumericalScale` re-derives the delta through `scale.getPixelForValue` /
`scale.getValueForPixel` rather than through the plot width the handler measured — Round 1 observed
`Apr 2025 to Apr 2026` (a 4-month step, ≈33% of span) against the designed `May 2025 to May 2026`
(3 months, exactly D-12's 25%). The pure module's arithmetic is correct and unit-tested; the runtime
bypasses it by delegating to the plugin, which is exactly why the suite stayed green while shipped
behaviour differed.

one file.

Output: two new pure range functions and one pure option-shape builder in `trends-zoom-logic.ts`,
their tests, and a `chart-zoom.ts` that delegates to all three.

    `zoomStepRange(current: ZoomRange, full: ZoomRange, minRangeMs: number, direction: 'in' | 'out'): ZoomRange`
    — centre-preserving proportional zoom. Compute `span = current.max - current.min` and
    `centre = (current.min + current.max) / 2`. Target span is `span / ZOOM_FACTOR` for `'in'` and
    `span * ZOOM_FACTOR` for `'out'`, then clamped into `[minRangeMs, full.max - full.min]`. Lay the
    target span symmetrically around `centre`, then translate (never re-scale) the result back inside
    `full`: if the new max exceeds `full.max`, shift both bounds left by the overshoot; if the new min
    then falls below `full.min`, shift both bounds right by the undershoot; finally hard-clamp each
    bound to `full`. Guard clause first: if `current.min`, `current.max`, `full.min`, `full.max` or
    `minRangeMs` is non-finite, or `current.max <= current.min`, return `current` unchanged.

    `panStepRange(current: ZoomRange, full: ZoomRange, direction: 'earlier' | 'later'): ZoomRange`
    — span-preserving proportional pan. Compute `span = current.max - current.min` and
    `delta = PAN_FRACTION * span`, signed negative for `'earlier'` and positive for `'later'`. Add the
    signed delta to both bounds, then translate the pair back inside `full` the same way
    `zoomStepRange` does (shift, never shrink), so the span is preserved exactly whenever
    `span <= full.max - full.min`. Same non-finite / inverted-range guard, returning `current`.
