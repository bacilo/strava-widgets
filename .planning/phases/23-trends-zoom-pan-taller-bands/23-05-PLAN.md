<objective>
Wire `chart-zoom.ts` into the three zoomable mount functions, and give each zoomable tab its own
zoom-range slot in the Trends view closure so the range survives a tab switch and resets on a full
remount.

Purpose: this is where TRN-01 and TRN-02 actually become true on screen, and where TRN-04's state
round-trip is built. The destroy-and-rebuild lifecycle 18-UI-SPEC § 7 locked is not worked around
here - it is worked *within*: the range is saved out of the live chart on every settle and passed
back in at construction, exactly the way `volumeGranularity` and `loadWindow` already are.

Output: three wired mount functions in `trends-charts.ts`, three zoom-range slots in `trends.ts`,
and an `unmount()` that clears them.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Chart lifecycle (destroy and rebuild) | State is carried across a destroy in the view closure and re-applied at construction |
| Lazy chunk boundary | `trends-charts.ts` gains a static import of `chart-zoom.ts`, which statically imports the plugin and Hammer |
| In-memory zoom state | Written only by the controller's settle, read only at mount |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-23-CANVAS | Denial of Service (broken view) | `activeChartHandle` / destroy-and-rebuild with a live plugin | mitigate | The plugin is per-instance, never on the global registry (asserted against `Chart.register` in Task 1), and `chart.destroy()` fires the plugin's `stop` hook, removing its listeners and destroying its Hammer manager. `ChartHandle.destroy()` keeps its `destroyed` idempotence guard and now also destroys the controller. The residual risk - a stranded or duplicated canvas under rapid tab cycling - is unobservable to this repo's DOM-less tests and is discharged by `23-VALIDATION.md`'s TRN-04 discriminator row in plan 23-07. |
| T-23-LAZY | Denial of Service (page weight) | `trends.ts` static import graph | mitigate | The plugin is imported only from `chart-zoom.ts`, which is imported only from `trends-charts.ts`, which `trends.ts` reaches solely via `await import`. Plan 23-07 Task 1 asserts the built chunk graph rather than trusting import placement. |
| T-23-V5 | Tampering | zoom state | accept | State lives in the view closure only. D-24: no `localStorage`, no `sessionStorage`, no URL parameter - asserted in Task 3. |
| T-23-SC | Tampering | npm dependencies | transfer | Installed and audited in plan 23-01. |

No authentication, session, access-control or cryptography surface.
