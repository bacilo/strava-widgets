<objective>
Build the independent recount Criterion 4 requires: a standalone script that opens the shipped
`data/dashboard/index.json` off disk and counts severe-tier activities with its own arithmetic,
importing nothing from the module that wrote those fields.

Purpose: D-03 exists because a verifier that imports the classifier agrees with itself by
construction. This project's own history has three shipped defects behind a green gate, and its
checkpoint rule is that two code paths sharing an implementation agreeing with each other is
not evidence. The recount's claim is deliberately narrow and honest — "what shipped matches
what was reported" — and it catches the real regression: a compute step that silently stopped
emitting a field.

Output: `scripts/compute-pace-quality-recount.mjs`, its npm script, and a demonstrated-failing
proof that it can disagree.
</objective>

    Create `scripts/compute-pace-quality-recount.mjs` and add
    `"compute-pace-quality-recount": "node scripts/compute-pace-quality-recount.mjs"` to
    `package.json` scripts — with NO `npm run build &&` prefix, deliberately.

    The script reads `data/dashboard/index.json` with `readFileSync` + `JSON.parse` and nothing
    else. It imports `fs`, `path` and `url` only. Its header must state, in its own words: this

    cheaper form. Instead recount from the three tier strings: an activity counts toward the
    composite when at least one of `quality.decimation.tier`, `quality.gapProfile.tier`,
    `quality.impossibleSamples.tier` is exactly the string `'severe'`. Then, SEPARATELY, compare
    that count against `row.quality.anySevere` and against `totals.qualityAnySevere`, and report
    any disagreement as a finding with the offending ids. Three numbers that should agree, one
    of which was derived without the classifier — that is the whole design.

    Report to stdout, and exit non-zero on any of these:
      - a row missing `quality`, or missing any of the five named sub-objects (name the ids);
      - a tier string outside the closed set `none` / `minor` / `severe` / `not-computable`;
      - the recomputed composite disagreeing with `totals.qualityAnySevere`;
      - the recomputed composite disagreeing with the per-row `anySevere` flags;
      - `schemaVersion !== 1`.
    Print, in the success path: both denominators (total rows; rows whose
    `quality.notComputableReason` is null), the recomputed composite against each, the
    per-signal severe counts, and the not-computable count.

    Add a `--expect <n>` flag that additionally exits non-zero when the recomputed composite
    does not equal `n`. This is how CI and plan 27-10's checkpoint pin the number against
    `27-CALIBRATION.md` without the script reading that report (reading the report would make
    it agree with the thing it is checking).

    Keep `main()` behind the self-execution guard and export the pure counting function so the
    test can drive it on a hand-built document.

  <action>
    Create `scripts/compute-pace-quality-recount.test.mjs` (vitest). It imports the script's
    pure counting function and must not run `main()` or read the real index — assert that
    importing the module performs no file read by driving every case from hand-built documents.

    Cases, each asserting the recount's verdict rather than its internals:
      - A document where three distinct rows are severe on three different signals → composite 3.
      - A document where one row is severe on all three signals → composite 1, not 3. The union
        is a set of activities, not a sum of flags; this is the case a naive marginal-sum
        implementation gets wrong.
      - A row with all three tiers `'not-computable'` → not counted in the composite, and
        counted in the not-computable total.
      - **The mutation case (the demonstrated-failing half).** Take a valid document, then:
        (a) flip one row's `quality.decimation.tier` from `'severe'` to `'none'` while leaving
        `quality.anySevere` at `true` → the recount reports a disagreement naming that row id
        and the run fails. This is the exact regression D-03 exists to catch: the classifier's
        summary flag surviving while the field it summarizes silently stopped being emitted.
        (b) delete `quality` entirely from one row → the recount fails naming that row id.
        (c) set one tier to the string `'critical'` → the recount fails on the closed-set check.
      - The `--expect` predicate: correct value passes, off-by-one fails.

    Every mutation case must assert BOTH directions on the same document: the unmutated copy
    passes and the mutated copy fails. A test that only shows the failure does not prove the
    check discriminates; a test that only shows the pass does not prove it can fail.
  </action>
  <verify>
    <automated>npx vitest run scripts/compute-pace-quality-recount.test.mjs</automated>
  </verify>

    - Importing the module in the test triggers no read of `data/dashboard/index.json`,
