<objective>
Add one additive, numeric, detector-derived field, `contaminatedMetres`, to every activity in the
best-efforts document. Plan 37-04 sorts the queue by this figure and plan 37-05 recounts it.

Purpose: CUR-06 orders the queue "by contaminated metres", and no numeric figure for it exists today. The
reason string is length-bounded with "+N more", so it cannot be summed (CONTEXT finding 1). Only
`computeActivityEfforts` holds the detector's `UnreliableSegment[]` and the per-distance `intersecting`
list, so the figure is produced there, once per activity, de-duplicated by segment index pair (D-07).

Output: the type field, the compute change, the fail-closed client parse, and the test fixtures `tsc`
flags. This plan widens the schema: after it merges, `data/stats/` must be regenerated on the primary
checkout before the post-merge test gate (see `<verification>`).
</objective>
