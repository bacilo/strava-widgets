Locus, confirmed from the code (re-read it before editing rather than taking this on trust):
`findCreepStretches` in `src/analytics/pause-classification.ts`. Its merge branch handles the case
where the candidate union's aggregate would exceed `maxSpeedMps` by pushing the new window as its
own stretch — `mergedStretches.push({ startIdx: i, endIdx: j })` inside the `else` of the
`candidateMetres / candidateSeconds <= maxSpeedMps` check, reached when `i <= last.endIdx`, i.e.
precisely when the new window OVERLAPS the previous stretch. That is the double count. Plan
34-06's earlier fix addressed unions that exceed the bound; it did not address overlap, and its
resolution created this.

The two implementations encode different rules, which is the root cause D-22 settles:
`localCreepWindows` (the scan) unions qualifying windows by index overlap and never re-checks the
union's speed; `findCreepStretches` refuses to merge when the union would exceed the bound. On this
activity the union runs at about 0.64 m/s against the 0.5 m/s bound, so the two rules genuinely
disagree — a semantics decision, not a typo.

This is the class of defect the project's "guards must assert against an independent value" lesson
predicts: every in-repo test agreed with itself, and only the independent scan disagreed.
</defect>

<semantics>
D-22, restated here as the rule to implement (34-CONTEXT.md D-22 is the arbiter):
- Qualifying window: unchanged — a window of at least `minSec` inside one covered run whose own
  `metres / seconds <= maxSpeedMps`.
- OVERLAPPING (sharing at least one sample index, including sharing only the boundary sample) or
  CONTAINED windows merge into one stretch spanning `[min start index, max end index]`.
- DISJOINT windows (sharing no sample index) stay separate, however close in time. Adjacency alone
  never merges.
- The reported stretch carries the union's own `seconds` and `metres`.
- Every constituent window is within the bound. The union's own aggregate speed MAY exceed it, and
  is disclosed rather than asserted. Plan 34-06's stronger claim is retired here, in the docblock,
  in the test, and in STOP-02 / ROADMAP criterion 4 (both already amended 2026-09-23).
- Covered runs still bound everything: a stretch never crosses a gap, a pause or an unreliable
  segment, because qualifying windows are found within a single `CoveredRun`.
</semantics>
