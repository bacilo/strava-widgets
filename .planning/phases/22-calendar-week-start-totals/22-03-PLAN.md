<objective>
Render the week totals and make the Calendar view honour a week start it reads from storage. This is
the DOM half of CAL-02 and the read half of CAL-01.

Purpose: plans 22-01 and 22-02 produced a week-start-aware derivation and a place to put the eighth
column. Nothing is visible yet. This plan makes the grid render Monday-first by default with a total
cell at the end of every week row. It deliberately does NOT add the toggle control — that is plan
22-04 — so the render restructure can be reviewed and gated on its own.

Output: `calendar.ts` with three new exported pure helpers, a `buildWeekTotalCell` builder, a
`renderGrid` function that replaces the flat cell loop, and `calendar.test.ts` pinning the helpers to
values read from the live archive.

**Explicitly NOT in scope.** No `.segmented` control, no click handler, no `writeWeekStart` call —
all of that is plan 22-04. No new CSS: plan 22-02 already shipped `.calendar-grid`'s eighth track and
the `.calendar-week-total` rules. No ARIA grid/row/cell roles on `.calendar-grid` (D-11 rejects
retrofitting them; the grid is a plain CSS grid of buttons with no roles today, and adding them risks
regressing the day cells' announcements for more than CAL-02 asks).
</objective>

<rounding_is_load_bearing>
Plan 22-05's blocking checkpoint asks the developer to read ten week-total time values back from the
browser against tables computed in `22-RESEARCH.md` / `22-VALIDATION.md`. Those tables were produced
with **round-to-nearest-minute**. Truncating instead would make five of the ten rows disagree by one
minute and the checkpoint would record a false FAIL against correct code.

Verified this session by summing `movingTimeSec` from `data/dashboard/index.json` for October 2025:

| Week row | Exact seconds | Round-to-nearest (correct) | Truncate (wrong) |
|----------|---------------|-----------------------------|-------------------|
| Sunday 1–4 / Monday 1–5 | 20500 | **5h 42m** | 5h 41m |
| Sunday 5–11 / Monday 6–12 | 28378 | **7h 53m** | 7h 52m |
| Sunday 12–18 | 19594 | **5h 27m** | 5h 26m |
| Sunday 19–25 | 36831 | **10h 14m** | 10h 13m |
| Sunday 26–31 / Monday 27–31 | 19911 | **5h 32m** | 5h 31m |
| Monday 13–19 | 28691 | **7h 58m** | 7h 58m |
| Monday 20–26 | 27734 | **7h 42m** | 7h 42m |

`formatWeekDuration` must be pinned to these seconds-to-string pairs by unit test, so a later
refactor cannot silently break the checkpoint's read-back.
</rounding_is_load_bearing>
