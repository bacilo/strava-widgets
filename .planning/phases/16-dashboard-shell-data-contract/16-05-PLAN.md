<objective>
Build the two data-access clients the whole dashboard runs on: one that fetches the compact index once and caches it, and one that fetches an individual activity's detail files only when that activity is opened.

Purpose: DASH-02's second half and the mechanical core of the D-07 proving slice. These two modules are where the lazy contract either holds or silently breaks, and they are the only dashboard code that constructs a URL from a route param — so they are also where the id-validation chokepoint gets enforced.
Output: `src/dashboard/data/index-client.ts` and `detail-client.ts` with unit tests that mock `fetch` and assert call counts.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| route param → fetch URL | `:id` from the address-bar-editable hash is interpolated into a same-origin static path |
| network response → application state | Published JSON is parsed and handed to renderers without further validation |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-16-DC-01 | Tampering | `loadDetail` URL construction in `src/dashboard/data/detail-client.ts` | mitigate | `isValidActivityId` (`/^\d{1,20}$/`) is called as the first statement, before any interpolation; a non-matching id throws `InvalidActivityIdError` with zero network calls, asserted by tests on `calls.length === 0`. Prevents both confusing 404 probing and the DOM-XSS path a later phase would open by echoing a raw param |
| T-16-DC-02 | Denial of Service | Repeated index fetches per navigation | mitigate | The index client memoizes the in-flight promise, so the ~300-500KB manifest is fetched once per session regardless of how many views request it; RESEARCH.md lists per-route re-fetching as the phase's named anti-pattern |
| T-16-DC-03 | Denial of Service | Poisoned failure cache blocking Retry | mitigate | Both clients delete the memoized promise on rejection, so the UI-SPEC Retry action issues a genuine new request instead of replaying a cached error |
| T-16-DC-04 | Information Disclosure | Same-origin static fetches over HTTPS | accept | GitHub Pages serves HTTPS by default and D-11 keeps every fetch same-origin (no CORS, no raw.githubusercontent coupling); all served data is already public (ASVS V4/V9 per RESEARCH.md Security Domain) |
| T-16-DC-05 | Tampering | Parsed JSON handed to renderers unvalidated | transfer | Schema mismatch is warned on, not enforced. The real exposure is free-text `name` reaching the DOM; mitigated at the render boundary in plans 06/07 via `textContent` (threat T-16-VW-01) |
</threat_model>
