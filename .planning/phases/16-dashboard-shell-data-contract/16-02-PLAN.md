```typescript
type Theme = 'light' | 'dark';
type ThemeMode = Theme | 'auto';
getEffectiveTheme(): Theme {
  const themeAttr = this.host.getAttribute('data-theme') as ThemeMode | null;
  if (themeAttr === 'light') return 'light';
  if (themeAttr === 'dark') return 'dark';
  return this.mediaQuery.matches ? 'dark' : 'light';
}
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| localStorage → document DOM | The persisted theme mode is browser-writable (devtools, extensions, a stale value from a future schema) and is used to set a DOM attribute |
| system media query → render callback | `prefers-color-scheme` changes trigger re-render work |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-16-TH-01 | Tampering | `readStoredMode` / `applyThemeMode` in `src/dashboard/theme.ts` | mitigate | `parseThemeMode` allow-lists exactly `'light' \| 'dark' \| 'auto'` and returns `'auto'` for anything else, so an arbitrary stored string can never reach `setAttribute('data-theme', ...)`. The widget `ThemeManager` analog deliberately omits this guard because its input is a developer-set host attribute; localStorage is not |
| T-16-TH-02 | Denial of Service | `localStorage` access in Safari private mode / storage-disabled contexts | mitigate | Both `getItem` and `setItem` are wrapped in try/catch; a throwing storage degrades to `'auto'` and a still-applied `data-theme` attribute rather than an unhandled exception that blanks the shell |
| T-16-TH-03 | Information Disclosure | Persisted theme preference | accept | A single non-identifying UI preference on a public single-athlete site; no PII, no session state (ASVS V3 not applicable per RESEARCH.md Security Domain) |
</threat_model>
