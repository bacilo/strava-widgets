<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| URL hash fragment → application state | The fragment is directly editable in the address bar and shareable by link; it is untrusted input, not internal state |
| route param → fetch URL / DOM | `:id` from `#/activity/:id` is interpolated into a same-origin fetch path by plan 05 and rendered by plans 06-07 |
| published index manifest → public web | `data/dashboard/index.json` is served openly from GitHub Pages |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-16-RT-01 | Tampering | `matchRoute` route params consumed by `src/dashboard/data/detail-client.ts` (plan 05) | mitigate | `isValidActivityId` enforces `/^\d{1,20}$/` and is the single exported chokepoint; plans 05-07 must call it before building any `data/activities/<id>.json` URL or writing the param to the DOM. Non-matching ids short-circuit to the UI-SPEC error state without a fetch |
| T-16-RT-02 | Denial of Service | `decodeURIComponent` in `matchRoute` | mitigate | Malformed percent-escapes (`%`, `%zz`) throw `URIError`; the decode is wrapped in try/catch returning `null`, so a hand-typed bad URL renders the not-found path instead of throwing during bootstrap |
| T-16-RT-03 | Information Disclosure | `DashboardIndexRow` field set published to GitHub Pages | mitigate | The row contract explicitly excludes `athlete`, `upload_id`, `external_id`, `gear_id`, and privacy flags from `StravaActivity`; only the D-09 field set is declared, and the acceptance criteria grep for leaked identifier members |
| T-16-RT-04 | Spoofing | Deep-linked route rendering a view the URL claims | accept | Read-only public single-athlete site with no authentication or access control (RESEARCH.md Security Domain: ASVS V2/V4 not applicable) — there is no privileged view to spoof into |
</threat_model>
