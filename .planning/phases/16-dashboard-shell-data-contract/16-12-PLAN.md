<objective>
Make displayed dates and index ordering correct for the 55 intervals.icu-migrated activities regardless of the viewer's or build machine's timezone, and stop the list and overview error paths from painting over a view they no longer own.

Purpose: every intervals.icu record carries `start_date_local` without a `Z` suffix (verified: `data/activities/i174109928.json` has `2026-08-06T07:28:22`). `formatActivityDate` parses that as browser-local time and then reads `getUTC*` components, silently shifting by the viewer's UTC offset. The verifier reproduced it in two real timezones: an evening run shows as the next day for US viewers, an early-morning run as the previous day for European viewers. It affects list, overview and detail — all three import the same formatter — and Phase 17's calendar view would inherit it as date-bucketing corruption. The same root assumption skews the index sort key on a non-UTC build machine. Separately, the list and overview catch blocks paint unconditionally, so a stale rejection wipes whatever view the user navigated to; `detail.ts:240-244` already does this correctly.

Output: one normalized date chokepoint with timezone-independence tests, a normalized NaN-safe index sort key, and two container-ownership guards.
</objective>
