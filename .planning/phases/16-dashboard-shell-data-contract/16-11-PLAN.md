<objective>
Make the theme toggle visible and single-icon in both themes on both a light-OS and a dark-OS machine, and lock the fix behind a regression test.

Purpose: design-token parity with `src/widgets/shared/theme-manager.ts` is exact and no-flash first paint works, but the control that operates the theme is invisible in light mode (human-confirmed at the 16-09 checkpoint) — which is what fails SC3 and blocks DASH-03. Output: corrected rules in `src/dashboard/styles.css` and a new `src/dashboard/styles.test.ts` asserting each of them.
</objective>

    1. Add the declaration `color-scheme: light;` inside the existing `:root[data-theme="light"]` block (line 35) and `color-scheme: dark;` inside the existing `:root[data-theme="dark"]` block (line 45). This makes the browser's used color scheme follow the attribute `theme.ts` writes rather than the OS preference, which is what currently lets a dark-OS browser resolve `ButtonText` to near-white while the nav surface stays the forced-light `#f5f5f7`. Do not add a `prefers-color-scheme` media query — `data-theme` is always a concrete `light` or `dark`, never `auto`, so a media query would be a second source of truth. Do not remove the `color-scheme` meta tag from `index.html`; it declares support, and these two rules pin the choice.

    2. Add `color: var(--text);` to the `.theme-toggle` rule (line 141) and to the `.app-nav__toggle` rule (line 131) — either by adding the declaration to each rule, or by writing one combined `.theme-toggle, .app-nav__toggle { color: var(--text); }` rule. Keep the existing `fill: currentColor;` on `.theme-toggle`. This is what makes the icons' `currentColor` resolve to a theme token instead of the UA's `ButtonText`; the hamburger icon's `stroke="currentColor"` lines have the same problem and the same fix.

    3. Replace the rule at lines 153-155, `.theme-toggle__icon--active { fill: var(--accent); }`, with two rules: first `.theme-toggle__icon { display: none; }`, then `.theme-toggle__icon--active { display: inline; color: var(--accent); }`. Order matters — the `--active` rule must come second so it wins at equal specificity. Use `color`, not `fill`: a `fill` declaration on the svg root is always beaten by the children's own `fill="currentColor"` presentation attributes (a specified value on the element beats an inherited one), and the sun's rays use `stroke`, which a `fill` rule never reaches at all; `color` works for both because every child references `currentColor`. The literal declaration `fill: var(--accent)` must not survive anywhere in the file.

    4. Update the file header comment (lines 6-8). It currently reads "so no system-color-scheme media query belongs in this file" — keep that statement and extend it to say that `color-scheme` is declared per `data-theme` block for the same reason: the attribute, never the OS media query, is the single source of truth. Add a one-line comment above the `.theme-toggle__icon` rules explaining that the icon swap uses `display` rather than `fill` because SVG presentation attributes override inherited fill (WR-04).
  </action>
