<file_path_correction>
**GAP-24-05 item 1 names the wrong file, and following it literally would produce another
unsatisfiable row. This is corrected here, with the grounding, rather than silently.**

The amended GAP-24-05 says to edit `data/stats/best-efforts.json`. The detail view never reads that
document. `src/dashboard/data/best-efforts-client.ts:116` fetches
`` `${baseUrl}stats/best-efforts/${activityId}.json` `` with `baseUrl` defaulting to `'data/'`, and its
own docblock says the archive-wide document is deliberately not fetched because it is multi-MB. So
the file whose `wasPRAtTheTime` / `excludedFromRecords` fields feed `buildPrBadgeLabels` is the
per-activity shard `data/stats/best-efforts/4556693525.json` (1,844 such shards exist).

Second correction, load-bearing: the page under test is served by `npm run curate`, which serves the
already-BUILT `dist/widgets` tree under `/strava-widgets` (D-01, D-02). So the copy the browser
actually reads is **`dist/widgets/data/stats/best-efforts/4556693525.json`**. The curate server's D-07
instant mirror copies ONLY `data/best-effort-exclusions.json` into `dist/widgets/data/`
(`curate-server.mjs`'s `mirrorExclusions`, `PUBLISH_EXCLUSIONS_PATH`); the best-efforts shards under
`dist/widgets` are refreshed only by `npm run build-widgets`. An executor who edits the repo copy
alone will see no change on screen and will have no idea why.

**Therefore: edit BOTH copies, keeping them byte-identical to each other throughout,** so any disk
quote in the record is unambiguous, and snapshot both.

Third fact, which changes what counts as proof of restoration: `dist/widgets/*` is **gitignored**
(`.gitignore:4`). `git status --porcelain` will never report a change to the served copies. Byte
identity for those two files must be proven by `sha256sum` / `cmp` against snapshots taken outside
the repository. `git status` remains the correct proof for the two working-tree files.

The archive-wide `data/stats/best-efforts.json` is deliberately **NOT** edited this round. It stays
clean as an independent reference for the pinned expected values, and its `generatedAt` field
doubles as a tamper detector for an accidental Recompute (see the R35 validity check).
</file_path_correction>
