Lay the build-tier foundations every other Phase 24 plan depends on: widen the vitest
collection glob to reach `scripts/`, extract the data-copy walk into a side-effect-free
module, and ship D-10(a)'s build-time curation-artifact guard as a **pure function that
returns violations** with the `process.exit(1)` wrapper left at the call site — the shape
that makes D-11's "observed failing" proof possible at all.

was deleted (Phase 19 R3-CR-01, Phase 23 WR-06). D-11 exists because of that history, and
OD-2 exists because D-10's literal call site (inside `copyDataFiles()`) runs *before*
`buildPages()`/`buildDashboard()` populate the JS/HTML side of `dist/widgets` — the most
likely leak vector. A guard called there could never go red against a real regression.

`scripts/lib/curation-guard.test.mjs`, a widened `vitest.config.ts`, a `.curate-dist/`

    `CURATE_MARKER = '__curate'`, `SCANNED_EXTENSIONS = ['.js', '.html', '.css', '.map']`, and
    `findCurationArtifacts(publishDir)`.

    `findCurationArtifacts` mirrors `assertNoPrivateArtifacts`'s recursive `readdirSync(dir,
    { withFileTypes: true })` walk but with three deliberate deviations:
      1. It RETURNS an array of `{ path, reason }` violations. It must NEVER call
         `process.exit`, `console.error` or throw on a violation — the exiting wrapper lives at
         the call site. This is what makes D-11's planted-fixture test able to observe it red.
      2. It scans the WHOLE `publishDir` tree, not just a `data` subdirectory.
      3. Content scanning is restricted to files whose extension is in `SCANNED_EXTENSIONS`.
         This restriction is load-bearing and must be documented in the module's JSDoc: it is
         what guarantees the guard can never catch `dist/widgets/data/best-effort-exclusions.json`,
         which is public, already published, already asserted 200-and-parses at
         `verify-dashboard-publish.mjs:294`, and fetched at runtime by `detail.ts:465` and
         `records.ts:56`. Only the WRITE path is private; the data is not.

    Three violation kinds, each with a distinct human-readable `reason` string:
      - a directory or file named `__curate` anywhere in the tree
      - a directory named `.curate-dist` anywhere in the tree
      - a scanned-extension file whose contents contain the literal `__curate`

    Return `[]` when `publishDir` does not exist (mirroring `assertNoPrivateArtifacts`'s early
    return) and `[]` for a clean tree.

    Then in `scripts/build-widgets.mjs`: import `findCurationArtifacts` from
    `./lib/curation-guard.mjs` and define a local `assertNoCurationArtifacts()` wrapper,
    placed in the file immediately after `assertNoPrivateArtifacts` so the two guards read as
    the pair D-10 describes. The wrapper calls `findCurationArtifacts('dist/widgets')`; if the
    array is non-empty it `console.error`s one `✗ Curation-artifact guard failed: {path} — {reason}`
    line per violation and then `process.exit(1)` — never a warning, because `dist/widgets` is
    what actually gets deployed from a public repo. On an empty array it logs a `✓ Curation-artifact
    scan:` line naming the number of files scanned, matching `assertNoPrivateArtifacts`'s own
    success-line style.

    Call `assertNoCurationArtifacts()` as the LAST statement inside `buildAllWidgets()` after
    `await buildDashboard()` and before the two closing `console.log` lines — NOT inside
    `copyDataFiles()`. Add a comment at that call site recording this as OD-2's dated amendment
    to D-10's literal "same place as assertNoPrivateArtifacts" wording, and stating the reason:
    `copyDataFiles()` runs before `buildPages()`/`buildDashboard()`, so a guard there would pass

  </action>
