<objective>
Close GAP-24-01: make the `Excluded — {reason}` badge in the "Best Efforts This Run" panel derive
its on/off state from the LIVE `data/best-effort-exclusions.json` at render time, so it is correct
immediately after a curate Save with no Recompute and no rebuild — and symmetrically so an untick
clears it immediately, closing R11's mirror-image staleness in the same change.

Purpose: ROADMAP criterion 2 requires the reason to render in the same session with no rebuild.
Round 1's R5 recorded FAIL because the badge is gated on `row.excluded`, which
`detail-best-efforts-logic.ts:95` reads from `effort.excludedFromRecords` — a field baked into the
precomputed `data/stats/best-efforts.json`. Save writes the exclusions file and reloads, the app
re-fetches it, the data is present and correct (cache was explicitly excluded before the FAIL was
recorded), but the flag stays `false` until `compute-best-efforts` reruns. Only `exclusionReason`
is loaded live (`detail.ts:463`), and it merely decorates a badge the precomputed flag must first
enable. This plan moves the FLAG onto the same live read the REASON already uses.

Note on `24-RESEARCH.md` Architecture Pattern 2 and OD-1, which describe the post-Save reload as
letting "the existing, UNMODIFIED `detail.ts`/`detail-sections.ts` renderer repaint": that phrasing
is about the OVERLAY not becoming a second renderer for one panel, which is what D-03 forbids. This
plan does not add a renderer — it keeps exactly one, and changes which document that one renderer
reads its exclusion flag from. `detail-sections.ts` is genuinely untouched; `detail.ts` changes only
its data source, not its rendering. The reload mechanism itself (OD-1) is unchanged.

Output: a live-derived panel-row exclusion flag, unit coverage of all four derivation cases, a
source-structure guard on the wiring, both guards observed red against a planted regression, and a
recorded fresh build identity for the Round 2 checkpoint.
</objective>
