<objective>
Add the write half of the curate server: `PUT`/`DELETE /__curate/exclusions/:activityId`, a
`POST /__curate/recompute` runner, an Origin/Host gate on every write, and an atomic write that
mirrors into the served build so a Save is visible in the same session.

Purpose: this is where the phase can quietly break the engine. Three rules are non-negotiable.
(1) An untick DELETES the entry — leaving `distances: []` would produce an entry that
`buildExclusionIndex` silently skips, so the file would read as excluded while excluding nothing.
(2) The read path keeps its full tolerance — `buildExclusionIndex` accepts distance arrays,
duplicate entries and malformed rows, and that tolerance is a separate, tested contract from what
curate writes. Do not "simplify" it. (3) Curate never touches git: `data/best-effort-exclusions.json`
sits in the nightly workflow's push-paths filter, so a commit reaching origin triggers a full
rebuild and deploy. A tickbox must not be able to cause that.

Output: the mutation and routing code in `scripts/curate-server.mjs`, expressed as pure functions
wherever the JSON contract or the security decision lives, so every one of them is unit-testable.
</objective>
