<objective>
Close **WR-14** (`24-REVIEW.md` § Wave 7 Review; item 2 of the amended **GAP-24-05** in
`24-VALIDATION.md`): `scripts/lib/curation-guard.mjs`'s walk has no `entry.isFile()` test, so every
non-directory, non-regular entry falls through to an unguarded `readFileSync(entryPath, 'latin1')`.

Purpose: `readdirSync(…, { withFileTypes: true })` uses `lstat` semantics, so `entry.isDirectory()`
is **false** for a symlink that points at a directory. The reviewer and the round-4 verifier both
independently reproduced three throws against the shipped module — a dangling symlink throws
`ENOENT`, a symlink to a directory throws `EISDIR`, a mode-000 file throws `EACCES` — and a FIFO is
worse than a throw: `readFileSync` on one blocks until a writer appears, hanging the build with no
output at all. Each throw escapes `findCurationArtifacts`, escapes `assertNoCurationArtifacts()`
(which has no try/catch), and lands in `build-widgets.mjs:340`'s `buildAllWidgets().catch(...)`,
which prints `Widget build failed: EISDIR: illegal operation on a directory, read` — naming neither
the curation guard nor the offending path. That fails *closed*, which is why WR-14 is a Warning and
not a Critical, but this is the guard ROADMAP criterion 3 depends on, and the docblock's claim that
latin1 means "scanning arbitrary bytes can never throw" is true of the *decode* and false of the
*read*, which is the step that actually throws.

Output: an `entry.isFile()` gate and a `readFileSync` try/catch, both reporting violations instead
of throwing, with all five classes observed RED first (D-11) and the attributed build-level message
observed against the REAL `dist/widgets` tree.
</objective>

From `scripts/lib/curation-guard.mjs`:

```
export const CURATE_DIR_NAME = '__curate';
export const CURATE_MARKER = '__curate';
export const UNSCANNED_EXTENSIONS = ['.json'];
export function findCurationArtifacts(publishDir): Array<{ path: string, reason: string }>
```

The walk body today (lines 71-131), in order, for each `entry` of
`readdirSync(dir, { withFileTypes: true })`:

1. `if (entry.isDirectory())` — flags `__curate` / `.curate-dist` by name, then `walk(entryPath)`, `continue`.
2. name check: `entry.name === CURATE_DIR_NAME` → violation.
3. name check: `entry.name === '.curate-dist'` → violation.
4. `const ext = scanExtension(entry.name); if (ext !== null && UNSCANNED_EXTENSIONS.includes(ext)) continue;`
5. `const content = readFileSync(entryPath, 'latin1');` ← **the unguarded read WR-14 names**
6. `if (content.includes(CURATE_MARKER))` → violation.

There is no step between 3 and 4 that tests `entry.isFile()`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| filesystem entries under `dist/widgets` → `findCurationArtifacts`'s reader | The guard walks a tree whose contents are produced by Vite, esbuild and `copy-data-tree.mjs`, but which a developer, a stale build, or a misconfigured tool can also write into. Every entry it meets is untrusted input to a `readFileSync`. |
| a symlink's target → the process's read | `readdirSync` uses `lstat`, so the guard sees the LINK; `readFileSync` follows it. The link's target can point anywhere on the filesystem, including outside `dist/widgets`. |
| planted test fixtures → the REAL publish artifact | Task 2 writes symlinks into the actual `dist/widgets` tree that GitHub Pages publishes. |
| the guard's verdict → ROADMAP criterion 3's "provably absent" claim | A guard that aborts before finishing its walk has not proven anything, but the build's exit code looks the same as a real violation. |
