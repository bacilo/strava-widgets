THE INDEX CONVENTION THIS PHASE STANDARDISES ON (binding on plans 36-04 and 36-06):

The detector's half-open PAIR convention is already fixed by `classifyGapsWithSegments`'s pass 3
(`pace-derivation.ts`: `for (let i = seg.startIndex; i < seg.endIndex; i++) pairKinds[i] = 'unreliable'`).
So for an `UnreliableSegment`, PAIRS `seg.startIndex .. seg.endIndex - 1` are unreliable, and SAMPLES
`seg.startIndex` and `seg.endIndex` are shared boundary samples belonging to the CLEAN side
(32-CONTEXT.md D-06/D-07: adjacency is touching-only, clean samples are never swallowed).

The bound this task adds is in SAMPLE space and HALF-OPEN: `{ startIndex: lo, endIndex: hi }` sweeps
samples `lo .. hi - 1` and can therefore only produce a window over PAIRS `lo .. hi - 2`.

⚠ `36-RESEARCH.md`'s `complementSubIntervals` snippet pushes `{ startIndex: cursor, endIndex: seg.startIndex }`.
That is OFF BY ONE against the convention above: it drops the last clean pair (`seg.startIndex - 1`),
swallowing a clean sample. The correct complement bound is `endIndex: seg.startIndex + 1`. Plan 36-04
builds the complement and carries that correction; this plan's only job is to make
`{ startIndex, endIndex }` mean exactly "samples `lo` through `hi - 1`" and say so in the docblock, so
plan 36-04 has an unambiguous contract.

`data/streams/` and `data/activities/` are tracked in git (only `data/stats/`, `data/dashboard/`,
`data/tokens.json` and `data/private/*.json` are excluded), so a vitest test may read a real
committed stream directly. `src/analytics/pace-derivation.test.ts:65-68` is the existing `readStream`
helper to mirror; the same file's archive-sweep describe (around line 835) is the sweep shape.
