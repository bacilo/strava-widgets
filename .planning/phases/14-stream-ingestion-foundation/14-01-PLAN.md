  <behavior>
    - Normalizes FIT half-cadence with fractional precision: a sample with `cadenceRawRpm: 87, fractionalCadence: 0.5` yields `cadence: 175`
    - Normalizes intervals.icu integer cadence: a raw stream value of `87` yields `cadence: 174`
    - Treats an intervals.icu cadence `0` as a pause/dropout, not zero spm: a raw series `[86, 0, 88]` yields `cadence: [172, 172, 176]` (carry-forward), never a `0` entry
    - Omits the cadence channel when zero samples carry the field — the 2017 device-generation gap: `channels.cadence === false` and the `cadence` key is absent from the object
    - Omits the hr channel identically when no sample carries heart rate (the 38 extension-free GPX files)
    - Rejects out-of-bounds sentinels as missing rather than storing them: `hr: 255` and `hr: 0` are dropped, `cadenceRawRpm: 200` is dropped, `altM: 60000` is dropped
    - Uses native cumulative distance when present and sets `distanceSource: 'native'`
    - Falls back to cumulative haversine over lat/lng when no distance field exists (the GPX case) and sets `distanceSource: 'geo'`
    - Returns `null` when fewer than 2 usable samples exist, or when neither a distance field nor lat/lng is available
    - Clamps non-monotonic distance: a series `[0, 100, 90, 200]` yields a non-decreasing `d`
    - Emits `t` as integer seconds since the first sample, starting at 0
    - Decimates to a minimum 1s spacing and never exceeds 3000 samples
    - Contains no position data: the returned object has no `lat`, `lng`, or `latlng` key
  </behavior>
  <action>
Create `src/streams/derive-stream.ts` as a pure module. It must not import `node:fs`, `node:zlib`, or any network client — callers do all I/O and pass decoded data in. It may import `IntervalsProvider` from `../api/intervals-provider.js` solely for `extractCoordinates`.

Export two entry points, both funnelling into one shared internal normalizer:

- `deriveFromSamples(id: string, samples: RawSample[], source: StreamSource): CanonicalStream | null` — used by the FIT and GPX backfill paths.
- `deriveFromIntervalsStreams(id: string, streams: unknown): CanonicalStream | null` — used by the daily sync and the reconciliation branch. It converts the loosely-typed intervals.icu response into `RawSample[]` and then calls the same internal normalizer with `source: 'intervals'`.

Internal normalizer rules, all deterministic and all testable:

1. **Bounds constants** (export them so tests can reference them): `HR_MIN = 20`, `HR_MAX = 250`, `CADENCE_RAW_MAX = 150`, `ALT_MIN = -500`, `ALT_MAX = 9000`. Every extracted numeric field is coerced, bounds-checked, and dropped if it fails — never stored. This extends the existing `typeof === 'number'` position guard to `hr`, `cadence`, `distance`, and `altitude` per RESEARCH.md's Security Domain table.
2. **Time**: `t[i] = round(sample.tEpochS - samples[0].tEpochS)`, integer seconds. Drop any sample whose computed `t` is less than the previously kept `t` (out-of-order records).
3. **Distance**: if any sample carries an in-bounds finite `distanceM`, use the native series and set `distanceSource: 'native'`; clamp each value to `max(value, previousValue)` so `d` is non-decreasing. Otherwise, if samples carry `lat`/`lng`, accumulate haversine distance between consecutive points and set `distanceSource: 'geo'`. Otherwise return `null`. Round `d` to 0.1 m. Note in a comment that `'geo'` exists because the 38 archive GPX files carry no distance field — Phase 15 must be able to tell native from recomputed distance, which is why the provenance is recorded rather than silently mixed.
4. **Cadence**: FIT/GPX path — `2 * (cadenceRawRpm + (fractionalCadence ?? 0))`, computed only when `cadenceRawRpm` is in bounds. Intervals path — a raw value of `0` is treated as a dropout marker and yields no value for that sample (RESEARCH.md Pitfall 1: the API interleaves `0`s that are pause markers, not real zero-cadence samples); any other in-bounds raw value yields `raw * 2`. Round to 0.1.
5. **Heart rate**: integer, bounds-checked. **Altitude**: rounded to 0.1 m, bounds-checked.
6. **Channel presence and gap filling**: compute presence from ACTUAL field presence per file, never from source format (RESEARCH.md Pitfall 4 — a 2017 FIT file has no cadence at all). If a channel has zero in-bounds values across the whole activity, set `channels.X = false` and omit the array key entirely. If it has at least one, emit an array the same length as `t`, filling gaps by carrying forward the last valid value; leading gaps take the first valid value. Carry-forward (rather than nulls) keeps the parallel arrays index-aligned and satisfies D-01's "strip nulls" — no `null` may appear in any emitted array.
7. **Decimation** (CONTEXT.md D-01, light only): keep the first sample; keep a later sample when `t - lastKeptT >= minIntervalS`; always keep the final sample. Start `minIntervalS` at 1. If the kept count still exceeds 3000, retry at 2, then at 3, and stop at 3 regardless. This ladder is a fixed per-file resolution rule within D-01's stated ~1-3s band; it is NOT the D-02 size gate and must never be driven by a total-bytes budget.
8. **Rejection**: return `null` when fewer than 2 samples survive, or when distance could not be established. Callers translate `null` into a `no-samples` manifest reason.
9. `sampleCount` equals `t.length`; `schemaVersion` equals `STREAM_SCHEMA_VERSION`.

For `deriveFromIntervalsStreams`, reuse the container-shape handling from `intervals-provider.ts`: the response may be an array of `{type|name, data, data2}` objects or a plain object keyed by stream name. Look up `time`, `distance`, `heartrate` (also accept `hr`), `cadence`, and `altitude` (also accept `elevation` and `ele`). If a `time` stream is present use its values as second offsets; if it is absent, use the sample index as seconds, which matches intervals.icu's fixed-rate stream convention. For the geo-distance fallback, obtain positions via `IntervalsProvider.extractCoordinates(streams)` rather than re-implementing the `data`/`data2` parallel-array quirk.

Write `src/streams/derive-stream.test.ts` covering every item in the behavior block above, using literal synthetic inputs only — no filesystem or network access, so the suite runs in CI where `export_data/` does not exist. Follow `csv.test.ts`'s convention of naming the real quirk in each `it` description.
