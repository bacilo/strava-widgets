<objective>
Persist intervals.icu streams for newly-synced activities inside the existing daily sync loop, and make CI actually commit them.

Purpose: STREAM-02 and STREAM-03. `IntervalsSync.syncNewActivities()` already fetches the streams response for geometry — this plan extracts stream channels from that same response rather than issuing a second request per activity.
Output: extended `IntervalsSync`, the module's first test suite, and a corrected `file_pattern` in the daily workflow.

**Correction to CONTEXT.md:** its Integration Points section claims "`.github/workflows/daily-refresh.yml` commit pattern picks it up." It does not. The pattern is an explicit allowlist — `data/activities/*.json data/sync-state.json data/geo/*.json` — with no wildcard covering `data/streams/`. Without Task 3, every stream file CI produces is silently discarded on the next checkout. This repo already lost three months of deploys to exactly this bug class (STATE.md: a gitignored path in `file_pattern` froze gh-pages from Feb 23).
</objective>

  <action>
Extend `IntervalsSync` to persist streams without adding a network request.

Constructor: add `streamsDir: string` and `streamsManifestPath: string` to the destructured options object and the matching type literal, storing them as private fields — threaded exactly the way `activitiesDir` already is. Update the single call site in `src/index.ts`'s `syncIntervalsCommand` to pass `streamsDir: config.streamsDir` and `streamsManifestPath: config.streamsManifestPath`. Do not give these defaults; the module takes its paths by injection so tests can point them at a temp directory.

In `syncNewActivities()`, load the manifest once before the activity loop via `loadManifest(this.fileStore, this.streamsManifestPath)`, and call `saveManifest` once after the loop finishes — not per activity, so a 30-activity sync writes the manifest once. Track whether any entry changed so a sync that adds nothing leaves the manifest untouched.

Inside the existing per-activity `try` block that already calls `this.provider.fetchGeometry(...)`, after the existing geometry handling, derive and persist the stream from the SAME response. Choose the payload as `geometry.rawAll ?? geometry.raw` — `rawAll` is the unfiltered response and therefore the richer source when present, while `raw` is the coordinate-filtered response. Note in a comment that `raw` may be missing HR/cadence/altitude precisely because it was filtered to coordinate stream names, so when `rawAll` is absent and the derived stream reports `channels.hr === false && channels.cadence === false && channels.elevation === false`, one call to `this.provider['client']` is not permitted — instead widen the request at its source: pass the activity's full `raw.stream_types` list through the existing `streamTypes` option so `getStreams` asks for every stream the activity declares, not just coordinate names. Implement that by changing the `streamTypes` argument passed to `fetchGeometry` from the coordinate-filtered list to the complete `raw.stream_types` array when it is available. `fetchGeometry` already narrows to coordinate names internally for its own axis resolution, so passing the full list is safe and yields a response carrying every channel in one request.

Then: `const stream = deriveFromIntervalsStreams(String(activity.id), geometry.rawAll ?? geometry.raw)`. When non-null, `await this.fileStore.writeJson(\`${this.streamsDir}/${activity.id}.json\`, stream)` and `upsertAvailable(manifest, String(activity.id), { source: stream.source, distanceSource: stream.distanceSource, sampleCount: stream.sampleCount, channels: stream.channels })`. When null, `upsertUnavailable(manifest, String(activity.id), 'no-samples')` and `console.warn(\`  ${activity.id}: no usable stream samples; flagged no-samples\`)`.

All of this lives inside the existing `try`/`catch (error: any)` at lines 109-126 so a stream failure degrades exactly the way a geometry failure already does — warn, keep the activity, continue the sync. Extend the existing catch's warning text to mention that the stream was also not persisted. If `fetchGeometry` throws outright, record `upsertUnavailable(manifest, String(activity.id), 'no-samples')` in the catch so the activity still gets a manifest entry rather than becoming invisible to downstream badges.

Do not add a `getStreams`/`getAllStreams` call anywhere in this file.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| intervals.icu JSON → sync loop | Third-party API running unattended in CI; shapes have already diverged from documentation once (`data`/`data2`) |
| CI runner → repository contents | The nightly job holds `contents: write` and commits on its own |
| `INTERVALS_API_KEY` secret → logs | The key is injected as an env var into a job whose output is publicly readable |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-01 | Denial of Service | per-activity loop in `syncNewActivities` | mitigate | Stream derivation and persistence live inside the existing `try`/`catch` so a failure warns and the sync continues; asserted by the throwing-client test in Task 2. |
| T-14-11 | Denial of Service | intervals.icu request budget | mitigate | Reuse `fetchGeometry`'s response instead of issuing a second per-activity request; enforced by the `getStreams`/`getAllStreams` grep gate in Task 1 and the call-count assertion in Task 2. |
| T-14-06 | Information Disclosure | `INTERVALS_API_KEY` in CI logs | mitigate | No new logging of request URLs or headers is added; the key stays inside the existing `IntervalsClient`, and `src/index.ts`'s top-level handler already filters stack traces containing `token`/`secret`. |
| T-14-12 | Tampering | CI commit scope | mitigate | `file_pattern` stays an explicit allowlist; `data/streams/*.json` is added and verified non-gitignored, so `git add` cannot fail and silently skip the deploy. |
| T-14-03 | Information Disclosure | committed stream files | mitigate | Written objects come from `deriveFromIntervalsStreams`, whose schema carries no position data. |
